# Excel 收入统计工具

## Windows 使用方式（推荐）

1. [直接下载 ExcelRevenueTool-v0.11.3.exe](https://github.com/olu37776-bit/excel-arrival-tool/releases/download/v0.11.3/ExcelRevenueTool-v0.11.3.exe)。
2. 双击 `ExcelRevenueTool-v0.11.3.exe`。不需要安装 Python，也不需要运行 BAT 或打开终端。
3. 在窗口中选择三个必选源文件，并按需选择当月订货文件：
   - 遗留量 Excel
   - 当月订货 Excel（可选；没有时留空）
   - 要货明细 Excel
   - 国家运输周期 Excel
4. 无需选择汇总月份，程序自动识别数据中实际出现的收入年月。
5. 选择结果保存位置，点击“开始生成”。生成期间窗口保持响应；完成后可直接“打开结果”或“打开所在文件夹”。

第一次运行时，“上一次成功结果”留空。以后需要跨期比较或继承人工填写字段时，选择上一次成功生成的结果文件。

v0.11.1 兼容缺少新增系统列的旧版上期结果：按本期源数据补算收入预测和最终字段，并保留可继承的人工调整。四个最终字段同时保存公式与初始计算值，生成后即可读取；旧文件本身不会被修改，请用新版重新生成。

如果 Windows SmartScreen 提示未识别应用，这是因为程序尚未购买代码签名证书；可点击“更多信息”后选择“仍要运行”。

## 基表透视与最终字段

新版不再自动生成“RPD地区收入汇总”“CPD地区收入汇总”及隐藏 `_summary_source`。基表继续作为用户筛选、运算和自行创建 Excel 透视表的唯一主入口。

- 基表不加工作表保护，可编辑、筛选、排序并自行创建透视表。
- 黄色字段为人工输入；四个最终字段保留实时公式。填写人工字段后，最终字段在 Excel 自动计算模式下立即更新。
- 请填写“调整收入分段类别”“调整月份（按RPD）”“调整月份（按CPD）”“调整金额”，不要覆盖相邻最终公式列；明确金额 0 也有效，清空人工字段恢复自动结果。
- 用户自行创建的透视表由用户自行刷新；工具读取上期时仍会隔离原生透视显示区域和分组缓存，不继承透视对象。
- 结果工作簿保持普通自动计算，但不再启用强制全量重算，以降低与同一 Excel 会话中其他工作簿/VBA 脚本的计算竞争。

## Python 方式（备用）

电脑已安装 Python 3.10 或更高版本时，可以解压[源码](https://github.com/olu37776-bit/excel-arrival-tool/archive/refs/heads/main.zip)，然后在工具目录执行：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m revenue_tool.gui --config .\config\default.json
```

图形窗口中的四个源文件可以位于任意文件夹，不需要放进工具目录。

## 常见问题

- 导入 `.xlsx` 报 `cannot access local variable 'cell' where it is not associated with a value`：v0.11.3修复了读取空白工作表时的尺寸识别异常，源文件和上期结果中的可见/隐藏空白页均可保留，无需用户删除。完全没有业务表头的文件仍会提示缺少业务数据，不会伪造继承结果。
- v0.11.3导入时按实际单元格核对行列范围，兼容缺失、偏小（不只A1:A1）及虚大的范围声明，避免漏读或按错误列数填充。范围核对会增加一次扫描；真实存在的大量格式单元格、超大文件仍有性能成本，不承诺无限规模。
- 上期或源文件含分组透视时出现 `Nested.from_tree()` 错误：v0.11.1修复了数据导入误解析透视缓存的问题。程序只读取数据，原文件保持不变；输出Excel仍可编辑。
- 双击工作簿图标闪一下就消失：先单独启动Excel，再从“文件→打开”选择文件，记录是否只有这份文件触发退出。请提供原始文件与Excel版本供排查，不能仅凭此现象认定文件损坏。

- 双击 EXE 后首次显示较慢：单文件程序需要先解压运行组件，请等待几秒。
- 提示“工作簿不存在”：重新选择文件，并确认文件没有被移动或重命名。
- 输出路径必须包含文件名和 `.xlsx` 后缀。
- 输出文件不能覆盖源文件或作为输入的上一次结果。
- Excel 文件正在打开时可能无法覆盖原结果，请先关闭该文件。
- 公司安全策略直接拦截 EXE：需要由公司 IT 放行，或改用上面的 Python 方式。

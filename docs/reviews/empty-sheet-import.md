# v0.11.3 空白工作表导入修复（Issue #50）

## 根因与修复

已用“一个有值Sheet加一个空白Sheet”最小XLSX复现用户的 `cannot access local variable 'cell' where it is not associated with a value`。v0.11.1为只读模式补回缺失/占位尺寸时调用openpyxl 3.1.5的 `calculate_dimension(force=True)`；其内部在无实际单元格时引用未赋值的循环变量，导致任一空白页让整个文件导入失败。

改为适配器内安全恢复尺寸：初始边界A1，逐行读取真实单元格坐标扩展边界，忽略无坐标填充项和空XML行。样式空白单元格仍保留坐标；零、False、日期及格式不变。不通过吞掉解析异常伪造空表，真正损坏的XML仍明确失败。读取流程继续只读，不修改输入ZIP，不解析分组透视缓存；用户透视显示区域仍从业务读取视图排除。

用户追问其他边界后，进一步用实际D9有值但dimension=A1:B2的文件确认原条件会漏读；A1:XFD100则会给每行补到16384列。现对所有工作表实际范围进行一次恢复，不仅针对A1:A1。代价是每页多一次流式扫描，不整表物化。真实存在的超大数据/大量格式单元格仍有计算成本；无真实用户文件，不能据此保证任意规模导入性能。粘贴成普通值的透视仍无法可靠区分，损坏/加密文件也不能由范围恢复修复。

## 回归覆盖

- 空白可见、隐藏和veryHidden Sheet，缺失尺寸与A1:A1占位尺寸，A1:B2偏小范围和A1:XFD100虚大范围，只有空XML行。
- A1单值（文本、0、False），稀疏业务值、日期、前导零格式、只有样式的空单元格。
- 四类源文件带空页和A1:B2偏小范围仍产生7条基表记录，输入字节不变。
- 上期结果空页叠加同页用户透视、分组透视缓存、A1:B2偏小范围、元数据有/无，人工0/False和月份正确继承，输入字节不变。
- 全空上期文件报告业务表头不可用，而非Python异常；损坏XML仍报读取失败。
- Windows打包EXE smoke加入三种空白页，再叠加用户透视和分组缓存验证继承。

验证结果及正式发布信息将在CI完成后补充。本修复针对程序导入异常，不宣称已解决用户Excel普通模式启动退出或实机自动计算问题（#47、#45继续跟踪）。

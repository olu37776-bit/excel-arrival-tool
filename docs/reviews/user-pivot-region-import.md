# v0.11.2 同页用户透视与业务数据隔离（Issue #47）

## 故障与修复

v0.11.1忽略透视对象/缓存，但仍读取其显示单元格。已复现基表AS1旁边出现第二个合同号表头，导致继承不可用；下方类似业务数据的透视行也可能误入。用户明确自建透视无需继承。

新增pivot_input_view：通过当前工作表关系及pivotTableDefinition的location读取布局，导入视图将透视结果及报表筛选单元格置为空。只改变读取投影，不修改输入ZIP，不继承用户透视，不触及pivotCache反序列化。Header识别、源表角色识别、业务行导入统一使用同一视图。视图保持原行列坐标和数据格式，透视下方真实业务行仍可导入；不硬编码前40列，不以空行猜测结束位置。

支持关系的绝对/相对内部目标，标准pivotParts引用与openpyxl关系引用形式。找不到有效透视布局时明确报错，不将透视值悄悄当业务数据继承。输入仅限仍保留原生透视布局信息的工作簿；已复制粘贴为普通值的汇总无法自动可靠区分，请放独立工作表。用户透视若已覆盖原业务单元格，不能恢复被覆盖的数据。

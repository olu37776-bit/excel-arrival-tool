## 1. 结论

本轮文档已统一以下业务口径：

- 遗留量、当月新订货空值及无匹配输出0；
- 空白字符、`(空白)`、`#VALUE!`及等价VALUE标记按空值处理且不报异常；
- 货未发完规则允许“有最晚RPD、无最晚ASD”判定为Y；
- 两套到货日期均先按货未发完门控；
- 货未发完为Y时，RPD口径使用最晚RPD，CPD口径使用CPD；
- 收入分段新增`未录入订货`；
- 合同无正常行的异常精确为要货明细未找到合同号；
- 同业务组普通文本多值不再报错；
- 同一要货明细行备货/发货总控标识不同需要报错。

文档之间未发现相互矛盾的权威规则。

## 2. 对现有实现的预期偏差

后续代码审查应重点查找：

1. 金额空值仍输出空而非0；
2. `#VALUE!`仍进入异常清单；
3. 到货日期仍使用旧的ATA→ASD→RPD/CPD链而未检查货未发完；
4. 货未发完为Y时仍使用ATA或ASD；
5. RPD路径仍使用最小RPD而非最晚RPD；
6. 收入分段没有`未录入订货`；
7. 当月订货无匹配仍被当成异常；
8. 普通文本多值仍生成冲突异常；
9. 同行备货/发货总控标识不一致没有单独异常；
10. 合同未匹配要货明细仍被描述为“无供应中心”。

## 3. 需要测试覆盖的最小场景

- 遗留量空、当月新订货空 → 两列均为0；
- 金额/日期为`#VALUE!` → 按空处理且无异常；
- 货未发完=N，ATA存在 → 取ATA；
- 货未发完=N，ATA空、ASD存在 → ASD+海运周期；
- 货未发完=Y，最晚RPD存在 → RPD口径取最晚RPD+海运周期；
- 货未发完=Y，CPD存在 → CPD口径取CPD+海运周期；
- 所有候选日期空 → 到货日期空且无异常；
- RPD/CPD存在、金额均0 → 未录入订货；
- RPD/CPD存在、任一金额非0 → 订未发；
- 普通文本多值 → 取第一条且无冲突异常；
- 同行Y/N总控标识不同 → `CONTROL_FLAG_MISMATCH`；
- 合同在三表全集但要货明细无合同 → 无正常行并产生精确异常。

当前不存在以下已知跨文档冲突：

- `#VALUE!`到底报错还是按空处理；

## 2. 已确认的新规则

### 2.1 金额

- 遗留量、当月新订货必须输出数值；
- 空单元格、空白字符、`(空白)`、`#VALUE!`、合同无匹配均输出0；
- 其他非法非空金额记录异常，但输出仍为0。

### 2.2 安静空值

以下不写异常：

- 空单元格和空字符串；
- 半角/全角空格、制表符、换行；
- `(空白)`；
- `#VALUE!`；
- 空合同号行和空履行供应中心值被忽略。

### 2.3 货未发完与到货日期

到货日期先判断`货未发完`：

```text
货未发完 = Y：
    按RPD → 最晚RPD + 海运周期
    按CPD → CPD + 海运周期

货未发完 != Y：
    ATA优先
    否则取ASD
    不再回退RPD/CPD加周期
```

### 2.4 收入分段类别

```text
多次要货=Y → 需判断
否则ATA/ASD任一有效 → 发未收
否则RPD/CPD任一有效：
    遗留量=0且当月新订货=0 → 未录入订货
    任一金额不为0 → 订未发
否则 → 不要货
```

### 2.5 异常

- 合同进入全集但要货明细没有相同合同号：`CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`，不生成正常行；
- 同合同+履行供应中心内普通文本出现多个不同非空值：不报异常，取第一条有效值；
- 同一要货明细记录中备货总控标识和发货总控标识均为有效非空Y/N且不同：`CONTROL_FLAG_MISMATCH`；
- 完全重复行仍需识别、去重并防止制造分批。

## 3. 关键逻辑解释

现有`货未发完=Y`规则要求最晚ASD和最晚RPD均有效，因此“货未发完=Y且ASD为空”在逻辑上不可发生。

为避免后续实现出现不可达分支，本轮按业务目的作出明确解释：

- `货未发完=Y`时，已有ATA/ASD可能仅属于已完成批次；
- 整单最终到货日期不使用这些部分批次日期；
- 改用最晚RPD或CPD加海运周期。

该解释已单独记录在`DR-002`。后续实现不得重新恢复不可达条件。

## 6. 建议验收场景

至少覆盖：

- 遗留量和当月新订货均空→基表均为0；
- 合同无当月订货匹配→当月新订货0；
- 日期`#VALUE!`→按空处理且异常清单无该项；
- 货未发完=N、ATA有值→取ATA；
- 货未发完=N、ATA空、ASD有值→取ASD；
- 货未发完=Y→忽略已有ATA/ASD，按最晚RPD/CPD+周期；
- 货未发完=Y但周期缺失→到货日期空并记录周期异常；
- 所有日期空→到货日期空且不报缺日期异常；
- RPD/CPD存在、两金额均0→未录入订货；
- RPD/CPD存在、任一金额非0→订未发；
- 同组多个文本值→取第一条且无文本冲突异常；
- 同行备货Y、发货N→CONTROL_FLAG_MISMATCH；
- 合同不在要货明细→无基表行且有对应异常。

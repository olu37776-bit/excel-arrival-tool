## 2. 已修复的不一致

### R-001 `PRD` 与 `RPD` 冲突

**原问题**：主需求基线和旧 POC 使用 `PRD`，实际源字段及最新业务确认均为 `RPD日期`。

**修复**：

- 正式 canonical name 统一为 `RPD`；
- 输出统一为 `RPD`、`到货日期（按RPD）`、`收入年月（按RPD）`；
- `PRD` 仅允许出现在“旧 POC/旧称偏差说明”中。

**当前状态**：`RESOLVED`。

### R-002 “供应中心”显示名不一致

**原问题**：源表、运输规格和输出表使用不同名称，旧文档混用“供应中心”“供应中心简称”。

**修复**：

- 稳定内部字段 ID：`supply_center`；
- 要货明细源字段：`供应中心简称`；
- 国家运输周期源字段：`供应中心`；
- 用户可见输出：`履行供应中心`。

**当前状态**：`RESOLVED`。

### R-003 BG 源字段不一致

**原问题**：早期说明把要货明细 BG 视为同名字段。

**修复**：

```text
遗留量 行销产品维BG中文名称
→ 当月订货 行销产品维BG中文名称（若表存在）
→ 要货明细 BG_CN
```

核心业务只使用内部字段 `bg`。

**当前状态**：`RESOLVED`。

### R-004 当月订货表被错误视为必选

**原问题**：早期架构假定固定输入表，每次运行都必须有当月订货。

**修复**：

- 当月订货表改为可选输入；
- 缺表不得阻塞运行；
- BG 回退链自动跳过该来源；
- 未提供不得静默当成金额 0。

**当前状态**：`RESOLVED_WITH_TBD_DISPLAY`，空白还是 0 仍待确认。

### R-005 合同级金额与履行供应中心粒度混淆

**原问题**：曾错误地把合同级金额复制到多个供应中心行理解为重复统计缺陷。

**修复**：

- 遗留量、当月新订货明确为合同级字段；
- 同一合同展开为多供应中心行时复制展示；
- 当前版本不做金额汇总，不分摊也不聚合输出表金额。

**当前状态**：`RESOLVED`。

### R-006 收入分段类别误归为人工字段

**原问题**：早期把收入分段类别与最后三个人工字段一起继承。

**修复**：收入分段类别每次自动计算；只有以下三列人工维护并跨次继承：

1. 是否手工调整收入月份；
2. 手工调整收入月份；
3. 调整备注。

首次运行三列为空。

**当前状态**：`RESOLVED`。

### R-007 历史比较对象冲突

**原问题**：早期定义直接比较 `MIN(RPD)` 月份识别出货延迟；最新输出要求比较两期 RPD/CPD 自动收入年月。

**修复**：

- 当前变化清单比较 `收入年月（按RPD）` 和 `收入年月（按CPD）`；
- 分成 `RPD跨月变化`、`CPD跨月变化` 两个 Sheet；
- 人工调整月份不替代比较值；
- 如未来仍要独立“计划出货延迟”清单，必须另立规则。

**当前状态**：`RESOLVED_FOR_CURRENT_SCOPE`。

### R-008 规则状态名称扩散

**原问题**：存在 `PARTIALLY_CONFIRMED`、`CONFIRMED_BASE`、`CONFIRMED_SOURCE / OPTIONAL_INPUT` 等混合状态。

**修复**：权威状态统一为：

- `CONFIRMED`
- `PROVISIONAL`
- `TBD`
- `REJECTED`
- `IMPLEMENTATION_NOTE`

**当前状态**：`RESOLVED`。

## 3. 已确认且跨文档一致的核心规则

### 3.1 最终粒度

```text
合同号 + 履行供应中心
```

### 3.2 日期聚合

同一合同+履行供应中心内：

- ATA 取最大；
- ASD 取最大；
- RPD 取最小；
- CPD 取最大。

### 3.3 到货日期

按 RPD：

```text
ATA → ASD → MIN(RPD)+海运周期
```

按 CPD：

```text
ATA → ASD → MAX(CPD)+海运周期
```

ATA/ASD 命中时不加运输周期。

### 3.4 海运周期

基础键：

```text
国家 + 履行供应中心
```

单位为自然日，缺失时不得默认 0。特殊贸易类型规则仍待补充。

### 3.5 派生标记

- 多个供应中心发货：同合同不同履行供应中心数 > 1；
- 分批发货：同合同+履行供应中心相关总控/发货记录数 > 1；
- 多次要货：不同有效 RPD 日期数 > 1；
- 分批供应：不同有效 CPD 日期数 > 1。

### 3.6 收入分段类别

```text
多次要货=Y → 需判断
否则 ATA/ASD 任一有值 → 发未收
否则 RPD/CPD 任一有值 → 订未发
否则 → 不要货
```

### 3.7 三个人工字段

首次为空，后续按合同号+履行供应中心继承：

- 是否手工调整收入月份；
- 手工调整收入月份；
- 调整备注。

### P1-002 是否解锁备货多记录展示

## 7. 对当前代码的结论

现有 POC 的分层结构可参考，但领域模型和计算主线与正式需求不一致：

- 以 PO/Shipment 为中心，而不是合同号+履行供应中心；
- 使用 PRD，而正式字段是 RPD；
- 按 Trade Type 匹配运输周期，而正式基础键是国家+履行供应中心；
- 只计算一套到货/收入月份；
- 当前比较和业务键均不满足最新需求；
- 包含当前版本明确不需要的金额/数量汇总。

因此后续应按需求基线进行结构性修正，不建议在旧计算链上只替换表头名称。

# 跨月变化清单与输出工作簿规则

- 文档 ID：`COMPARISON-OUTPUT`
- 当前版本：`0.1`
- 状态：`ACTIVE-DRAFT`
- 日期：`2026-08-25`
- 关联：`docs/output-schema.md`

## 1. 输出工作簿结构

当前建议一个运行结果只生成一个 Excel 工作簿，至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`

后续异常清单可作为独立 Sheet 增加，不需要另生成文件。

变化清单应使用标准二维表结构：第一行为字段名，开启自动筛选，冻结首行。是否使用 Excel Table 对象属于实现细节，不改变业务含义。

## 2. 输出字段命名修正

正式输出中原字段 `供应中心` 统一更名为：

`履行供应中心`

内部字段 ID 仍保持 `supply_center`，源字段仍为要货明细表 `供应中心简称`。本次只改变输出显示名称，不改变匹配键、数据粒度或源字段绑定。

后续文档和代码中的用户可见输出标题均应使用 `履行供应中心`。

## 3. 比较粒度与数据来源

跨次比较的稳定业务粒度为：

`合同号 + 履行供应中心`

上期数据从上一次成功运行的主基表读取，本期数据来自本次新生成的主基表。比较清单本身不作为下一轮计算事实来源。

首次运行没有上期基表，因此两张跨月变化 Sheet 只输出表头，不产生变化记录。

## 4. RPD 跨月变化清单

比较字段：

- 上期 `收入年月（按RPD）`
- 本期 `收入年月（按RPD）`

只有两个年月跨月发生变化的记录才进入清单；“只列延后还是前后变化都列”仍待最终确认。

当前确认字段顺序：

1. 合同号
2. 遗留量
3. 当月新订货
4. 地区部
5. 国家
6. 客户群
7. 履行供应中心
8. 上期收入年月（按RPD）
9. 本期收入年月（按RPD）

建议但尚未确认的辅助列：

10. 变化方向（延后 / 提前）
11. 变化月数

这些辅助列只用于快速筛选和解释，不改变业务判断。

## 5. CPD 跨月变化清单

比较字段：

- 上期 `收入年月（按CPD）`
- 本期 `收入年月（按CPD）`

结构与 RPD 清单完全一致：

1. 合同号
2. 遗留量
3. 当月新订货
4. 地区部
5. 国家
6. 客户群
7. 履行供应中心
8. 上期收入年月（按CPD）
9. 本期收入年月（按CPD）

建议但尚未确认的辅助列：

10. 变化方向（延后 / 提前）
11. 变化月数

## 6. 为什么 RPD / CPD 分两个 Sheet

两种口径的业务含义不同，但字段结构一致。分 Sheet 有以下优点：

- 不需要额外“口径”列；
- 不会把一条记录的 RPD 与 CPD 变化混在一起；
- 业务人员可直接筛选、导出或单独查看某个口径；
- 后续两种口径若增加不同规则，不需要修改另一张表结构。

因此当前推荐 `RPD跨月变化` 与 `CPD跨月变化` 分开生成，而不是合并成一张宽表。

## 7. 待确认边界

1. 跨月变化清单是否同时包含“提前”和“延后”，还是只列收入月份延后的记录。
2. 是否增加 `变化方向`、`变化月数` 两个辅助列。
3. 如果上期或本期某个收入年月为空，是否进入变化清单，还是转入数据异常/状态变化清单。

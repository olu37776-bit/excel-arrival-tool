# 跨月变化清单与输出工作簿规则

- 文档 ID：`COMPARISON-OUTPUT`
- 当前版本：`0.2`
- 状态：`ACTIVE-DRAFT`
- 日期：`2026-08-25`
- 关联：`docs/requirements-baseline.md`、`docs/output-schema.md`

## 1. 输出工作簿结构

一次运行生成一个 Excel 结果工作簿，当前至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`

后续异常清单可作为独立 Sheet 增加，不需要另生成文件。

变化清单使用标准二维表：第一行为字段名，开启自动筛选并冻结首行。是否实现为 Excel Table 对象属于输出适配细节，不改变业务含义。

## 2. 输出命名与内部语义

用户可见字段统一使用：

```text
履行供应中心
```

内部字段 ID 保持 `supply_center`，要货明细源字段为 `供应中心简称`，国家运输周期源字段为 `供应中心`。

## 3. 比较粒度与基线

### BR-COMPARE-KEY-001 `[CONFIRMED]`

跨次比较的稳定业务键为：

```text
合同号 + 履行供应中心
```

不得把收入年月、金额、RPD/CPD 日期或其他会变化的字段放入身份键。

### BR-COMPARE-BASE-001 `[PROVISIONAL]`

当前按“本次成功运行”与“上一次成功运行”的基表比较。首次运行没有上期基表，因此两个变化 Sheet 只输出表头。

上一次结果由用户选择还是由工具自动定位最近一次成功运行，仍为 `TBD`。

### BR-COMPARE-SOURCE-001 `[CONFIRMED]`

比较值来自两期基表中的自动计算字段：

- `收入年月（按RPD）`
- `收入年月（按CPD）`

三个人工调整字段不替代这两个比较值。变化清单本身不作为下一轮业务事实来源。

## 4. RPD 跨月变化清单

比较：

- 上期 `收入年月（按RPD）`
- 本期 `收入年月（按RPD）`

当两个非空年月不相同时，属于候选跨月变化记录；最终只列延后还是同时列提前与延后，仍为 `TBD`。

当前确认字段顺序：

1. 合同号
2. 遗留量
3. 当月新订货
4. 地区部
5. 国家
6. 客户群
7. 履行供应中心
8. 上期收入年月（按RPD）
9. 本期收入年月（按RPD）

建议但尚未确认的辅助列：

10. 变化方向（延后 / 提前）
11. 变化月数

## 6. 为什么分成两个 Sheet

RPD 与 CPD 是不同业务口径。分 Sheet 可以：

- 避免一张表同时出现两套上期/本期字段造成阅读混乱；
- 允许业务人员单独筛选、导出和核查某个口径；
- 允许未来两种口径拥有不同边界规则；
- 避免增加额外“口径”列。

因此当前采用 `RPD跨月变化` 与 `CPD跨月变化` 两个独立 Sheet。

## 7. 空值、提前与延后边界

以下仍需业务确认：

1. 只列收入月份延后的记录，还是提前与延后都列；
2. 是否正式增加 `变化方向`、`变化月数`；
3. 上期空→本期有是否进入变化清单；
4. 上期有→本期空是否进入变化清单或异常清单；
5. 本期或上期收入年月因日期异常无法计算时，是否只进入异常清单。

在这些规则确认前，代码不得把空值转换为某个虚构年月参与比较。

## 8. 与旧延迟定义的边界

早期文档曾描述直接比较两期 `MIN(RPD)` 月份来识别出货延迟。当前已经确认的输出需求是比较两期自动计算的 RPD/CPD 收入年月并生成变化清单。

若后续仍需要独立的“计划出货延迟”清单，应另行定义名称、比较字段和输出列，不能与本文件的收入年月变化清单混用。

- 关联：`docs/requirements-baseline.md`、`docs/output-schema.md`

## 1. 输出工作簿

一次运行生成一个结果工作簿，至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`
4. `供应需要提拉诉求清单粗表`
5. `异常清单`

三张变化/差异清单均为标准二维表，第一行为表头，开启筛选并冻结首行。

## 2. 比较键

```text
合同号 + 履行供应中心
```

内部实现使用：

```text
contract_no + supply_center
```

不得使用收入年月、金额、行号或其他会变化的字段作为身份键。

## 3. 比较来源

比较上一次成功运行基表与本次基表中的自动字段：

- `收入年月（按RPD）`
- `收入年月（按CPD）`

人工调整月份不替代自动收入年月参与变化比较。

首次运行无上期结果时，两张跨期变化Sheet只输出表头。

## 6. 供应需要提拉诉求清单粗表

该Sheet比较同一期基表内两套自动收入年月，不与上期结果比较。

字段：

1. 合同号
2. 遗留量
3. 当月新订货
4. 地区部
5. 国家
6. 客户群
7. 履行供应中心
8. 收入年月（按RPD）
9. 收入年月（按CPD）

入表规则：

```text
两套收入年月均有效
且 abs(月份序号(RPD) - 月份序号(CPD)) >= 1
→ 进入供应需要提拉诉求清单粗表
```

两个年月相同不进入；任一年月为空时不进入该粗表。

收入年月为空可能是正常的无日期结果，也可能由运输周期异常导致。只有确实存在异常时才在异常清单记录原因；不得因为收入年月为空就自动制造异常。

## 7. 跨期变化入表规则

### 7.1 两期都有年月

年月相同：不进入变化清单。

年月不同：进入变化清单。

```text
本期 > 上期 → 变化方向 = 延后
本期 < 上期 → 变化方向 = 提前
变化月数 = 两个月份之间的绝对月份差
```

例如：

```text
2026-09 → 2026-10：延后，1
2026-11 → 2026-09：提前，2
```

### 7.2 空值状态变化

以下也进入变化清单：

```text
上期空 → 本期有 → 变化方向 = 新增
上期有 → 本期空 → 变化方向 = 取消
```

此时`变化月数`留空，不虚构月份差。

两期都为空：不进入变化清单。

如果某期为空是正常的无日期结果，不要求异常清单存在原因；如果为空由运输周期缺失、字段歧义或其他真实异常造成，则相应异常仍应独立记录。

## 8. 金额字段取值

变化清单和供应需要提拉粗表中的：

- 遗留量；
- 当月新订货；

均取基表规范化后的数值结果。

空单元格、空白字符、`(空白)`、`#VALUE!`或合同无匹配记录，均显示数值`0`，不得写空字符串或文本`0`。

## 9. 其他数据字段取值

变化清单中的合同号、地区部、国家、客户群、履行供应中心默认取本期基表值。

如果本期业务行已消失而只存在上期记录，则使用上期可用属性，并将变化方向视为取消/消失类状态。

合同进入本期合同全集但因要货明细无匹配合同而无法生成本期业务行时：

- 该事实进入异常清单；
- 若上期存在该业务键，通用比较器可以按“本期缺失”处理；
- 不得人为生成履行供应中心为空的本期基表行。

## 10. 历史基线

当前默认与“上一次成功运行”比较。

上一次结果由用户选择还是工具自动定位最近一次成功结果，属于交互实现选择，不改变业务比较规则。

## 11. 变更记录

- 遗留量、当月新订货在所有变化/差异清单中统一使用数值0空值口径；

- 明确空白字符、(空白)、#VALUE!不自动要求异常原因；
- 补充合同因要货明细无匹配而无法生成本期业务行时的比较边界。

## 1. 输出工作簿

一次运行生成一个结果工作簿，至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`
4. `供应需要提拉诉求清单粗表`
5. `异常清单`

三张变化/差异清单均为标准二维表，第一行为表头，开启筛选并冻结首行。

## 2. 普通比较键

正常要货业务行使用：

```text
合同号 + 履行供应中心
```

内部实现：

```text
contract_no + supply_center
```

无要货明细合同占位行使用显式：

```text
row_kind = CONTRACT_ONLY_NO_DEMAND
```

其履行供应中心为空，但不得把空中心占位行当成普通履行供应中心行比较。

## 3. 比较来源

比较上一次成功运行与本次运行中的自动字段和领域状态：

- `收入年月（按RPD）`
- `收入年月（按CPD）`
- `row_kind`或等价`demand_presence`状态

人工调整月份不替代自动收入年月参与比较。

首次运行无上期结果时，两张变化Sheet只输出表头。

## 6. 普通收入年月变化

仅对两期均为正常`DEMAND_CENTER`的业务键执行。

### 两期都有年月

```text
年月相同 → 不进入
本期 > 上期 → 延后
本期 < 上期 → 提前
变化月数 = 绝对月份差
```

### 空值状态变化

```text
上期空 → 本期有 → 新增
上期有 → 本期空 → 取消
两期都空 → 不进入
```

`新增`、`取消`的变化月数为空。

## 7. “有要货 ↔ 不要货”状态变化

普通月份比较不能稳定识别不要货状态，因此先执行合同级状态比较。

### 7.1 有要货变为不要货

```text
上期：合同存在一个或多个DEMAND_CENTER行
本期：合同存在CONTRACT_ONLY_NO_DEMAND占位行
```

必须同时进入RPD和CPD变化清单。

对上期每一个真实履行供应中心分别输出：

- 履行供应中心：上期真实中心；
- 上期收入年月：上期对应口径，允许为空；
- 本期收入年月：空；
- 变化方向：`变为不要货`；
- 变化月数：空。

即使上期收入年月为空，也必须入表。

### 7.2 不要货恢复为有要货

```text
上期：合同存在CONTRACT_ONLY_NO_DEMAND占位行
本期：合同存在一个或多个DEMAND_CENTER行
```

必须同时进入RPD和CPD变化清单。

对本期每一个真实履行供应中心分别输出：

- 履行供应中心：本期真实中心；
- 上期收入年月：空；
- 本期收入年月：本期对应口径，允许为空；
- 变化方向：`恢复要货`；
- 变化月数：空。

即使本期收入年月为空，也必须入表。

### 7.3 两期都是不要货

```text
上期NO_DEMAND + 本期NO_DEMAND
→ 不进入变化清单
```

### 7.4 去重优先级

`变为不要货`、`恢复要货`优先于普通`新增/取消`。

已由合同级状态变化输出的中心键，不得再重复输出普通新增或取消记录。

## 8. 状态持久化与旧结果兼容

新结果必须在隐藏系统数据中持久化`row_kind`或等价状态，不增加用户可见列。

读取旧结果时允许兼容推断：

```text
履行供应中心为空
且
收入分段类别=不要货
→ CONTRACT_ONLY_NO_DEMAND
```

新结果不得继续只依赖空值推断状态。

## 9. 变化清单属性来源

普通变化优先取本期属性；本期业务键不存在时取上期属性。

状态变化：

- `变为不要货`：合同属性优先取本期占位行，履行供应中心取上期真实中心；
- `恢复要货`：取本期真实履行供应中心行属性。

金额字段继续使用统一两位小数规范化值。

## 10. 供应需要提拉诉求清单粗表

该Sheet比较同一期基表内两套自动收入年月，不与上期结果比较。

字段：

1. 合同号
2. 遗留量
3. 当月新订货
4. 地区部
5. 国家
6. 结转类型
7. 客户群
8. 履行供应中心
9. 收入年月（按RPD）
10. 收入年月（按CPD）

入表规则：

```text
row_kind = DEMAND_CENTER
且两套收入年月均有效
且 abs(月份序号(RPD)-月份序号(CPD)) >= 1
→ 入表
```

两个年月相同不进入；任一为空不进入；`CONTRACT_ONLY_NO_DEMAND`占位行始终排除。

## 11. 历史基线

默认与“上一次成功运行”比较。

上一次结果由用户选择还是工具自动定位，属于交互实现选择，不改变本文件规则。

## 12. 验收场景

- 提前、延后、普通新增、普通取消；
- 有要货→不要货，且上期月份有值；
- 有要货→不要货，且上期月份为空；
- 多供应中心→不要货，每个上期中心分别输出；
- 不要货→有要货，且本期月份有值；
- 不要货→有要货，且本期月份为空；
- 两期均不要货不输出；
- 状态变化不重复输出普通新增/取消；
- 不要货占位行不进入供应提拉清单。

## 13. 变更记录

- 普通月份变化和有要货/不要货状态变化均透传同一结转类型字段。

### 0.5 - 2026-08-26

- 增加合同级`有要货/不要货`状态比较；
- 增加`变为不要货`、`恢复要货`变化方向；
- 明确月份为空时仍需发现状态变化；
- 明确多供应中心的逐中心追溯；
- 要求持久化`row_kind`并兼容旧结果；
- 防止状态事件与普通新增/取消重复。

### 0.4 - 2026-08-25

- 新增供应需要提拉诉求清单粗表；
- 明确同一期RPD/CPD收入年月偏差达到1个月及以上时入表。

### 0.3 - 2026-08-25

- 增加提前、延后、变化方向和变化月数；
- 空→有、有→空进入变化清单。

# DR-006 “不要货”状态在RPD/CPD跨期清单中的显式识别

- 状态：`CONFIRMED`
- 日期：`2026-08-26`
- 关联：
  - `docs/decisions/DR-005-retain-contract-without-demand-detail.md`
  - `docs/comparison-output.md`
  - Issue #13

## 1. 问题

`DR-005`定义了无要货明细合同的显式状态：

```text
row_kind = CONTRACT_ONLY_NO_DEMAND
收入分段类别 = 不要货
```

如果跨期比较只按：

```text
合同号 + 履行供应中心 + 自动收入年月
```

执行，则不能稳定发现“有要货变为不要货”。例如上期真实履行供应中心行的收入年月本来就是空，本期又变为不要货时，两期月份都为空，普通空值比较会直接跳过。

因此，“不要货”必须作为合同级业务状态变化显式参与RPD和CPD跨期比较。

## 2. 状态模型

按合同识别每期状态：

```text
HAS_DEMAND
- 该合同存在至少一条 row_kind = DEMAND_CENTER 的真实履行供应中心行

NO_DEMAND
- 该合同存在 row_kind = CONTRACT_ONLY_NO_DEMAND 的占位行
```

同一期同一合同不得同时存在`HAS_DEMAND`和`NO_DEMAND`。若出现，属于实现或数据状态错误，应记录明确异常并不得静默猜测。

## 3. 有要货变为不要货

条件：

```text
上期合同状态 = HAS_DEMAND
本期合同状态 = NO_DEMAND
```

必须同时进入：

- `RPD跨月变化`
- `CPD跨月变化`

对上期每一个真实履行供应中心分别输出一行：

| 字段 | 取值 |
|---|---|
| 合同号 | 当前合同号 |
| 履行供应中心 | 上期真实履行供应中心 |
| 上期收入年月 | 上期对应RPD/CPD口径，允许为空 |
| 本期收入年月 | 空 |
| 变化方向 | `变为不要货` |
| 变化月数 | 空 |
| 其他合同属性 | 优先取本期合同占位行；本期无值时回退上期对应行 |

无论上期收入年月是否为空，都必须入表。

## 4. 不要货恢复为有要货

条件：

```text
上期合同状态 = NO_DEMAND
本期合同状态 = HAS_DEMAND
```

必须同时进入两张跨期变化清单。

对本期每一个真实履行供应中心分别输出一行：

| 字段 | 取值 |
|---|---|
| 合同号 | 当前合同号 |
| 履行供应中心 | 本期真实履行供应中心 |
| 上期收入年月 | 空 |
| 本期收入年月 | 本期对应RPD/CPD口径，允许为空 |
| 变化方向 | `恢复要货` |
| 变化月数 | 空 |
| 其他合同属性 | 取本期真实履行供应中心行 |

无论本期收入年月是否为空，都必须入表。

## 5. 其他状态

```text
上期NO_DEMAND + 本期NO_DEMAND
→ 不进入跨期变化

上期HAS_DEMAND + 本期HAS_DEMAND
→ 继续按合同号+履行供应中心和自动收入年月执行普通比较
```

普通比较的方向继续包括：

- 提前
- 延后
- 新增
- 取消

`变为不要货`和`恢复要货`优先于普通新增/取消。已由状态转换生成的业务键不得再重复生成普通变化行。

## 6. 不要货占位行的展示边界

不要货占位行自身的履行供应中心为空，但两张跨期清单不输出一条空中心的普通新增/取消行。

- 变为不要货：展示上期受影响的真实中心；
- 恢复要货：展示本期出现的真实中心。

这样既能发现状态变化，又不把空中心伪装成真实履行供应中心。

## 7. 与供应提拉清单的关系

`供应需要提拉诉求清单粗表`仍只比较同一期两个有效收入年月。

`CONTRACT_ONLY_NO_DEMAND`占位行两个收入年月均为空，继续排除，不因本决策进入供应提拉清单。

## 8. 历史状态持久化与兼容

新生成结果必须持久化可恢复的`row_kind`或等价状态，建议写入隐藏系统Sheet，不新增用户可见基表列。

读取旧结果时允许使用以下组合做兼容识别：

```text
履行供应中心为空
且
收入分段类别=不要货
→ 推断为 CONTRACT_ONLY_NO_DEMAND
```

兼容推断只用于旧结果；新结果不得继续只靠空值猜测状态。

## 9. 验收场景

- 上期真实中心有RPD/CPD月份，本期不要货 → 两张清单均为`变为不要货`；
- 上期真实中心月份为空，本期不要货 → 仍进入两张清单；
- 上期多中心、本期不要货 → 每个上期中心分别输出；
- 上期不要货、本期真实中心有月份 → `恢复要货`；
- 上期不要货、本期真实中心月份为空 → 仍为`恢复要货`；
- 两期均不要货 → 不输出；
- 状态变化事件不再重复输出普通新增/取消；
- 不要货占位行不进入供应提拉清单。

## 10. 实施影响

后续代码至少需要：

1. 上期结果读取恢复`row_kind`；
2. 比较器先按合同生成状态转换事件；
3. 再执行普通业务键/月比较；
4. 增加`变为不要货`、`恢复要货`方向；
5. 防止状态事件与普通新增/取消重复；
6. 增加多中心、空月份、旧结果兼容和工作簿输出测试。

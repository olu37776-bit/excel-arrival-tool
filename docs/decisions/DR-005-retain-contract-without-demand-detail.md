# DR-005 要货明细无合同匹配时保留“不要货”合同占位行

- 状态：`CONFIRMED`
- 日期：`2026-08-26`
- 关联：
  - `docs/requirements-baseline.md`
  - `docs/source-schema.md`
  - `docs/output-schema.md`
  - `docs/comparison-output.md`
  - Issue #13

## 1. 决策

合同进入当期合同全集后，如果要货明细中完全找不到该合同号，不再将该合同视为异常并丢弃。

该状态的业务含义为：

```text
当前合同没有要货
```

工具必须在基表中保留一条合同级占位行，并填写：

```text
收入分段类别 = 不要货
```

本决策取代此前以下旧行为：

```text
记录 CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL
不生成正常业务行
```

后续实现和验收不得继续按旧行为处理。

## 2. 适用条件

本决策仅适用于：

```text
合同号存在于当期合同全集
且
要货明细中该合同号的匹配记录数 = 0
```

合同全集继续按既有规则形成：

```text
当月订货文件未提供：
遗留量合同号 ∪ 要货明细合同号

当月订货文件已提供且可用：
遗留量合同号 ∪ 当月订货合同号 ∪ 要货明细合同号
```

因此，无要货明细合同通常来源于遗留量和/或当月订货。

## 3. 与“有要货记录但供应中心为空”的区别

以下两种状态必须分开：

### A. 要货明细中完全没有该合同号

```text
匹配记录数 = 0
```

这是本决策定义的正常“不要货”状态：

- 保留合同；
- 生成一条合同占位行；
- 不记录合同未找到或供应中心缺失异常。

### B. 要货明细中存在该合同号，但匹配行没有可用履行供应中心

```text
匹配记录数 > 0
但有效供应中心数 = 0
```

这是要货明细数据不完整，不得直接等同为“不要货”。继续按既有数据质量规则处理，并保留可追溯异常。

## 4. 输出粒度例外

正常要货业务行粒度仍为：

```text
合同号 + 履行供应中心
```

无要货明细合同允许生成一种受控例外行：

```text
合同号 + 空履行供应中心
```

实现应在内部显式标记行类型，例如：

```text
row_kind = CONTRACT_ONLY_NO_DEMAND
```

不要求在用户可见基表中增加`row_kind`列，但不能仅靠偶然空值推断该行类型。

同一合同最多生成一条该占位行。

## 5. 字段规则

无要货明细合同占位行按以下规则输出。

### 5.1 合同级字段

继续按现有合同级来源规则填写：

- 合同号；
- 遗留量；
- 当月新订货；
- BG；
- 地区部；
- 国家；
- 结转类型；
- 客户群；
- 项目名称。

当月订货文件未提供时，`当月新订货=0`；BG跳过当月订货来源。

### 5.2 要货明细及履约字段

由于要货明细中没有该合同，不得虚构来源值：

| 输出字段 | 值 |
|---|---|
| 贸易术语 | 空 |
| 履行供应中心 | 空 |
| 多个供应中心发货 | `N` |
| 是否解锁备货 | 空 |
| 分批发货 | `N` |
| 海运周期 | 空 |
| ATA | 空 |
| ASD | 空 |
| RPD | 空 |
| 多次要货 | `N` |
| 最晚ASD | 空 |
| 最晚RPD | 空 |
| 货未发完 | 空 |
| CPD | 空 |
| 分批供应 | `N` |
| 到货日期（按RPD） | 空 |
| 到货日期（按CPD） | 空 |
| 收入年月（按RPD） | 空 |
| 收入年月（按CPD） | 空 |
| 收入分段类别 | `不要货` |

### 5.3 收入分段类别必须显式识别无要货状态

`CONTRACT_ONLY_NO_DEMAND`不是通过“日期刚好全部为空”间接推断出来的普通记录，而是由以下事实直接确定的业务状态：

```text
要货明细中该合同号匹配记录数 = 0
```

因此收入分段策略必须把它作为最高优先级的显式分支：

```text
0. row_kind = CONTRACT_ONLY_NO_DEMAND
   或 demand_detail_match_count = 0
   → 收入分段类别 = 不要货

1. 其余正常合同+履行供应中心行
   → 再执行既有的多次要货、ATA/ASD、RPD/CPD和金额判断规则
```

该分支必须先于以下判断执行：

- `多次要货 = Y → 需判断`；
- `ATA/ASD存在 → 发未收`；
- `RPD/CPD存在且金额为0/非0 → 未录入订货/订未发`；
- 普通日期全空 → 不要货。

实现不得只依赖以下偶然条件：

```text
ATA、ASD、RPD、CPD均为空
```

原因是这些日期为空只是无要货占位行的输出结果，不是其业务身份。领域模型或收入分段策略必须接收到明确的`row_kind`、`demand_presence`或等价结构化状态。

即使该合同的`遗留量`或`当月新订货`不为0，只要要货明细中完全没有该合同号，该占位行的收入分段仍然必须是：

```text
不要货
```

不得因为金额非0改判为`订未发`，也不得因为缺少履行供应中心改判为异常。

### 5.4 人工字段

三个人工字段规则不变：

- 是否手工调整收入月份；
- 手工调整收入月份；
- 调整备注。

首次出现时为空；后续运行可按：

```text
合同号 + 空履行供应中心
```

继承上一期同类占位行的人工值。

如果后续该合同出现真实履行供应中心，不将空中心占位行的人工值自动复制到任意真实中心行。

## 6. 异常边界

无要货明细合同属于正常业务状态，不产生：

- `CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`；
- `MISSING_SUPPLY_CENTER`；
- `TRANSIT_COUNTRY_MISSING`；
- `TRANSIT_NOT_FOUND`；
- `TRANSIT_VALUE_UNAVAILABLE`；
- 缺少ATA/ASD/RPD/CPD或到货日期的异常。

原因：该行本身没有要货，不需要执行履行供应中心、海运周期和到货日期计算。

这不影响以下异常继续生效：

- 字段缺失或字段匹配歧义；
- 合同级国家冲突；
- 遗留量/当月订货中的非法非空金额；
- 完全重复源行等既有数据问题。

## 7. 比较与差异清单

该占位行的两个自动收入年月均为空，因此：

- 当前行本身不进入`RPD跨月变化`；
- 当前行本身不进入`CPD跨月变化`；
- 当前行不进入`供应需要提拉诉求清单粗表`。

若上期存在真实履行供应中心行、本期变为无要货占位行，原真实业务键按既有跨期比较规则处理；不得把空履行供应中心伪装成任意历史真实中心。

## 8. 实施影响

后续代码修复至少需要：

1. 将`RevenueEngine.calculate()`中无要货明细时的`issue + continue`替换为占位行构建；
2. 领域模型支持受控的空履行供应中心占位键，并显式保存`row_kind=CONTRACT_ONLY_NO_DEMAND`或等价状态；
3. 抽取统一的合同级字段构建逻辑，避免正常中心行和占位行重复实现；
4. 跳过占位行的海运周期、日期聚合和到货计算；
5. 收入分段策略首先识别`CONTRACT_ONLY_NO_DEMAND`并直接返回`不要货`，不得只依赖日期全空；
6. 人工字段继承支持合同号+空中心；
7. 输出写出允许该受控场景的空履行供应中心；
8. 比较与供应差异逻辑不把占位行当成真实供应中心行；
9. 删除该场景下`CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`异常；
10. 增加领域单元测试、输入到输出集成测试和真实结果验收。

## 9. 最小验收场景

- 遗留量有合同、要货明细无合同 → 保留一行，`不要货`；
- 当月订货有合同、要货明细无合同 → 保留一行，`不要货`；
- 遗留量和当月订货同时有合同、要货明细无合同 → 只保留一行；
- 当月订货文件未提供、遗留量合同无要货明细 → 保留一行；
- 遗留量和/或当月新订货不为0，但无要货明细 → 仍为`不要货`，不得变成`订未发`；
- 履行供应中心为空且不虚构文本；
- 四个派生标记分别为`N/N/N/N`：多个供应中心发货、分批发货、多次要货、分批供应；
- 所有日期、海运周期、到货日期和收入年月为空；
- 无合同未找到、供应中心缺失或海运周期缺失异常；
- 要货明细存在合同但供应中心为空时，不错误套用本决策；
- 后续出现真实中心时按实际中心生成正常行；
- 收入分段策略单元测试能够证明该分类来自显式行类型，而不是日期全空的偶然结果。

# DR-001 人工调整字段的初始化与继承

- 状态：`CONFIRMED`
- 日期：`2026-08-25`
- 关联：`docs/output-schema.md`

## 决策

最终基表中以下五个稳定字段ID属于人工维护字段：

1. `manual_adjust_flag`（显示为`是否手工调整预测`）
2. `manual_revenue_forecast_rpd`（显示为`调整月份（按RPD）`）
3. `manual_revenue_forecast_cpd`（显示为`调整月份（按CPD）`）
4. `manual_revenue_month`（显示为`调整金额`）
5. `adjustment_note`（显示为`调整备注`）

旧显示名仍用于上一次结果兼容读取。显示名称变化不改变字段数据类型、初始化、继承或计算规则。

`收入分段类别` 不属于人工维护字段，应按本次业务数据每次重新计算。

## 初始化

首次运行时，上述五个字段全部留空。

后续运行中新出现、且上一轮结果中不存在对应业务记录的行，上述五个字段同样留空。

## 后续运行继承

后续运行时，如果上一轮结果中存在同一业务记录，则继承上一轮的五个字段值，本次自动计算过程不得覆盖这些人工值。

稳定业务粒度为：

```text
合同号 + 履行供应中心
```

内部实现使用稳定字段 ID：

```text
contract_no + supply_center
```

输出显示名称变化不得破坏继承键。

## 与自动字段的边界

- `收入分段类别`：每次重新计算；
- `收入年月（按RPD）`：每次重新计算；
- `收入年月（按CPD）`：每次重新计算；
- 五个人工调整字段：首次为空，后续继承。

当前工具不根据人工调整字段反向修改 RPD、CPD、到货日期、自动收入年月或收入分段类别。

人工调整月份是否作为未来收入统计的最终有效月份，待未来新增收入统计需求时另行定义；它不参与当前 RPD/CPD 跨月变化清单的比较。

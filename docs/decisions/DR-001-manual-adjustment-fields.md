# DR-001 三个人工调整字段的初始化与继承

- 状态：`CONFIRMED`
- 日期：`2026-08-25`
- 关联：`docs/output-schema.md`

## 决策

最终基表中只有以下三个字段属于人工维护字段：

1. `是否手工调整收入月份`
2. `手工调整收入月份`
3. `调整备注`

`收入分段类别` 不属于人工维护字段，应按本次业务数据每次重新计算。

## 初始化

首次运行时，上述三个字段全部留空。

后续运行中新出现、且上一轮结果中不存在对应业务记录的行，上述三个字段同样留空。

## 后续运行继承

后续运行时，如果上一轮结果中存在同一业务记录，则继承上一轮的三个字段值，本次自动计算过程不得覆盖这些人工值。

稳定业务粒度为：

```text
合同号 + 履行供应中心
```

内部实现使用稳定字段 ID：

```text
contract_no + supply_center
```

输出显示名称变化不得破坏继承键。

## 与自动字段的边界

- `收入分段类别`：每次重新计算；
- `收入年月（按RPD）`：每次重新计算；
- `收入年月（按CPD）`：每次重新计算；
- 三个人工调整字段：首次为空，后续继承。

当前工具不根据人工调整字段反向修改 RPD、CPD、到货日期、自动收入年月或收入分段类别。

人工调整月份是否作为未来收入统计的最终有效月份，待未来新增收入统计需求时另行定义；它不参与当前 RPD/CPD 跨月变化清单的比较。

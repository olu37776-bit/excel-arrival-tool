## 1. 目的

根据真实结果验收补充三个必须满足的实施边界：

1. 七个结转国家必须可靠命中；
2. 输出工作簿筛选后必须能使用 Excel 原生“数据 → 清除”恢复全部行；
3. 海运周期无法取得时必须进入异常清单，并明确说明具体原因。

本决策不改变既有业务粒度、日期规则、金额规则和源字段定义。

## 2. 结转国家匹配

### 2.1 业务名单不变

结转类型仍只根据遗留量来源自身的`国家中文名称`判断。

以下七个国家必须输出：

```text
结转类型 = 交付类
```

名单：

1. 阿拉伯联合酋长国
2. 巴基斯坦
3. 巴西
4. 菲律宾
5. 马来西亚
6. 沙特阿拉伯
7. 印度尼西亚

其中`阿拉伯联合酋长国`和`沙特阿拉伯`已在真实结果中出现未命中的问题，必须作为回归测试固定覆盖。

### 2.2 匹配语义

国家匹配不得直接依赖原始单元格字符串逐字节相等。

统一使用稳定国家 identity：

1. Unicode NFKC；
2. 去首尾空白；
3. 折叠/清理普通空格、全角空格、制表符和换行；
4. 清理不具有业务含义的常见零宽/格式控制字符；
5. 再与七国 canonical name 比较。

正式国家名经过上述规范化后必须稳定命中。

若真实资料存在合法别名，应通过显式 alias → canonical 映射处理，不使用编辑距离、相似度或任意模糊猜测。

### 2.3 来源边界

不得改成使用最终回退后的国家判断结转类型。

```text
遗留量自身国家命中七国 → 交付类
遗留量自身国家未命中 → 空
```

要货明细国家仅用于其他既有规则，不替代结转类型来源。

## 3. Excel筛选可用性

### 3.1 用户行为要求

所有可见业务输出 Sheet 必须支持 Excel 原生筛选交互：

- 基表
- RPD跨月变化
- CPD跨月变化
- 供应需要提拉诉求清单粗表
- 异常清单

用户在任意一列或多列应用筛选后：

1. Excel 功能区`数据 → 排序和筛选 → 清除`必须可用；
2. 点击“清除”后一次恢复该 Sheet 的全部数据行；
3. 表头筛选下拉仍然保留；
4. 保存、关闭、重新打开文件后仍可重复上述操作。

### 3.2 实现边界

当前输出使用 Excel Structured Table。如果该结构导致桌面版 Excel 的`数据 → 清除`交互不符合要求，可以改为普通二维区域 + worksheet AutoFilter，或采用其他能满足原生交互的实现。

是否继续使用 Structured Table 属于实现选择，不属于业务要求。

修复不得破坏：

- 冻结首行；
- 表头样式；
- 日期格式；
- 金额格式；
- 三个人工字段可编辑性；
- 输出列顺序和Sheet名称。

该项必须以 Windows 桌面版 Excel 实机行为作为最终验收，不只验证 openpyxl 对象结构。

## 4. 海运周期不可取得时的异常诊断

### 4.1 正常固定周期

贸易术语规范化后属于：

```text
FCA
FOB
EXW
```

海运周期直接为5天，不查国家运输周期表，因此不产生查表失败异常。

### 4.2 查表场景

其他贸易术语按：

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

只要当前业务行需要通过该路径取得海运周期，而最终无法得到有效周期，就必须在异常清单说明原因。

### 4.3 原始空值与派生失败的区别

既有全局规则继续成立：

- 空单元格；
- 空白字符；
- `(空白)`；
- `#VALUE!`及等价VALUE标记；

这些原始值本身安静规范化，不因“源单元格为空”单独报格式异常。

但如果当前业务行需要海运周期，规范化后因此无法得到有效周期，则必须记录一次**海运周期不可取得的业务异常**。这样既避免空白噪声，又保证到货日期失败可追溯。

### 4.4 异常分型

至少区分以下原因：

#### `TRANSIT_COUNTRY_MISSING`

```text
非FCA/FOB/EXW
且当前业务国家为空
→ 无法构造国家+履行供应中心查找键
```

异常原因应明确写：`缺少国家，无法匹配国家运输周期表`。

#### `TRANSIT_NOT_FOUND`

```text
国家、履行供应中心均有效
但国家运输周期表不存在该组合
```

异常原因应明确写：

```text
国家运输周期表无对应组合：<国家> + <履行供应中心>
```

#### `TRANSIT_VALUE_UNAVAILABLE`

```text
国家运输周期表存在对应组合
但运输周期规范化后为空/不可用
```

异常原因应明确写：`已找到国家+供应中心组合，但运输周期无可用值`。

#### `INVALID_TRANSIT_DAYS`

运输周期为非空真实值，但无法解析为合法非负整数自然日时，记录该异常并保留原始值。

### 4.5 异常字段

海运周期相关异常至少应能追溯：

- 合同号；
- 履行供应中心；
- 国家；
- 源文件；
- Sheet；
- 查找组合或原始运输周期值；
- 异常代码；
- 原因。

同一个业务键、同一个根因不得重复生成无意义噪声异常。

## 5. 验收场景

### 5.1 结转国家

- 阿拉伯联合酋长国 → 交付类；
- 沙特阿拉伯 → 交付类；
- 其余五国逐一命中；
- 七国名称带前后空白/全角空格/换行仍命中；
- 非七国不误命中；
- 判断来源仍为遗留量国家。

### 5.2 Excel筛选

- 单列筛选后`数据 → 清除`可用；
- 多列组合筛选后一次清除全部条件；
- 清除后恢复全部数据行；
- 重新打开文件后仍正常；
- 五个业务Sheet均验证。

### 5.3 海运周期

- FCA/FOB/EXW → 5天，无查表异常；
- 普通贸易术语且组合存在 → 正常周期；
- 组合不存在 → `TRANSIT_NOT_FOUND`；
- 国家为空 → `TRANSIT_COUNTRY_MISSING`；
- 组合存在但周期为空/VALUE → `TRANSIT_VALUE_UNAVAILABLE`；
- 非空非法周期 → `INVALID_TRANSIT_DAYS`；
- 到货日期依赖周期而周期不可用时，结果留空且原因可追溯。

## 6. 实施影响

后续代码修复至少检查：

- 国家 identity/alias 规范化；
- 七国结转判断及参数化测试；
- Excel输出筛选实现和桌面Excel验收；
- 海运周期解析、查找和异常分型；
- 异常清单字段完整性；
- 防止同一根因重复报错。

本决策只冻结用户可见行为和业务边界，不强制具体类名或技术实现。

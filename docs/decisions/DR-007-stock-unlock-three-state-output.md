# DR-007 “是否解锁备货”三态输出

- 状态：`CONFIRMED`
- 日期：`2026-08-26`
- 关联：
  - `docs/output-schema.md`
  - `docs/source-schema.md`
  - Issue #17

## 1. 决策

最终输出字段`是否解锁备货`继续来源于要货明细的`备货总控标识`，但不再输出原始Y/N拼接值。

旧输出示例：

```text
Y|Y|N
```

旧拼接规则废止。新输出只允许：

```text
未解锁
部分解锁
已解锁
空
```

## 2. 计算粒度

按同一：

```text
合同号 + 履行供应中心
```

收集去除完全重复明细后的真实记录。

仅有效非空`Y/N`参与三态计算。

## 3. 闭合判断规则

规则按以下顺序执行，避免“只要有N”和“全部为N”重叠：

```text
1. 没有任何有效Y/N
   → 空

2. 所有有效值均为Y
   → 未解锁

3. 所有有效值均为N
   → 已解锁

4. 同时存在Y和N
   → 部分解锁
```

因此，“只要有N就是部分解锁”的准确含义是：

```text
存在N，且同时也存在Y
→ 部分解锁
```

全部为N时必须输出`已解锁`。

## 4. 示例

| 去重后有效备货总控标识 | 输出 |
|---|---|
| `Y` | 未解锁 |
| `Y,Y` | 未解锁 |
| `N` | 已解锁 |
| `N,N` | 已解锁 |
| `Y,N` | 部分解锁 |
| `Y,Y,N` | 部分解锁 |
| `N,N,Y` | 部分解锁 |
| 无有效值 | 空 |

重复值的数量不改变状态；只看有效值集合是`{Y}`、`{N}`还是`{Y,N}`。

## 5. 数据质量边界

- 空单元格、空白字符、`(空白)`、`#VALUE!`及等价VALUE标记按既有规则忽略；
- 非空且非Y/N值继续记录`INVALID_ENUM_VALUE`，不作为有效值参与计算；
- 同一行`备货总控标识`与`发货总控标识`不同，继续记录`CONTROL_FLAG_MISMATCH`；
- `发货总控标识`不直接参与`是否解锁备货`三态计算；
- 完全重复明细必须先去除；
- 无要货明细合同占位行输出空。

如果一组内同时存在有效Y/N和非法值，三态根据有效Y/N计算，非法值异常仍保留。

## 6. 配置与实现边界

现有`stock_flag_delimiter`及原始值拼接逻辑不再定义业务输出。

后续实现应：

1. 建立独立的三态聚合函数或策略；
2. 删除或废弃仅服务于Y/N拼接的配置；
3. 保持稳定内部字段ID仍为`stock_unlocked`；
4. 保持最终显示名仍为`是否解锁备货`；
5. 不把三态中文文案写散在Reader、Writer和GUI中。

## 7. 验收场景

- 全Y → 未解锁；
- 全N → 已解锁；
- Y/N混合 → 部分解锁；
- 无有效值 → 空；
- 完全重复行不改变结果；
- 非法值有异常且不污染有效集合；
- 同行备货/发货标识不一致异常继续存在；
- 无要货占位行为空；
- Excel最终单元格不再出现`Y|N`形式。

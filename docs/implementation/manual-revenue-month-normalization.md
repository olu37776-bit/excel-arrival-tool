---

## 1. 问题

当前读取上一次结果时，两个调整月份字段只接受：

```text
YYYY-MM
```

或Excel日期对象。

因此用户按自然习惯填写：

```text
9月
10月
9
10
2026-9
2026年9月
```

会被判定为：

```text
INVALID_PREVIOUS_MANUAL_MONTH
上期人工月份非空且不是YYYY-MM，已按空白处理
```

这不符合业务使用习惯。上述输入包含足够信息时，应由工具归一化为标准`YYYY-MM`，而不是直接丢弃并报错。

---

## 2. 目标

建立统一的人工月份归一化规则：

```text
用户可使用常见月份写法
→ 工具结合本行自动收入年月判断年份
→ 内部统一为YYYY-MM
→ 新结果统一显示YYYY-MM
```

成功归一化属于正常业务输入，不写入异常清单。

只有确实无法识别，或缺少年份且无法唯一推断时，才给出明确、可操作的提示。

---

## 3. 标准输出

两个调整月份字段在系统内部、继承结果和新生成工作簿中统一保存为：

```text
YYYY-MM
```

示例：

```text
2026-09
2027-01
```

Excel单元格必须继续使用文本格式：

```text
@
```

不得写为Excel日期对象，不得显示为：

```text
Sep-26
9月-26
```

工具不修改用户选择的上一次结果原文件；只在新生成结果中输出归一化后的值。

---

## 4. 空值规则

以下值按人工月份空白处理，不报异常：

- 空单元格；
- 空字符串；
- 半角/全角空格、制表符、换行；
- `(空白)`；
- `VALUE`、`#VALUE`、`#VALUE!`；
- 等价Excel错误空值。

结果：

```text
None
```

空白与无效非空输入必须区分。

---

## 5. 可直接确定年份的输入

以下输入不需要参考本行自动收入年月，直接规范化。

### 5.1 年月文本

允许：

```text
2026-09
2026-9
2026/09
2026/9
2026.09
2026.9
2026年09月
2026年9月
202609
```

统一输出：

```text
2026-09
```

### 5.2 完整日期文本

允许常见完整日期文本，并只取年月：

```text
2026-09-01
2026/09/01
2026.09.01
2026年9月1日
```

统一输出：

```text
2026-09
```

### 5.3 Excel日期或日期时间

如果单元格由`openpyxl`读取为`date`或`datetime`：

```text
2026-09-01
→ 2026-09
```

### 5.4 旧工作簿英文月份显示兼容

为兼容此前错误日期格式产生的工作簿，允许显式英文月份缩写：

```text
Sep-26
Sep-2026
```

统一输出：

```text
2026-09
```

英文月份缩写必须使用程序内固定映射，不依赖操作系统区域语言。

### 5.5 数值年月

Excel单元格为整数或整数浮点时：

```text
202609
202609.0
```

可解释为`YYYYMM`，统一输出：

```text
2026-09
```

非整数数值不得按年月猜测。

### 5.6 Unicode和空白规范化

解析前统一执行：

```text
Unicode NFKC
首尾空白清理
内部无意义空白清理
```

因此：

```text
２０２６年９月
→ 2026-09
```

## 6. 仅包含月份的输入

用户可只填写月份：

```text
9
09
9月
09月
9月份
10
10月
```

也允许Excel数值：

```text
9
10
9.0
10.0
```

前提：数值必须为1至12之间的整数。

仅包含月份时，系统必须结合本行业务参考月份补全年份，禁止直接使用电脑当前年份、文件创建年份或程序运行年份。

## 7. 参考月份选择

### 7.1 调整月份（按RPD）

按以下顺序选择参考月份：

```text
1. 收入年月（按RPD）
2. 收入年月（按CPD）
```

### 7.2 调整月份（按CPD）

按以下顺序选择参考月份：

```text
1. 收入年月（按CPD）
2. 收入年月（按RPD）
```

同口径自动月份优先；只有同口径为空或不可用时，才使用另一口径。

自动收入年月在作为参考前也需规范化：

- `YYYY-MM`文本直接使用；
- `date/datetime`取年月；
- 其他无效值视为不可用参考。

---

## 8. 最近年份推断算法

假设参考月份为：

```text
reference = YYYY-RR
```

用户只填写月份：

```text
MM
```

建立三个候选：

```text
(YYYY-1)-MM
YYYY-MM
(YYYY+1)-MM
```

使用月份序号：

```text
month_index = year * 12 + month
```

计算每个候选与参考月份的绝对月份距离。

### 8.1 唯一最近候选

只有一个候选距离最小时，选择该候选。

示例：

| 参考月份 | 用户输入 | 结果 | 原因 |
|---|---|---|---|
| `2026-06` | `9月` | `2026-09` | 向后3个月最近 |
| `2026-09` | `10` | `2026-10` | 向后1个月最近 |
| `2026-12` | `1月` | `2027-01` | 向后1个月最近 |
| `2026-01` | `12` | `2025-12` | 向前1个月最近 |
| `2026-11` | `2月` | `2027-02` | 向后3个月最近 |

### 8.2 距离并列

如果两个候选与参考月份距离相同，系统不能猜测年份。

典型场景：

```text
参考月份 = 2026-03
用户输入 = 9月

2025-09：相差6个月
2026-09：相差6个月
```

处理：

```text
结果 = 空
异常代码 = MANUAL_MONTH_YEAR_REQUIRED
```

提示：

```text
调整月份只填写了月份，但无法根据本行自动收入年月唯一确定年份；请填写完整年月，例如2026-09
```

## 9. 没有可用参考月份

如果：

```text
收入年月（按RPD）为空
且
收入年月（按CPD）为空
```

用户又只填写：

```text
9月
10
```

系统没有可靠年份依据，不得使用当前年份强行补齐。

处理：

```text
结果 = 空
异常代码 = MANUAL_MONTH_YEAR_REQUIRED
```

提示用户填写完整年月。

如果用户已经填写完整年月，例如：

```text
2026-09
```

即使两个自动收入年月都为空，也应正常接受。

---

## 10. 真正无效的输入

以下输入无法形成合法单一月份：

```text
0
0月
13
13月
2026-00
2026-13
2026-02-30
9-10
9月或10月
九月份左右
abc
```

处理：

```text
结果 = 空
异常代码 = INVALID_PREVIOUS_MANUAL_MONTH
严重级别 = WARNING
```

建议提示：

```text
调整月份无法识别。可填写2026-09、2026年9月、9月或9；仅填写月份时，系统会根据本行自动收入年月补全年份。
```

异常上下文至少包含：

```text
合同号
履行供应中心
字段ID
原始值
同口径自动收入年月
另一口径自动收入年月
```

成功归一化不得生成`INVALID_PREVIOUS_MANUAL_MONTH`或其他信息性异常。

---

## 11. 处理顺序

读取上一次结果的一行业务数据时，不得依赖当前Excel列顺序或配置遍历顺序。

必须分阶段处理：

```text
第一步：
按稳定字段ID定位并缓存本行所有原始单元格

第二步：
解析合同号、履行供应中心、自动RPD收入年月、自动CPD收入年月

第三步：
使用两个自动收入年月作为上下文，归一化两个人工调整月份

第四步：
解析其他人工字段并构造PreviousData/BaseRow
```

这样即使用户移动列、插入非关键列或显示名变化，也不会影响年份推断。

## 13. Excel数值和日期识别边界

数值处理顺序：

```text
1. 单元格被Excel/openpyxl识别为日期
   → 取日期年月

2. 数值为1至12的整数
   → 视为仅月份输入

3. 数值为合法6位YYYYMM
   → 视为完整年月

4. 其他数值
   → 无效，不按Excel序列日期猜测
```

只有单元格格式或`openpyxl`类型明确表示日期时，才允许按Excel序列日期转换。不得把普通金额或编号误判为日期。

**状态：CURRENT FINAL AUTHORITY**  
**文档分支：`enterprise-battle-map-authority`**  
**本地实施分支：`feature/enterprise-battle-map`**  
**适用范围：企业首页导航、页面结构、视觉布局、目标/实时、空间拓展、汇总 API、测试与审查**  
**取代：`enterprise-home-canonical-authority-v1.md`**

---

## 1. 本次修正结论

1. 企业首页当前阶段**暂不建设 Heatmap**；Heatmap 作为后续独立阶段保留，不得在当前首页实现中放空白图、假数据或随机图。
2. 当前首页不得继续显示 `xx`；真实可计算指标必须绑定数据库聚合结果。
3. 三个业务模块的“目标”暂时采用集中静态配置，后续需求人确认后只改一个配置文件。
4. 三个业务模块的“实时”统一由各模块 `已下单金额（$M）`求和得到。
5. 首页“空间拓展”沿用已确认的项目级业务条件，并在五个业务模块范围内汇总。
6. 首页视觉需充分利用企业专项、三张进度卡和空间拓展卡，不再保留大面积无意义空白。

## 2. 页面身份与导航

企业首页是一级“企业”本身对应的页面，不是“总览”子菜单。

```text
企业  ← 点击后进入企业首页
├─ MOX
├─ TOB
└─ ISP&大企
   ├─ ISP
   ├─ 电力
   └─ 大企
```

硬约束：

- 不存在独立“总览”菜单；
- 点击一级“企业”直接进入企业首页；
- 点击“ISP&大企”父项进入 ISP 页面，不得返回企业首页；
- “企业专项”和“空间拓展”都是首页内容，不是导航项；
- 当前阶段首页不包含 Heatmap、明细表格、新增或编辑入口。

## 4. 企业专项

标题：

```text
企业专项
```

定义文案：

```text
聚焦四大客户群，加速方案补齐，形成PtP+PtMP整体解决方案优势，贡献1.2亿$
```

要求：

- 位于首页最上方；
- 复用现有 MOX专项 / TOB专项 / ISP专项 的成熟结构和样式；
- 只替换标题和定义文案；
- 不另建第二套专项视觉组件；
- 文案保持原文，不缩写、不改写；
- 企业专项本身不承担三个模块目标的自动分配；不得把 `1.2亿$`擅自拆分为 MOX、TOB、ISP&大企目标。

## 5. 三个并列经营卡片

企业专项下方固定显示三张同级卡片：

```text
MOX ｜ TOB ｜ ISP&大企
```

每张卡片至少显示：

```text
模块名称
目标：n M$
实时：n M$
达成率：n%
进度条
```

### 5.1 视觉规则

- 桌面宽度下三列等宽并列；
- 卡片高度、标题层级、数字字号和留白一致；
- 所有主要文字居中；
- 参考现有“骨干”页面顶部成熟统计卡样式；
- 目标与实时是同一卡片内部指标，不得拆成独立顶级卡片；
- `实时`使用更高视觉权重；
- `达成率 = 实时 / 目标 × 100%`，仅作为目标和实时的派生展示，不新增业务来源；
- 目标为空或小于等于 0 时不计算达成率，并显示“待确认”；
- 进度条最大视觉值可封顶 100%，但文字达成率允许显示超过 100%；
- 禁止在页面出现 `xx`、随机数字或伪造 0。

### 5.2 目标静态配置

当前目标暂时写死，但必须集中维护，不允许散落在 Vue 模板中。

推荐：

```text
src/enterprise/home/contracts/enterprise-home-contract.js
```

概念格式：

```js
export const ENTERPRISE_HOME_TARGETS = Object.freeze({
  mox: null,
  tob: null,
  ispAndLargeEnterprise: null
})
```

规则：

- 目标值的单位统一为 M$；
- 具体数字优先复用当前项目已经存在且可证明有效的目标常量；
- 不得根据“贡献1.2亿$”自行分摊三个模块目标；
- 若当前没有三个明确目标值，配置保持 `null`，页面显示“待确认”，不得继续显示 `xx`；
- 后续需求人给出目标后，只修改该集中配置和对应测试。

## 6. “实时”计算规则

统一 canonical 字段：

```text
orderedAmountMusd = 已下单金额（$M）
```

### 6.1 MOX 实时

```text
MOX实时 = SUM(MOX.已下单金额（$M）)
```

### 6.2 TOB 实时

```text
TOB实时 = SUM(TOB.已下单金额（$M）)
```

### 6.3 ISP&大企实时

`ISP&大企`是首页聚合分组，范围固定为三张业务表：

```text
ISP
+ 电力
+ 大企（油气矿、广电等）
```

公式：

```text
ISP&大企实时
= SUM(ISP.已下单金额（$M）)
+ SUM(电力.已下单金额（$M）)
+ SUM(大企.已下单金额（$M）)
```

### 6.4 金额处理

- 数据库/API canonical 数值单位统一为 M$；
- `NULL`和空值按 0 参与聚合；
- 非法非数值数据不得悄悄拼接为字符串，应在数据校验中报告并在聚合中排除；
- UI统一使用数字格式化，不把格式化字符串写回数据库；
- 精度与小数位由共享金额 formatter 统一维护，不在三个卡片各写一套。

## 7. 空间拓展汇总

三张经营卡片下方显示一张全宽“空间拓展”卡片，内部三个指标横向并列并居中：

```text
空间拓展
可参与总空间：n M$ ｜ 总项目：n个 ｜ 已落地：n个
```

汇总范围为五个业务模块：

```text
MOX + TOB + ISP + 电力 + 大企
```

每一行仍表示一个独立项目/机会点，项目数量按记录数统计，不按客户去重。

### 7.1 可参与总空间

沿用已经确认的项目条件：

```text
空间洞察 = 已孵化
AND
项目状态 = 跟踪
```

对符合条件的五模块记录的 `整体空间（M$）`求和：

```text
可参与总空间
= SUM(
    overallSpaceMusd
    WHERE spaceInsight = 已孵化
      AND projectStatus = 跟踪
  )
```

这里的“整体空间”明确指金额字段：

```text
整体空间（M$）
```

不得使用：

- 整体空间分类（肥肉/瘦肉/骨头）；
- 整体空间（跳）；
- 26年订货空间（$M）；
- 已下单金额（$M）。

### 7.2 总项目

```text
总项目
= COUNT(projectStatus = 跟踪)
```

范围为五个业务模块全部记录。

### 7.3 已落地

```text
已落地
= COUNT(
    spaceInsight = 已孵化
    AND projectStatus = 跟踪
  )
```

因此：

- `总项目`包含所有“跟踪”记录；
- `已落地`是“跟踪”记录中同时满足“已孵化”的子集；
- `可参与总空间`与`已落地`使用相同记录集合，前者求金额，后者计数。

## 8. 首页汇总 Contract

推荐单一首页 Contract：

```text
src/enterprise/home/contracts/enterprise-home-contract.js
```

它至少定义：

```js
{
  targetConfig,
  realtimeMetrics,
  expansionMetrics,
  display,
  formatterIds
}
```

Metric key 建议：

```text
home.realtime.mox
home.realtime.tob
home.realtime.ispAndLargeEnterprise
home.expansion.availableSpace
home.expansion.totalProjects
home.expansion.landed
```

首页 Contract 描述最终业务规则；Vue 页面不得自行重复编写 SUM/COUNT/WHERE 条件。

## 9. 聚合 API

企业首页不得为了六个数字加载五张完整明细。

推荐提供一个聚合接口：

```text
GET /api/enterprise/home-summary
```

推荐响应：

```json
{
  "modules": {
    "mox": { "target": null, "realtime": 0, "achievementRate": null },
    "tob": { "target": null, "realtime": 0, "achievementRate": null },
    "ispAndLargeEnterprise": { "target": null, "realtime": 0, "achievementRate": null }
  },
  "expansion": {
    "availableSpace": 0,
    "totalProjects": 0,
    "landed": 0
  }
}
```

要求：

- 聚合优先由 API/`database.js`/SQLite 完成；
- 使用各模块最终 canonical DB 映射，不以中文 label 拼 SQL；
- 不返回五张表完整记录；
- 不使用前端 `Promise.all`拉取五份明细后再聚合；
- Summary 加载失败时显示明确错误状态，不退回 `xx`或随机数字；
- 目标值可由服务端或前端集中 Contract 注入，但只能有一个静态 Authority；
- 与数据库 Schema 变更有关时遵循 `V*.sql + _migrations + database.js`机制。

## 11. 页面状态与布局细节

### 11.1 加载状态

- 企业专项可以立即显示；
- 三张经营卡和空间拓展使用一致 skeleton；
- 数据到达后一次替换，不先显示 `xx`；
- 不同指标不得产生布局跳动。

### 11.2 空数据

真实结果为 0 时显示 `0`或`0.00`；目标未确认时显示“待确认”。二者不得混淆。

### 11.3 错误状态

汇总 API 失败时：

- 保留企业专项与页面结构；
- 指标区域显示“数据加载失败”；
- 允许使用现有统一重试机制；
- 浏览器控制台保留可诊断错误；
- 不展示旧缓存或假数字冒充实时值。

### 11.4 响应式

- 宽屏：三张经营卡一行三列；
- 较窄：允许按现有设计系统换行；
- 空间拓展卡保持全宽；
- 不通过缩小字体制造拥挤布局。

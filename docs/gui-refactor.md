# Excel 到货与收入月份工具 GUI 重构设计

- 文档 ID：`GUI-REFACTOR-DESIGN`
- 当前版本：`0.1`
- 状态：`ACTIVE-DRAFT`
- 日期：`2026-08-25`
- 适用仓库：`olu37776-bit/excel-arrival-tool`
- 需求依据：
  - `docs/requirements-baseline.md`
  - `docs/source-schema.md`
  - `docs/output-schema.md`
  - `docs/comparison-output.md`

> 本文只规定 GUI 的职责、交互、视觉、线程模型和与 Application 的接口。业务规则仍以需求文档和领域实现为准，GUI 不得复制或重写 Excel 计算逻辑。

## 1. 不可变输入输出前提

### GUI-IO-001 `[CONFIRMED]` 输入是四个独立 Excel 文件

本期输入由四个彼此独立的 Excel 源文件组成：

1. 遗留量 Excel；
2. 当月订货 Excel；
3. 要货明细 Excel；
4. 国家运输周期 Excel。

当前 GUI 继续为四个源文件分别提供选择入口。不得改成“选择一个包含多个 Sheet 的输入工作簿”。

当月订货允许某个合同号无匹配数据，但源文件本身仍属于本次运行的四个输入文件之一。

### GUI-IO-002 `[CONFIRMED]` 输出是一个多 Sheet 工作簿

一次运行只生成一个结果 Excel，当前包含：

1. `基表`；
2. `RPD跨月变化`；
3. `CPD跨月变化`；
4. `供应需要提拉诉求清单粗表`；
5. `异常清单`；
6. 必要的隐藏元数据 Sheet。

GUI 只选择一个输出文件路径，不为每个 Sheet 分别选择文件。

### GUI-IO-003 `[CONFIRMED]` 上期结果是可选输入

`上一次成功结果`用于：

- 三个人工字段继承；
- RPD/CPD 跨期变化比较。

首次运行可不选择上期结果。

## 2. 当前 GUI 现状

当前实现位于：

```text
src/revenue_tool/gui.py
```

技术为 `Tkinter + ttk`，当前界面包含：

- 四个独立源文件选择框；
- 一个输出文件选择框；
- 一个上一次成功结果选择框；
- “开始生成”和“退出”按钮；
- 一行状态文字；
- 处理完成后通过 MessageBox 显示结果数量。

### 2.1 当前做对的部分

- 输入确实按四个独立文件选择；
- 上期结果可选；
- 输出只选择一个 `.xlsx` 文件；
- GUI 没有直接实现 BG、海运周期、RPD/CPD、到货日期等业务规则；
- GUI 调用 Application 流程，而不是直接操作 openpyxl。

### 2.2 当前需要重构的部分

1. GUI 直接依赖具体函数 `run_pipeline(...)` 及其参数列表；
2. `run_pipeline()`在 GUI 主线程同步执行，大文件处理时窗口可能卡顿或显示未响应；
3. 文件输入、历史输入、输出设置和处理状态缺少清晰分区；
4. 只有一行状态文字，没有稳定的运行状态模型；
5. 处理结果主要依赖弹窗，关闭弹窗后缺少持续可见的结果摘要；
6. 无“打开结果文件”“打开所在文件夹”快捷操作；
7. 文件选择后缺少明确的有效/无效状态提示；
8. 视觉使用默认 ttk 样式，层次弱，像调试表单；
9. GUI 中存在具体业务统计字段的硬编码展示，后续扩展容易继续堆叠；
10. 界面代码、线程控制、参数校验、消息拼接集中在一个文件中。

## 3. 重构目标

### GUI-GOAL-001 功能目标

GUI 应让普通业务用户完成以下任务：

1. 分别选择四个源 Excel；
2. 可选选择上一次成功结果；
3. 选择结果保存位置；
4. 清楚看到输入是否就绪；
5. 点击一次开始处理；
6. 处理期间看到当前阶段和进度状态；
7. 处理结束后看到核心数量和异常数量；
8. 一键打开结果文件或输出目录；
9. 出现技术失败时得到可理解的错误提示；
10. 出现业务数据异常时仍能拿到结果文件和异常清单。

### GUI-GOAL-002 工程目标

- GUI 只依赖稳定的 Application 接口；
- GUI 不知道业务计算细节；
- GUI 不直接实例化 Excel Reader、Writer 或领域策略；
- 处理任务不阻塞主线程；
- GUI 框架未来可替换，不影响 Application 和 Domain；
- 结果统计字段通过 `RunResult`读取，不重新扫描输出 Excel；
- 所有用户可见文本集中管理，避免散落字符串；
- 文件路径校验、运行状态和展示状态可以单独测试。

## 4. 技术选择

### GUI-TECH-001 `[RECOMMENDED]` PySide6

GUI 重构目标技术采用：

```text
PySide6 + Qt Widgets + 少量 QSS
```

选择原因：

- 原生桌面窗口，不需要启动本地 Web 服务；
- 文件选择、线程、信号、布局和高 DPI 支持成熟；
- 比默认 Tkinter 更容易实现稳定、克制的现代界面；
- 后续增加历史记录、设置或结果详情时不需要再次换框架；
- 可继续通过 PyInstaller 打包 Windows EXE。

### 4.1 不采用 Web 前端

当前版本不采用 React、Vue、Electron、Tauri 或浏览器页面，原因是：

- 当前只有一个主操作页面；
- 不需要本地 HTTP 服务和端口；
- 不需要前后端协议、进程管理和额外构建链；
- 桌面文件选择和本地 EXE 分发更符合实际使用方式。

### 4.2 视觉原则

PySide6 只用于提供更好的布局、状态和桌面体验，不建设华丽动效或复杂主题。

禁止：

- 渐变背景；
- 大面积高饱和色；
- 玻璃拟态；
- 多余动画；
- 仪表盘图表；
- 自动轮播；
- 为了“高级感”增加无业务意义的页面。

## 5. GUI 与业务核心的边界

### 5.1 目标依赖关系

```text
PySide6 MainWindow
        ↓
GUI ViewModel / Presenter
        ↓
RunApplicationService
        ↓
Domain + Ports + Adapters
```

GUI 不得直接依赖：

- `openpyxl`；
- 领域策略类；
- Excel 列名和列号；
- 输出 Sheet 的单元格结构；
- 当前 `run_pipeline()`内部实现。

### 5.2 稳定运行请求

Application 应提供稳定请求对象：

```python
from dataclasses import dataclass
from pathlib import Path

@dataclass(frozen=True)
class RunRequest:
    legacy_path: Path
    monthly_order_path: Path
    demand_detail_path: Path
    transit_path: Path
    output_path: Path
    previous_path: Path | None = None
```

GUI 只负责收集和验证这些路径，然后提交 `RunRequest`。

### 5.3 稳定运行结果

```python
@dataclass(frozen=True)
class RunResult:
    output_path: Path
    base_count: int
    rpd_change_count: int
    cpd_change_count: int
    supply_pull_count: int
    issue_count: int
    status: str
```

`status`建议值：

- `SUCCESS`：成功且无异常；
- `SUCCESS_WITH_ISSUES`：成功生成结果，但存在异常清单；
- `FAILED`：技术失败，未生成有效结果。

### 5.4 进度事件

Application 通过可选进度接口上报阶段，不让 GUI 推测当前执行到哪里：

```python
@dataclass(frozen=True)
class ProgressEvent:
    stage: str
    percent: int | None
    message: str
```

建议用户可见阶段：

1. 检查文件；
2. 读取源数据；
3. 校验并整理数据；
4. 计算到货与收入月份；
5. 对比上期结果；
6. 写入结果文件；
7. 完成。

百分比无法可靠估计时使用不确定进度条，不虚构精确进度。

## 7. 控件与交互

### 7.1 源文件行

四个源文件每行包括：

- 业务名称；
- 只读路径框；
- `选择`按钮；
- 状态文本或图标。

状态只使用三种：

- `未选择`；
- `已选择`；
- `无效`。

完整路径通过悬浮提示显示，主界面优先显示文件名，避免超长路径破坏布局。

### 7.2 上期结果

- 明确标记“可选”；
- 未选择时显示“首次运行可留空”；
- 选择后显示文件名和路径提示；
- 可提供一个简洁的`清除`按钮。

### 7.3 输出路径

- 使用保存文件对话框；
- 默认文件名建议：

```text
到货收入结果_YYYYMMDD_HHmm.xlsx
```

- 记忆用户上次选择的输出目录；
- 不允许覆盖四个源文件或上期结果；
- 已存在同名输出时，在开始前给出覆盖确认。

### 7.4 开始按钮

按钮状态：

- 未满足最小输入条件：禁用；
- 输入就绪：启用；
- 正在运行：禁用并显示“处理中”；
- 运行完成或失败：恢复启用。

不设置多个同级主按钮。`开始生成`是页面唯一主操作。

### 7.5 处理结果

处理成功后在窗口内持续显示：

- 基表行数；
- RPD变化数；
- CPD变化数；
- 供应需要提拉数；
- 异常数；
- 输出文件路径。

操作按钮：

- `打开结果`；
- `打开所在文件夹`。

当异常数大于 0 时，结果状态显示为“已完成，存在数据异常”，而不是“失败”。

## 8. 界面状态模型

GUI 使用明确状态机，禁止依靠零散布尔变量决定控件状态。

```text
EMPTY
  ↓ 选择有效文件
READY
  ↓ 开始
RUNNING
  ├─ 成功无异常 → SUCCESS
  ├─ 成功有异常 → SUCCESS_WITH_ISSUES
  └─ 技术失败   → FAILED
```

### 8.1 各状态行为

| 状态 | 文件控件 | 开始按钮 | 进度 | 结果区 |
|---|---|---|---|---|
| `EMPTY` | 可编辑 | 禁用 | 隐藏 | 空状态 |
| `READY` | 可编辑 | 启用 | 隐藏 | 保留上次结果或空 |
| `RUNNING` | 禁用 | 禁用 | 显示 | 显示处理中 |
| `SUCCESS` | 可编辑 | 启用 | 完成 | 成功摘要 |
| `SUCCESS_WITH_ISSUES` | 可编辑 | 启用 | 完成 | 成功+异常摘要 |
| `FAILED` | 可编辑 | 启用 | 停止 | 技术错误摘要 |

## 9. 线程模型

### GUI-THREAD-001 `[REQUIRED]` 业务处理不得运行在 UI 主线程

当前同步调用会在大文件处理中阻塞窗口。重构后采用：

```text
Qt 主线程：窗口、控件、状态更新
Worker 线程：RunApplicationService.run(request)
Signal：进度、成功、失败
```

建议组件：

```text
RunWorker(QObject)
RunThreadController
MainWindow
```

约束：

- Worker 不直接操作任何 Qt 控件；
- MainWindow 不直接捕获领域内部对象；
- 通过不可变事件传递进度和结果；
- 运行时禁止重复点击开始；
- 用户关闭窗口时，如果正在运行，应提示“处理尚未完成，是否退出”；
- 第一版不承诺可中途取消，因为 openpyxl 写文件过程不适合强制终止。

## 10. 校验与错误展示

### 10.1 开始前校验

GUI 只负责文件级校验：

- 四个源文件均已选择；
- 文件存在；
- 扩展名受支持；
- 四个输入路径互不相同；
- 输出路径不覆盖输入或上期结果；
- 上期结果存在且可读。

字段、Sheet、数据类型和业务内容校验仍由 Application/Adapter 负责。

### 10.2 技术失败

以下情况使用模态错误对话框，并在主窗口保留错误摘要：

- 输入文件无法打开；
- 配置无法加载；
- 输出文件无法保存；
- 程序内部未处理异常。

错误提示结构：

```text
发生了什么
可能原因
建议操作
```

不得只显示 Python 异常类型和堆栈。

### 10.3 业务与数据异常

业务异常不弹出大量消息框。处理完成后：

- 结果区显示异常数量；
- 提示“详细原因见结果文件中的异常清单”；
- 允许直接打开结果文件。

## 11. 视觉规范

目标风格：克制、清晰、偏 Windows 商务工具。

### 11.1 颜色

建议令牌：

```text
窗口背景：#F5F7FA
卡片背景：#FFFFFF
边框：    #E5E7EB
主文字：  #1F2937
次文字：  #6B7280
主色：    #2563EB
成功：    #15803D
警告：    #B45309
错误：    #B91C1C
```

使用规则：

- 页面只保留一个主色；
- 成功、警告、错误色仅用于状态；
- 不用大面积彩色背景；
- 不仅依赖颜色表达状态，必须同时有文字。

### 11.2 字体

优先使用系统字体：

```text
Segoe UI / Microsoft YaHei UI
```

建议层级：

- 主标题：18–20 px，半粗体；
- 区块标题：14–16 px，半粗体；
- 正文和控件：12–14 px；
- 辅助说明：11–12 px。

### 11.3 间距和尺寸

- 窗口推荐初始尺寸：`920 × 620`；
- 最小尺寸：`820 × 560`；
- 页面外边距：24 px；
- 区块间距：16 px；
- 控件高度：36–40 px；
- 卡片圆角：6–8 px；
- 阴影可不用，或仅使用非常轻微边框区分层次。

### 11.4 图标

只在以下位置使用简单线性图标：

- 文件选择；
- 成功/警告/失败状态；
- 打开文件；
- 打开文件夹。

不为每一个字段增加装饰图标。

GUI 代码不再集中在一个 `gui.py`：

```text
src/revenue_tool/
├─ entrypoints/
│  └─ gui/
│     ├─ __init__.py
```

职责：

| `ui_text.py` | 用户可见文案集中定义 |
| `styles.qss` | 克制的视觉样式 |

### 12.1 兼容入口

保留：

```text
python -m revenue_tool.gui
```

或者提供新的命令：

```text
revenue-tool-gui
```

`run_tool.bat`和 EXE 最终都指向新的 GUI 启动入口。

## 13. 用户偏好持久化

GUI 可在本地保存非业务偏好：

```text
%LOCALAPPDATA%/ExcelArrivalTool/ui-settings.json
```

允许保存：

- 上次打开目录；
- 上次输出目录；
- 窗口尺寸和位置；
- 是否自动打开结果文件。

不得保存：

- 真实 Excel 内容；
- 合同数据；
- 结果表数据；
- 用户手工调整值；
- GitHub 凭据。

默认不自动保存完整业务文件路径列表；如后续确需“最近文件”，应单独确认隐私和公司环境要求。

## 14. 高 DPI、键盘和可用性

- 支持 Windows 125%、150%缩放；
- Tab 顺序按页面从上到下；
- Enter 在 READY 状态可触发开始；
- Escape 不应在运行中直接关闭程序；
- 文件状态必须同时使用文字，不只使用颜色；
- 超长文件名使用省略显示，完整路径可悬浮查看；
- 窗口缩放时路径框伸缩，按钮宽度保持稳定。

## 15. 测试策略

### 15.1 ViewModel 单元测试

不启动真实 Excel 计算，验证：

- 四个输入齐全后才进入 READY；
- 路径重复时无法开始；
- 输出覆盖输入时无法开始；
- 上期结果为空仍可运行；
- RUNNING 状态禁用输入和开始按钮；
- SUCCESS_WITH_ISSUES 正确显示异常数量；
- FAILED 状态保留可重试能力。

### 15.2 GUI 组件测试

使用 `pytest-qt`验证：

- 选择文件后路径和状态更新；
- 点击开始后 Worker 被提交；
- 进度信号更新进度区；
- 成功信号显示结果卡片；
- 失败信号显示技术错误；
- 打开结果和文件夹调用正确系统接口。

### 15.3 Application 替身

GUI 测试使用 Fake Application Service：

```python
class FakeRunService:
    def run(self, request, progress): ...
```

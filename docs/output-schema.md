## 2. RPD 命名正式确认

业务方已确认：源要货明细表中的准确字段为 `RPD日期`，最终输出字段为：

- `RPD`
- `到货日期（按RPD）`
- `收入年月（按RPD）`

因此 `RPD` 为正式 canonical name。此前 POC/旧需求中出现的 `PRD` 属于旧假设，后续领域模型、配置、代码、测试和历史对比均应迁移为 RPD。

## 3. 输出名称与业务字段解耦

### OS-NAME-001 `[CONFIRMED]`

输出表头名称未来允许变化，例如“地区部”“供应中心”等显示名可调整；这不应改变业务字段绑定。

实现必须使用稳定内部字段 ID，例如：

- `contract_no`
- `supply_center`
- `rpd`
- `arrival_date_rpd`
- `manual_revenue_month`

输出标题单独由输出模板/配置定义。

## 4. 人工维护字段与跨次继承

以下字段由用户人工填写，不由本次源表重新计算：

1. `收入分段类别`
2. `是否手工调整收入月份`
3. `手工调整收入月份`
4. `调整备注`

当前确认规则：

- 新一轮运行生成基表时，若能在上一轮结果中找到对应业务记录，则继承上一轮这四个字段；
- 本次计算不得覆盖已继承的人工值；
- 首次出现、且上一轮没有对应记录时，这四个字段默认为空，等待人工填写；
- 当前稳定匹配键候选为 `合同号 + 供应中心`，仍需确认供应中心变化/拆分/合并场景下如何继承。

## 5. 已确认的日期与运输计算

### 5.1 日期聚合粒度

同一：

`合同号 + 供应中心`

范围内：

- ATA = `MAX(天_ATA)`；
- ASD = `MAX(ASD日期)`；
- RPD = `MIN(RPD日期)`；
- CPD = `MAX(CPD日期)`。

### 5.2 到货日期（按 RPD）

```text
若 ATA 有值：MAX(ATA)
否则若 ASD 有值：MAX(ASD)
否则：MIN(RPD) + 最终海运周期
```

ATA、ASD 命中时不加海运周期。

### 5.3 到货日期（按 CPD）

```text
若 ATA 有值：MAX(ATA)
否则若 ASD 有值：MAX(ASD)
否则：MAX(CPD) + 最终海运周期
```

ATA、ASD 命中时不加海运周期。

### 5.4 海运周期

基础海运周期按：

`国家 + 供应中心`

从国家运输周期表取得 `运输周期`，单位为自然日。特殊贸易类型可以对基础周期进行业务规则调整，但不得改变基础字段绑定。

### 5.5 收入年月

- `收入年月（按RPD）` = `到货日期（按RPD）` 的年月；
- `收入年月（按CPD）` = `到货日期（按CPD）` 的年月。

## 8. 金额字段的未决问题

`遗留量` 与 `当月新订货` 的源字段已确定，但遗留量表和当月订货表没有供应中心，而最终输出粒度是 `合同号 + 供应中心`。

因此仍需确认：同一合同有多个供应中心时，合同级金额如何落到多行，避免后续汇总重复计算。

## 9. 字段解析策略

详细规则见 `docs/source-schema.md`。原则为：

1. 规范化后精确匹配优先；
2. 明确 alias 后精确匹配；
3. 只有配置显式允许时才使用 `contains`；
4. `contains` 必须唯一命中；多个候选立即报错；
5. 禁止使用无限制模糊相似度自动选列。

这样既允许适应类似“地区部/地区部中文/地区部中文名称”的可控变化，又避免把“设备订未收-新”和其他相近金额字段误认为同一字段。

## 10. 当前下一步优先确认事项

1. 地区部、客户群、项目名称的来源优先级；
2. 结转类型的定义和计算规则；
3. 多个供应中心发货、是否解锁备货、分批发货、多次要货、分批供应的准确判定；
4. 同一合同多供应中心时，遗留量/当月新订货如何呈现；
5. 最终合同全集如何产生；
6. 手工调整收入月份对最终统计口径的作用。

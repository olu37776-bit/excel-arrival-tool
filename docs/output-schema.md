## 2. 输出名称与源字段解耦

输出标题未来可以变化。业务代码只依赖稳定内部字段 ID 和源字段配置；不能依赖输出列名，也不能依赖 Excel 固定列字母。

RPD 已正式确认：源字段为 `RPD日期`，此前 POC/旧文档中的 PRD 属于错误假设，后续代码和测试必须迁移到 RPD。

## 3. 合同级字段与供应中心级字段

### BR-CONTRACT-FIELD-001 `[CONFIRMED]`

`遗留量` 与 `当月新订货` 都是合同级字段：

- 遗留量按合同号从遗留量表取得；
- 当月新订货按合同号从当月订货表取得；
- 它们不按供应中心拆分，也不需要分摊；
- 当同一合同因为多个供应中心展开成多行时，这两个合同级值随合同复制到对应的每个供应中心行。

当前工具不做收入金额汇总，因此不对这些重复展示的合同级金额做求和、分摊或去重统计。

## 4. 已确认的属性字段来源优先级

- BG：遗留量 → 当月订货 → 要货明细；
- 地区部：遗留量 → 要货明细；
- 国家：遗留量 → 要货明细；
- 客户群：遗留量 → 要货明细；
- 项目名称：遗留量 → 要货明细；
- 贸易术语：要货明细；
- 供应中心：要货明细。

当月订货不参与地区部、客户群、项目名称的回退链。

## 5. 结转类型

### BR-CARRYOVER-001 `[CONFIRMED]`

结转类型只根据**遗留量表自身的 `国家中文名称`**判断，不使用输出“国家”经过回退后的结果。

若遗留量表 `国家中文名称` 属于以下任一国家：

- 阿拉伯联合酋长国
- 巴基斯坦
- 巴西
- 菲律宾
- 马来西亚
- 沙特阿拉伯
- 印度尼西亚

则：

```text
结转类型 = 交付类
```

其他值（包括遗留量表没有该国家值）当前规则为留空。

## 6. 多个供应中心发货

### BR-MULTI-SC-001 `[CONFIRMED]`

按合同号判断：

```text
同一合同号对应的不同“供应中心简称”数量 > 1 → Y
否则 → N
```

该标记是合同级属性，可复制到该合同的每个供应中心输出行。

## 7. 备货/发货总控与分批发货

### BR-STOCK-001 `[PARTIALLY_CONFIRMED]`

`是否解锁备货` 来源于要货明细 `备货总控标识`，源值为 Y/N。

如果同一 `合同号 + 供应中心` 下存在多条记录，当前暂不强行压缩为单个 Y/N；先保留每次出现的标识信息，等待后续业务确认最终展示形式。

### BR-SHIP-SPLIT-001 `[CONFIRMED]`

业务方确认：`备货总控标识` 与 `发货总控标识` 应同步。

分批发货判断关注同一 `合同号 + 供应中心` 下是否存在多条总控/发货记录：

```text
记录数 > 1 → 分批发货 = Y
否则 → N
```

不要求这些记录的 Y/N 值彼此不同；即使是 `Y/Y` 或 `N/N`，只要存在多条对应记录，也属于分批发货。

单次发货记录可能同时携带 ATA、ASD、RPD、CPD，不以某个日期字段是否非空单独判断分批。

## 8. 多次要货与分批供应

### BR-MULTI-DEMAND-001 `[CONFIRMED]`

按同一 `合同号 + 供应中心` 统计不同有效 RPD 日期：

```text
不同 RPD 日期数 > 1 → 多次要货 = Y
否则 → N
```

业务上理论上不会出现完全相同 RPD 日期重复表示两次要货；实现仍按“不同有效日期数”判断，以避免重复数据造成误判。

### BR-SPLIT-SUPPLY-001 `[CONFIRMED]`

按同一 `合同号 + 供应中心` 统计不同有效 CPD 日期：

```text
不同 CPD 日期数 > 1 → 分批供应 = Y
否则 → N
```

同样按不同有效日期数判断。

## 9. 日期与到货计算

同一 `合同号 + 供应中心` 内：

- ATA = MAX(`天_ATA`)
- ASD = MAX(`ASD日期`)
- RPD = MIN(`RPD日期`)
- CPD = MAX(`CPD日期`)

按 RPD 到货日期：

```text
有 ATA → MAX(ATA)
否则有 ASD → MAX(ASD)
否则 → MIN(RPD) + 最终海运周期
```

按 CPD 到货日期：

```text
有 ATA → MAX(ATA)
否则有 ASD → MAX(ASD)
否则 → MAX(CPD) + 最终海运周期
```

ATA/ASD 命中时不加海运周期。收入年月分别取对应到货日期的年月。

## 10. 当前工具范围

### BR-SCOPE-001 `[CONFIRMED]`

当前版本先完成：

- 四张源表读取与字段校验；
- 目标基表生成；
- 合同级属性和供应中心级属性填充；
- 派生标记；
- 海运周期与到货日期计算；
- 收入年月字段生成；
- 四个人工字段跨次继承；
- 多次运行的 RPD 跨月延迟识别。

当前**不做收入金额汇总、收入统计报表或金额聚合**。输出中保留“遗留量”“当月新订货”只是为了基表展示和后续使用。

## 11. 人工维护字段

以下四列不由本次源表计算，默认从上一轮同一业务记录继承：

- 收入分段类别
- 是否手工调整收入月份
- 手工调整收入月份
- 调整备注

首次出现且上一轮无对应记录时留空。稳定继承键当前候选为 `合同号 + 供应中心`。

## 12. 仍待确认的高优先规则

1. 最终合同全集/输出行如何形成；
2. `是否解锁备货` 在同组多条记录时，最终输出是保留组合、取最新、取任一值还是其他展示方式；
3. 手工调整收入月份是否覆盖某个自动收入年月用于后续用途；
4. ATA/ASD 已命中时，运输周期规格缺失是否仍作为阻塞错误。

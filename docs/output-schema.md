## 2. 名称与字段解耦

### OS-NAME-001 `[CONFIRMED]`

输出标题未来可以变化。核心业务代码只使用稳定内部字段 ID，不依赖输出标题，也不依赖固定 Excel 列字母。

例如内部字段 `supply_center`：

- 要货明细源字段：`供应中心简称`；
- 国家运输周期源字段：`供应中心`；
- 当前输出显示名：`履行供应中心`。

### OS-NAME-002 `[CONFIRMED]` RPD

正式 canonical name 为 `RPD`：

- 源字段：`RPD日期`；
- 输出字段：`RPD`；
- 派生字段：`到货日期（按RPD）`、`收入年月（按RPD）`。

旧 POC 或旧说明中的 `PRD` 不得继续用于正式领域模型和配置。

## 3. 最终业务粒度

### OS-GRAIN-001 `[CONFIRMED]`

基表一行的粒度为：

```text
合同号 + 履行供应中心
```

同一合同存在多个履行供应中心时，每个中心输出一行。

### OS-GRAIN-002 `[TBD]` 行集合来源

最终合同全集及展开算法尚未完全确认，详见主需求基线 `BR-GRAIN-003`。

## 4. 合同级字段

### OS-CONTRACT-001 `[CONFIRMED]`

`遗留量` 与 `当月新订货` 按合同号取得：

- 不按履行供应中心拆分；
- 不分摊；
- 同一合同展开为多行时复制到每个履行供应中心行；
- 当前版本不做金额汇总。

### OS-CONTRACT-002 `[CONFIRMED]` 可选当月订货

当月订货表允许缺失。整表缺失或某合同未匹配时，不得阻塞整个运行，也不得把“未提供”静默当成金额 0。

当前输出空白还是 0 为 `TBD`，推荐空白。

### OS-CONTRACT-003 `[TBD]` 同合同多行

若遗留量表或当月订货表中同一合同出现多条记录，金额字段应取第一条、最大、求和或报错尚未确认。实现前必须结合本地数据审计和业务确认冻结。

## 5. 属性字段来源与冲突

### OS-ATTR-001 `[CONFIRMED]` 来源优先级

- BG：遗留量 `行销产品维BG中文名称` → 当月订货同名字段（若表存在）→ 要货明细 `BG_CN`；
- 地区部：遗留量 `地区部中文名称` → 要货明细 `地区部`；
- 国家：遗留量 `国家中文名称` → 要货明细 `国家中文名称`；
- 客户群：遗留量 `客户群中文名称` → 要货明细 `签约客户群`；
- 项目名称：遗留量 `交付项目中文名称` → 要货明细同名字段；
- 贸易术语：要货明细 `贸易术语`；
- 履行供应中心：要货明细 `供应中心简称`。

### OS-ATTR-002 `[CONFIRMED]` 国家唯一性

同一合同必须对应唯一国家。出现多个不同国家时产生数据异常，不允许取第一条。

### OS-ATTR-003 `[TBD]` 其他文本冲突

同一合同或同一合同+履行供应中心下，如果 BG、地区部、客户群、项目名称、贸易术语等出现多个不同非空值，最终取值或报错规则尚未冻结。不得在实现中静默选择第一条。

## 6. 结转类型

### OS-CARRYOVER-001 `[CONFIRMED]`

只读取遗留量表自身的 `国家中文名称`。

以下国家输出 `交付类`：

- 阿拉伯联合酋长国
- 巴基斯坦
- 巴西
- 菲律宾
- 马来西亚
- 沙特阿拉伯
- 印度尼西亚

其他情况留空。不得使用要货明细回退得到的国家触发结转类型。

## 7. 发货与供应标记

### OS-MULTI-SC-001 `[CONFIRMED]`

```text
同一合同的不同有效履行供应中心数量 > 1 → Y
否则 → N
```

### OS-STOCK-001 `[PROVISIONAL]`

`是否解锁备货` 来源于 `备货总控标识`，源值为 Y/N。

同一合同+履行供应中心存在多条记录时，当前要求保留每次出现的值，但以下仍为 `TBD`：

- 是否去重；
- 保留源顺序还是固定排序；
- 单元格分隔符；
- 空值是否保留；
- 非 Y/N 值如何处理。

### OS-SPLIT-SHIPMENT-001 `[CONFIRMED]`

同一合同+履行供应中心下相关总控/发货记录数大于 1 时：

```text
分批发货 = Y
```

否则为 `N`。多条记录值可以相同，不要求同时出现 Y 和 N。

`备货总控标识` 与 `发货总控标识` 应同步；若不一致，应进入异常或告警，具体等级待确认。

### OS-MULTI-DEMAND-001 `[CONFIRMED]`

```text
不同有效 RPD 日期数 > 1 → 多次要货 = Y
否则 → N
```

### OS-SPLIT-SUPPLY-001 `[CONFIRMED]`

```text
不同有效 CPD 日期数 > 1 → 分批供应 = Y
否则 → N
```

## 8. 海运周期

### OS-TRANSIT-001 `[CONFIRMED]` 基础匹配

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

运输周期单位为自然日，缺失时不得默认 0。

### OS-TRANSIT-002 `[PROVISIONAL]` 特殊贸易类型

部分特殊贸易类型会调整基础运输周期。具体类型与调整方式未补充，但必须在独立规则层完成，不得改写源字段绑定或日期优先级。

### OS-TRANSIT-003 `[TBD]` ATA/ASD 命中时的规格缺失

ATA 或 ASD 已命中时，到货日期本身不需要运输周期。此时运输周期规格缺失是阻塞错误还是非阻塞告警尚未确认。

## 9. 日期聚合与到货日期

### OS-DATE-001 `[CONFIRMED]`

同一合同+履行供应中心内：

- ATA = `MAX(天_ATA)`；
- ASD = `MAX(ASD日期)`；
- RPD = `MIN(RPD日期)`；
- CPD = `MAX(CPD日期)`。

空值不参与聚合；非空但无法解析为日期的值产生数据异常。

### OS-ARRIVAL-RPD-001 `[CONFIRMED]`

```text
有 ATA → MAX(ATA)，不加海运周期
否则有 ASD → MAX(ASD)，不加海运周期
否则 → MIN(RPD) + 最终海运周期
```

### OS-ARRIVAL-CPD-001 `[CONFIRMED]`

```text
有 ATA → MAX(ATA)，不加海运周期
否则有 ASD → MAX(ASD)，不加海运周期
否则 → MAX(CPD) + 最终海运周期
```

### OS-MONTH-001 `[CONFIRMED]`

- 收入年月（按RPD）= 到货日期（按RPD）的年月；
- 收入年月（按CPD）= 到货日期（按CPD）的年月。

## 10. 收入分段类别

### OS-SEGMENT-001 `[CONFIRMED]`

每次运行重新计算，粒度为合同号+履行供应中心：

```text
1. 多次要货 = Y → 需判断
2. 多次要货 != Y，且 ATA 或 ASD 任一有值 → 发未收
3. 多次要货 != Y，ATA/ASD 为空，且 RPD 或 CPD 任一有值 → 订未发
4. 多次要货 != Y，ATA/ASD/RPD/CPD 全空 → 不要货
```

日期非空但无法解析时不得按“空”继续分类。

## 11. 人工字段

### OS-MANUAL-001 `[CONFIRMED]`

只有最后三个字段为人工维护字段：

- 是否手工调整收入月份；
- 手工调整收入月份；
- 调整备注。

首次运行或上一轮无同一合同号+履行供应中心记录时为空；后续从上一轮基表继承。本次自动计算不得覆盖。

`收入分段类别` 每次重新计算，不继承。详细见 `docs/decisions/DR-001-manual-adjustment-fields.md`。

## 12. 格式建议

- 金额：保留 Excel 数值类型，显示格式由目标模板决定；
- ATA/ASD/RPD/CPD、到货日期：Excel 日期值，建议显示 `yyyy-mm-dd`；
- 收入年月与手工调整收入月份：建议显示 `yyyy-mm`；
- Y/N 标记：统一大写文本；
- 首次人工字段、缺失的可选来源：保持真正空单元格，不写字符串 `NULL`、`None` 或 `N/A`，除非后续另有业务规定。

## 13. 跨期变化输出

RPD/CPD 收入年月变化不作为基表附加列，而是在同一工作簿的独立 Sheet 中输出。详细规则见 `docs/comparison-output.md`。

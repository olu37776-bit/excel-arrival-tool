- 关联需求基线：`docs/requirements-baseline.md`

> 本文件记录源 Excel 的稳定业务字段契约。输出表显示名称允许后续变化，但业务代码不得通过输出显示名称反向推断源字段。核心代码使用稳定内部字段 ID；源字段映射由配置承载。

## 1. 输入表存在性

### FS-INPUT-001 `[CONFIRMED]` 当月订货表为可选输入

`当月订货表`不是每次运行都必然存在。月初可能尚未完成当月订货取数，因此：

- 缺少当月订货表不得阻塞整次运行；
- 当月订货相关字段应进入“数据不可用”分支，而不是报缺表致命错误；
- BG 等存在回退链的字段，在当月订货表缺失时直接跳过该来源，继续使用下一来源；
- `当月新订货` 在未提供当月订货表时如何展示（空值还是 0）仍需业务确认，默认不得把“未提供”静默等价为金额 0。

其他输入表的必选/可选状态后续逐表冻结。

## 6. 已确认的多来源优先级

- `BG`：遗留量 `行销产品维BG中文名称` → 当月订货 `行销产品维BG中文名称` → 要货明细 `BG_CN`；若当月订货表未提供，则跳过第二来源；
- `国家`：遗留量 `国家中文名称` → 要货明细 `国家中文名称`；
- `地区部`：遗留量 `地区部中文名称` → 要货明细 `地区部`；
- `客户群`：遗留量 `客户群中文名称` → 要货明细 `签约客户群`；
- `项目名称`：遗留量 `交付项目中文名称` → 要货明细 `交付项目中文名称`。

当月订货表不参与地区部、客户群、项目名称的回退链。

## 7. 字段匹配与解耦策略

### FS-MATCH-001 `[CONFIRMED]` 三层解耦

必须区分：

1. 稳定内部字段 ID，例如 `bg`、`contract_no`、`supply_center`；
2. 每张源表自己的实际字段名，例如 `行销产品维BG中文名称`、`BG_CN`；
3. 最终输出显示名，例如 `BG`、`履行供应中心`。

三者不得互相绑定。源字段名变化时只调整字段映射配置；输出表头变化时只调整输出模板/显示配置；核心业务规则仍使用内部字段 ID。

### FS-MATCH-002 `[CONFIRMED]` 精确优先、受控包含匹配

读取源表时按以下顺序解析字段：

1. 对表头做有限规范化：Unicode NFKC、去首尾空白、折叠连续空白/换行、英文大小写不敏感；
2. 先与配置中的准确字段名和明确 aliases 做规范化后的精确匹配；
3. 只有某字段在配置中显式允许 `contains` 时，才执行包含匹配；
4. 包含匹配必须唯一命中，否则报 `AMBIGUOUS_FIELD`；
5. 未命中报 `MISSING_FIELD`。

不得使用编辑距离、相似度或“最像字段名”自动选择业务字段。

### FS-MATCH-003 `[CONFIRMED]` 同一内部字段可映射不同源字段名

例如内部字段 `bg`：

```text
遗留量表      -> 行销产品维BG中文名称
当月订货表    -> 行销产品维BG中文名称
要货明细表    -> BG_CN
输出显示      -> BG
```

业务规则只读取内部字段 `bg`，不得假设三个来源的表头名称相同。

## 8. 当前已确认的关键映射

- 遗留量 → 遗留量表 `设备订未收-新`；
- 当月新订货 → 当月订货表 `设备订货（不含VAT）`，但该源表本身允许缺失；
- 履行供应中心 → 要货明细 `供应中心简称`；
- 贸易术语 → 要货明细 `贸易术语`；
- ATA → 要货明细 `天_ATA`；
- ASD → 要货明细 `ASD日期`；
- RPD → 要货明细 `RPD日期`；
- CPD → 要货明细 `CPD日期`；
- 要货明细 BG → `BG_CN`；
- 基础海运周期 → 国家运输周期表按 `国家 + 供应中心` 匹配 `运输周期`。

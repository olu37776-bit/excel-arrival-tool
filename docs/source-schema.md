## 1. 输入源文件

当前真实结构为四个相互独立的 Excel 文件，每个文件承载一个固定业务角色：

1. 遗留量
2. 当月订货
3. 要货明细
4. 国家运输周期

不得要求用户先合并为一个工作簿。四个文件都需要提供；允许的是某个合同在当月订货表中没有匹配记录，此时该合同的当月新订货输出0。必需源文件无法读取属于技术故障。

## 6. 字段优先级

- BG：遗留量 `行销产品维BG中文名称` → 当月订货同名字段 → 要货明细 `BG_CN`；
- 地区部：遗留量 `地区部中文名称` → 要货明细 `地区部`；
- 国家：遗留量 `国家中文名称` → 要货明细同名字段；
- 客户群：遗留量 `客户群中文名称` → 要货明细 `签约客户群`；
- 项目名称：遗留量 `交付项目中文名称` → 要货明细同名字段。

优先来源值为空时继续下一来源。

## 7. 三层解耦

核心实现必须区分：

1. 稳定内部字段 ID；
2. 每个独立源表的真实字段名；
3. 输出表显示名称。

例如：

```text
内部：supply_center
要货明细：供应中心简称
国家运输周期：供应中心
输出：履行供应中心
```

源字段名改变只改映射；输出名称改变只改输出配置；业务规则继续使用内部字段 ID。

## 8. 统一字段匹配机制

所有字段使用同一套解析机制：

1. Unicode NFKC；
2. 去首尾空白；
3. 折叠连续空格、制表符和换行；
4. 英文字母大小写不敏感；
5. canonical/alias精确匹配优先；
6. 精确未命中时执行包含匹配；
7. 包含匹配只有唯一候选时成功；
8. 多个候选记录 `AMBIGUOUS_FIELD`，该字段本次不可用但整批继续；
9. 未命中记录 `MISSING_FIELD`；
10. 禁止相似度、编辑距离或“最像字段”自动选择。

## 9. 安静空值规范化

### FS-EMPTY-001 `[CONFIRMED]`

以下输入统一视为空值，不写异常：

- `None`或真正空单元格；
- 空字符串；
- 只含半角/全角空格、制表符、换行的文本；
- NFKC和空白规范化后等于`(空白)`的占位文本；
- Excel错误值或文本值`#VALUE!`。

字段类型处理：

| 类型 | 规范化结果 |
|---|---|
| 金额 | `Decimal(0)` |
| 日期 | `None` |
| 文本 | `None` |
| Y/N标识 | `None` |
| 运输周期 | `None` |

除`#VALUE!`外的其他非空Excel错误类型，仍按对应字段的非法值规则处理。

## 10. 数据类型

### 10.1 合同号

合同号按文本处理，保留前导零并去首尾空白。空合同号、空白字符、`(空白)`或`#VALUE!`所在行不进入合同全集或业务索引，直接忽略，不写异常。

### 10.2 金额

`legacy_amount`和`monthly_new_order`必须输出数值：

- 空单元格、空白字符、`(空白)`、`#VALUE!`、合同无匹配记录 → `0`，不报错；
- 合法数值 → 使用实际数值；
- 其他非空且无法解析的值 → 记录`INVALID_AMOUNT`，本次输出按`0`处理。

不得把金额列写成空字符串，否则会影响后续透视和汇总。

### 10.3 日期

ATA、ASD、RPD、CPD接受Excel日期或明确可解析的日期文本：

- 空单元格、空白字符、`(空白)`、`#VALUE!` → `None`，不报错；
- 合法日期 → `date`；
- 其他非空且无法解析的值 → 记录`INVALID_DATE`并排除聚合。

### 10.4 文本

普通文本先执行NFKC、首尾空白清理和空白折叠。空白字符、`(空白)`、`#VALUE!`归一为`None`，不报错。

### 10.5 Y/N标识

备货总控标识、发货总控标识：

- 去空白并转大写；
- `Y`、`N`为有效值；
- 空白字符、`(空白)`、`#VALUE!`归一为空，不报错；
- 其他非空值记录`INVALID_ENUM_VALUE`。

### 10.6 运输周期

运输周期应为非负整数自然日：

- 空白字符、`(空白)`、`#VALUE!`归一为空，不单独报错；
- 显示格式为`#,##0`、底层为非整数浮点时，按零位小数显示结果四舍五入取整，不得直接截断；
- 其他无法可靠转换的非空值记录`INVALID_TRANSIT_DAYS`。

## 11. 重复与基数

### 11.1 完全重复行

四个源表读取后均识别完全重复行：

- 只保留第一条参与计算；
- 记录`DUPLICATE_ROW_IGNORED`；
- 不得增加分批发货、多次要货、分批供应或履行供应中心数量。

### 11.2 遗留量/当月订货同合同多行

完全重复去除后，同一合同仍有多行时：

- 按原表顺序取第一条；
- 后续合同级记录出现不同非空值时，按现行合同级冲突规则记录异常；
- 不阻塞运行；
- 不求和、不取最大、不分摊。

### 11.3 要货明细多行

同一`合同号 + 履行供应中心`允许多条真实业务记录，用于日期聚合和派生标记。完全重复行必须先去除。

同组内普通文本字段出现多个不同非空值时：

- 不记录文本冲突异常；
- 需要单值时按原顺序取第一条有效值；
- 不影响日期聚合和分批判断。

### 11.4 国家运输周期重复键

同一`国家 + 供应中心`多行时：

- 完全重复先去重；
- 仍有多个不同运输周期时取第一条并记录冲突；
- 不阻塞整批。

## 12. 合同全集与要货明细匹配

### FS-CONTRACT-001 `[CONFIRMED]`

合同全集由遗留量、当月订货、要货明细三表合同号并集去重。

合同存在于全集，但要货明细中完全没有相同`原合同号`记录时：

- 记录`CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`；
- 不生成正常业务行；
- 不把它描述为“找到了合同但没有供应中心”。

要货明细中履行供应中心为空的记录不参与履行供应中心集合；空值本身不写异常。只有实际存在非空履行供应中心时才生成正常业务行。

## 13. 备货/发货总控标识一致性

### FS-CONTROL-001 `[CONFIRMED]`

一致性按要货明细的同一条去重后真实记录判断，而不是只比较组内汇总结果：

```text
同一行的备货总控标识、发货总控标识均为有效非空Y/N
且两者不同
→ CONTROL_FLAG_MISMATCH
```

任一值为空、空白占位或`#VALUE!`时，不记录该异常。

## 14. 海运周期数据使用

贸易术语为`FCA`、`FOB`、`EXW`任一值时，不查国家运输周期表，海运周期直接为5天。

其他贸易术语按：

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

查不到组合时记录异常并返回空海运周期。

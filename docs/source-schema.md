# 源表字段契约基线

- 文档 ID：`SOURCE-SCHEMA`
- 当前版本：`0.5`
- 状态：`ACTIVE-DRAFT`
- 建立日期：`2026-08-25`
- 最近自审：`2026-08-25`
- 关联：`docs/requirements-baseline.md`、`docs/output-schema.md`

> 本文件记录源 Excel 的存在性、稳定业务字段、内部字段 ID、字段匹配、数据类型和基数契约。输出显示名称允许变化；核心代码不得通过输出标题或固定列字母反向推断源字段。

## 1. 输入资料存在性

### FS-INPUT-001 `[CONFIRMED]` 当月订货表可选

月初可能尚未完成当月订货取数，因此当月订货表允许整表不提供：

- 缺表不得阻塞整次运行；
- `当月新订货` 进入数据不可用分支；
- BG 回退链跳过当月订货来源；
- 不得把“未提供”静默等价为金额 0。

### FS-INPUT-002 `[PROVISIONAL]` 其他主要输入

当前理解为遗留量表、要货明细表和国家运输周期表属于主要输入。以下需要本地资料审计确认：

- 是否每次都必须提供；
- 是独立工作簿还是工作簿内 Sheet；
- 文件名、Sheet 名和表头行；
- 是否存在标题行、合并单元格、隐藏列或多层表头；
- 目标输出模板是外部输入还是程序内置模板。

## 6. 多来源字段优先级

### FS-PRIORITY-001 `[CONFIRMED]`

- BG：遗留量 `行销产品维BG中文名称` → 当月订货同名字段（若表存在）→ 要货明细 `BG_CN`；
- 国家：遗留量 `国家中文名称` → 要货明细同名字段；
- 地区部：遗留量 `地区部中文名称` → 要货明细 `地区部`；
- 客户群：遗留量 `客户群中文名称` → 要货明细 `签约客户群`；
- 项目名称：遗留量 `交付项目中文名称` → 要货明细同名字段。

当月订货不参与地区部、国家、客户群和项目名称的回退链。

## 7. 三层解耦

### FS-DECOUPLING-001 `[CONFIRMED]`

必须区分：

1. 稳定内部字段 ID；
2. 每张源表自己的准确字段名；
3. 最终输出显示名称。

例如：

```text
内部字段 ID：supply_center
要货明细：供应中心简称
运输规格：供应中心
输出显示：履行供应中心
```

又例如：

```text
内部字段 ID：bg
遗留量：行销产品维BG中文名称
当月订货：行销产品维BG中文名称
要货明细：BG_CN
输出显示：BG
```

源字段变化只调整映射配置；输出标题变化只调整输出模板；业务规则继续使用内部字段 ID。

## 8. 字段匹配策略

### FS-MATCH-001 `[CONFIRMED]` 规范化

匹配前仅执行有限规范化：

- Unicode NFKC；
- 去除首尾空白；
- 折叠连续空格、制表符和换行；
- 英文字母大小写不敏感。

不得删除具有业务意义的中文、数字、下划线、连字符或括号内容。

### FS-MATCH-002 `[CONFIRMED]` 匹配顺序

1. canonical/alias 规范化后精确匹配；
2. 只有配置显式允许的字段才执行 `contains`；
3. `contains` 必须唯一命中；
4. 多个候选报 `AMBIGUOUS_FIELD`；
5. 未命中报 `MISSING_FIELD`；
6. 禁止编辑距离、相似度或“最像字段”自动选择。

### FS-MATCH-003 `[TBD]` contains 白名单

哪些字段确实需要包含匹配尚未通过本地资料审计冻结。当前不得对全部字段全局启用 contains。

候选示例：`天_ATA` 可能允许配置 alias 或受控 contains，但必须先确认实际表头变体不会误命中其他 ATA 相关列。

## 9. 数据类型与标准化

### FS-TYPE-001 `[CONFIRMED]` 合同号

合同号按文本处理：

- 保留前导零；
- 去除首尾空白；
- 不把科学计数法或浮点数静默转换为合同号；
- 空值或明显损坏值进入异常清单。

### FS-TYPE-002 `[CONFIRMED]` 金额

`legacy_amount` 与 `monthly_new_order` 应解析为数值或空值。非空但无法解析的文本、公式错误或异常币种字符应产生数据异常。

金额的同合同多行聚合方式仍为 `TBD`。

### FS-TYPE-003 `[CONFIRMED]` 日期

ATA、ASD、RPD、CPD 接受 Excel 日期值或明确可解析的日期文本。非空但无法解析时不得当作空值，应产生数据异常。

### FS-TYPE-004 `[CONFIRMED]` Y/N 标识

备货总控标识和发货总控标识的预期值域为 Y/N。可在去空白和大小写统一后转为大写；其他非空值应记录 `INVALID_ENUM_VALUE`。

### FS-TYPE-005 `[CONFIRMED]` 运输周期

运输周期应为非负整数自然日。小数、负数、无法解析的文本或冲突值均属于异常。

## 10. 基数与重复键契约

### FS-CARDINALITY-001 `[TBD]` 遗留量合同重复

需要本地审计同一 `华为合同号` 是否可能出现多行。若存在，需确认：

- 金额求和、最大、第一条或报错；
- BG/地区部/国家/客户群/项目名称冲突时如何处理；
- 完全重复行是否只做去重告警。

### FS-CARDINALITY-002 `[TBD]` 当月订货合同重复

需要审计同一 `华为合同号` 的记录数与金额分布，并冻结 `设备订货（不含VAT）` 的聚合规则。

### FS-CARDINALITY-003 `[CONFIRMED]` 要货明细多行

同一 `合同号 + 履行供应中心` 允许多条要货明细，是日期聚合、多次要货、分批供应和分批发货的基础。

但完全重复行、文本属性冲突和总控标识不同步仍需识别，不能把所有重复都视为正常业务多行。

### FS-CARDINALITY-004 `[PROVISIONAL]` 运输规格唯一性

`国家 + 供应中心` 应唯一对应一个运输周期：

- 完全重复且周期相同，可视为重复数据并记录告警；
- 同键对应不同周期，必须报冲突错误，不得取第一条。

是否把完全重复也设为阻塞错误仍为 `TBD`。

## 11. 本地资料审计应提供的证据

每个源表至少记录：

- 实际文件名和路径；
- Sheet 名；
- 表头行和数据起始行；
- 实际列字母、列序号和完整原始表头；
- 是否与本契约精确匹配、alias 匹配或 contains 匹配；
- 数据行数、空值数、重复键数；
- 字段主要数据类型与异常值样例；
- 同一业务键下不同值数量；
- 隐藏列、合并单元格、公式列和多层表头。

审计只能报告 `MATCH`、`MISMATCH`、`AMBIGUOUS`、`MISSING`、`DATA_RISK`，不得根据当前代码或旧列号说明修改业务规则。

## 12. 当前关键映射摘要

- 遗留量 → `设备订未收-新`；
- 当月新订货 → `设备订货（不含VAT）`，源表可缺失；
- 履行供应中心 → `供应中心简称`；
- 贸易术语 → `贸易术语`；
- ATA → `天_ATA`；
- ASD → `ASD日期`；
- RPD → `RPD日期`；
- CPD → `CPD日期`；
- 要货明细 BG → `BG_CN`；
- 基础海运周期 → 国家+供应中心匹配 `运输周期`。

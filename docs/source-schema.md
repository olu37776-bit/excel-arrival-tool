## 5. 字段匹配策略

### FS-MATCH-001 `[CONFIRMED]` 内部字段 ID 稳定

业务规则和代码使用稳定内部字段 ID，例如 `contract_no`、`supply_center`、`rpd`。输出表头名称可以变化，不影响源字段绑定。

### FS-MATCH-002 `[CONFIRMED]` 精确匹配优先

读取源表时按以下顺序解析字段：

1. 对表头进行有限规范化：Unicode NFKC、去首尾空白、折叠连续空白/换行、英文大小写不敏感；
2. 先与配置中的准确字段名和明确 aliases 做规范化后的精确匹配；
3. 只有某个字段在配置中显式允许 `contains` 时，才执行包含匹配；
4. 包含匹配必须唯一命中，否则报 `AMBIGUOUS_FIELD`，不得自动选择第一列；
5. 未命中报 `MISSING_FIELD`。

### FS-MATCH-003 `[CONFIRMED]` 禁止无限制模糊匹配

不得使用编辑距离、相似度或“最像字段名”自动选择业务字段。包含匹配仅用于已知、受控的表头变化。

示例：

```json
{
  "rpd": {
    "canonical": "RPD日期",
    "aliases": ["RPD 日期"],
    "match_mode": "exact"
  },
  "ata": {
    "canonical": "天_ATA",
    "aliases": ["ATA"],
    "match_mode": "contains"
  }
}
```

## 6. 当前已确认的关键映射

- 输出“遗留量” → 遗留量表 `设备订未收-新`；
- 输出“当月新订货” → 当月订货表 `设备订货（不含VAT）`；
- 输出“供应中心” → 要货明细表 `供应中心简称`；
- 输出“贸易术语” → 要货明细表 `贸易术语`；
- 输出 ATA → 要货明细表 `天_ATA`；
- 输出 ASD → 要货明细表 `ASD日期`；
- 输出 RPD → 要货明细表 `RPD日期`；
- 输出 CPD → 要货明细表 `CPD日期`；
- 基础海运周期 → 国家运输周期表按 `国家 + 供应中心` 匹配 `运输周期`；
- BG 来源优先级：遗留量表 `行销产品维BG中文名称` → 当月订货表同名字段 → 要货明细表同名字段；
- 国家来源优先级：遗留量表 `国家中文名称` → 要货明细表 `国家中文名称`。

## 7. 尚待业务规则确认的字段来源优先级

以下输出字段已经能找到源字段候选，但来源优先级或派生规则尚未冻结：

- 地区部：遗留量 `地区部中文` / 当月订货 `地区部中文名称` / 要货明细 `地区部`；
- 客户群：遗留量 `客户群中文名称` / 要货明细 `签约客户群`；
- 项目名称：三张业务表均有 `交付项目中文名称`；
- 是否解锁备货：候选输入 `备货总控标识`；
- 分批发货：候选输入 `发货总控标识`，是否还需结合明细数量/状态待确认；
- 多次要货：候选为同一 `合同号 + 供应中心` 下的要货明细结构，准确判定待确认；
- 分批供应：尚需确认由 `需求状态`、明细结构或其他规则判定；
- 结转类型：四张源表中无同名/明显直接来源，视为派生字段，规则待确认。

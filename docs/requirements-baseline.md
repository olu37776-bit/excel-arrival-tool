## 1. 文档治理与修改方式

### 1.1 事实来源优先级

发生冲突时，按以下顺序判断：

1. 业务方最新明确确认、并已经记录在本文件中的规则；
2. 实际源 Excel、目标输出模板及其字段证据；
3. 经业务方确认的字段映射配置；
4. 原始《运算逻辑解释》；
5. 当前代码、README、测试和示例配置。

原始《运算逻辑解释》中写死的列字母、VLOOKUP 公式或旧表结构不能自动成为正式规则。

### 1.2 规则状态

- `CONFIRMED`：业务含义已经明确，可以据此实现和验收；
- `PROVISIONAL`：当前理解可用于设计，但仍需要进一步明确边界；
- `TBD`：尚未确认，不得在代码中静默假设；
- `REJECTED`：旧说明或旧实现已确认不适用；
- `IMPLEMENTATION_NOTE`：工程约束，不替代业务规则。

### 1.3 后续增量更新原则

用户后续可以逐条补充需求，不要求一次性讲完。每次更新本文件时应：

1. 修改或新增具有稳定 ID 的规则；
2. 标记规则状态；
3. 对改变既有含义的修改记录影响范围；
4. 在文末变更记录中新增一条，不静默覆盖历史决策；
5. 规则被确认后，再同步修改领域模型、处理逻辑、测试和 README。

## 2. 项目目标与范围

### 2.1 业务目标

工具读取多张业务 Excel，按正式字段语义完成数据关联、校验和计算，输出目标基表，并支持多次运行之间的按月延迟识别。

当前已经明确的核心结果包括：

- 以“合同号 + 供应中心简称”为最终记录粒度；
- 计算“到货日期（按 PRD）”；
- 计算“到货日期（按 CPD）”；
- 生成对应的“收入年月（按 PRD）”和“收入年月（按 CPD）”；
- 比较相邻运行中 `MIN(PRD)` 的月份，识别计划出货跨月延迟；
- 校验供应中心、国家、运输周期和日期等关键数据异常。

### 2.2 当前非目标

- 不做装运排程或资源优化；
- 不要求在输出中保留 VLOOKUP 等 Excel 公式；
- 不把真实业务 Excel、真实字段映射、运行快照或输出结果上传到公开仓库；
- 当前阶段不以现有 POC 的数量汇总、金额汇总或 Shipment 模型作为既定业务需求。

## 3. 输入资料与术语

### 3.1 输入资料

“底表”是以下源表的统称，不是一张独立输入表：

1. `遗留量表`；
2. `当月订货表`；
3. `要货明细表`；
4. `国家运输周期表`。

此外还有：

5. `目标输出基表格式`；
6. `运算逻辑解释`。

这些资料可能是独立工作簿，也可能位于工作簿的不同 Sheet。准确文件名、Sheet 名、表头行和字段别名需要根据实际文件审计后冻结。

### 3.2 关键术语

- `合同号`：跨表关联的主要合同标识；
- `供应中心简称`：来自要货明细表，决定最终输出行粒度，并参与运输周期匹配；
- `发货点`：当前对话中用于描述日期聚合范围。暂按供应中心对应的发货维度理解，但其与“供应中心简称”是否完全等价仍需确认；
- `国家`：合同级属性，参与运输周期匹配；
- `运输周期/海运周期`：自然日天数；
- `ATA`、`ASD`、`PRD`、`CPD`：保持源表原始字段标识。除已确认计算规则外，不依赖对英文全称的猜测。

## 4. 字段定位与配置边界

### BR-FIELD-001 `[CONFIRMED]` 业务字段优先

核心逻辑必须按业务字段名定位，不得把 `F 列`、`G 列`、`O 列`作为稳定业务接口。

列字母只用于：

- 审计当前文件结构；
- 发现字段移动或错误引用；
- 在异常报告中提供单元格位置。

### BR-FIELD-002 `[CONFIRMED]` 字段映射外置

源文件名、Sheet 名、表头行、规范字段名及字段别名应由映射配置承载。核心业务代码只使用规范字段名。

公开仓库只保留示例映射，例如：

- `config/field_mappings.example.json`

真实映射应保存在本地文件中，并通过 `.gitignore` 排除。

### BR-FIELD-003 `[REJECTED]` 原列号直接实现

以下旧说明不能直接用于实现：

- “遗留量取遗留量表 G 列”；
- 其他仅以列字母描述、但未核对实际表头的规则。

已发现遗留量表 G 列实际字段与预期金额语义不一致，因此必须先确认准确业务字段。

## 5. 最终数据粒度与行生成

### BR-ROW-001 `[CONFIRMED]` 最终唯一粒度

最终输出一行的业务粒度是：

```text
合同号 + 供应中心简称
```

同一合同号存在多个供应中心时，每个供应中心分别输出一行。

### BR-ROW-002 `[CONFIRMED]` 供应中心来源

供应中心来自要货明细表中的完整业务字段：

```text
供应中心简称
```

遗留量表和当月订货表不包含供应中心。

### BR-ROW-003 `[CONFIRMED]` 缺失供应中心

如果需要进入最终结果的合同无法从要货明细表获得供应中心，则记录数据异常，不得生成一个“供应中心为空”的正常结果行。

### BR-ROW-004 `[TBD]` 最终合同全集

尚需确认最终需要处理的合同全集来自哪种并集：

- 遗留量表 + 要货明细表；
- 遗留量表 + 当月订货表 + 要货明细表；
- 只以要货明细中的“合同号 + 供应中心”为基准；
- 其他业务口径。

在该规则确认前，不得沿用旧说明中“仅合并遗留量和要货明细合同号”的做法。

## 6. 国家规则

### BR-COUNTRY-001 `[CONFIRMED]` 国家来源优先级

国家按以下顺序解析：

1. 遗留量表中的国家；
2. 遗留量表无有效国家时，使用要货明细表中的国家。

### BR-COUNTRY-002 `[CONFIRMED]` 合同国家唯一性

同一合同号必须对应唯一国家。若同一合同号在任一来源或跨来源出现多个不同国家，则记录数据异常，不得静默选择其中一个。

合同国家确定后，可复用于该合同的多个供应中心输出行。

### BR-COUNTRY-003 `[TBD]` 国家值标准化

国家名称是否存在中文、英文、简称、地区名称或空格差异，以及哪些值可视为同一国家，需根据实际数据建立明确映射；不得仅用模糊字符串匹配。

## 7. 运输周期规则

### BR-TRANSIT-001 `[CONFIRMED]` 基础运输周期匹配键

国家运输周期表是规格表，至少包含：

```text
国家 + 供应中心 + 运输周期
```

基础运输周期使用下列复合键匹配：

```text
国家 + 供应中心简称
```

### BR-TRANSIT-002 `[CONFIRMED]` 时间单位

运输周期单位为自然日。

### BR-TRANSIT-003 `[CONFIRMED]` 找不到规格

当需要的“国家 + 供应中心”在国家运输周期表中找不到有效运输周期时，记录数据异常，不允许使用静默默认值。

### BR-TRANSIT-004 `[TBD]` ATA/ASD 已命中时的阻塞范围

ATA 或 ASD 命中时，日期计算本身不使用运输周期。仍需确认：

- 运输周期规格缺失是否一律阻塞该行；
- 或只在进入 PRD/CPD 回退计算时才阻塞，其他情况仅产生结构告警。

### BR-TRANSIT-005 `[CONFIRMED]` 特殊贸易类型扩展

部分特殊贸易类型会改变基础运输周期。具体业务规则可以写入代码，但必须与基础规格查询和日期优先级解耦：

```text
国家 + 供应中心 → 基础运输周期
基础运输周期 + 特殊贸易类型规则 → 最终运输周期
```

特殊贸易类型的准确字段来源、类型集合和调整方式尚未补充。

## 8. 日期分组与聚合

### BR-DATE-001 `[CONFIRMED]` 日期聚合范围

ATA、ASD、PRD、CPD 的取值都必须限定在同一业务组：

```text
合同号 + 供应中心简称
```

该规则对应业务前提“同一合同、同一发货点”。禁止只按合同号跨供应中心聚合。

### BR-DATE-002 `[CONFIRMED]` 日期聚合方式

在同一组内：

| 字段 | 聚合规则 |
|---|---|
| ATA | 取最大有效日期 `MAX(ATA)` |
| ASD | 取最大有效日期 `MAX(ASD)` |
| PRD | 取最小有效日期 `MIN(PRD)` |
| CPD | 取最大有效日期 `MAX(CPD)` |

空单元格不参与最大/最小计算。非空但无法解析为日期的值应记录数据异常。

## 9. 到货日期与收入年月

### BR-ARRIVAL-PRD-001 `[CONFIRMED]` 到货日期（按 PRD）

对每个“合同号 + 供应中心简称”组，按以下优先级计算：

```text
如果存在 ATA：
    到货日期（按 PRD） = MAX(ATA)
    不加运输周期
否则如果存在 ASD：
    到货日期（按 PRD） = MAX(ASD)
    不加运输周期
否则：
    到货日期（按 PRD） = MIN(PRD) + 最终运输周期（自然日）
```

如果 ATA、ASD、PRD 均无有效日期，则该组无法计算“到货日期（按 PRD）”，应记录数据异常。

### BR-ARRIVAL-CPD-001 `[CONFIRMED]` 到货日期（按 CPD）

对每个“合同号 + 供应中心简称”组，按以下优先级计算：

```text
如果存在 ATA：
    到货日期（按 CPD） = MAX(ATA)
    不加运输周期
否则如果存在 ASD：
    到货日期（按 CPD） = MAX(ASD)
    不加运输周期
否则：
    到货日期（按 CPD） = MAX(CPD) + 最终运输周期（自然日）
```

如果 ATA、ASD、CPD 均无有效日期，则该组无法计算“到货日期（按 CPD）”，应记录数据异常。

### BR-MONTH-001 `[CONFIRMED]` 收入年月

```text
收入年月（按 PRD） = 到货日期（按 PRD）的年份和月份
收入年月（按 CPD） = 到货日期（按 CPD）的年份和月份
```

建议输出：

- 到货日期：Excel 日期值，显示格式 `yyyy-mm-dd`；
- 收入年月：文本或年月值，显示格式 `yyyy-mm`。

## 10. 其他输出字段的当前状态

### BR-AMOUNT-001 `[TBD]` 遗留量

原说明引用遗留量表 G 列，但已确认该列不是预期金额字段。需确认：

- 准确业务字段名；
- 同一合同多行时的聚合方式；
- 金额口径、币种、含税/不含税；
- 合同存在多个供应中心时是否在每行重复展示、拆分或单独汇总。

### BR-AMOUNT-002 `[PROVISIONAL]` 当月新订货

候选业务字段为：

```text
设备订货（不含VAT）
```

但仍需通过实际表头确认其准确位置、合同匹配字段、重复记录聚合方式，以及在多个供应中心行上的展示/统计方式。

### BR-BG-001 `[PROVISIONAL]` BG 来源优先级

当前理解为：

1. 遗留量表中的 BG 业务字段；
2. 为空时，取当月订货表中的 `行销产品维BG中文名称`；
3. 仍为空时，取要货明细表中的 `BG`。

遗留量表中的准确 BG 字段名仍需确认。“合同号不存在”和“合同存在但 BG 为空”需要分别记录。

### BR-AMOUNT-003 `[TBD]` 合同级金额在多供应中心行上的重复风险

遗留量表和当月订货表没有供应中心，而最终结果可能为同一合同输出多行。若把合同级金额完整复制到每个供应中心行，后续汇总会重复计算。

必须在实现金额字段前明确以下方案之一：

- 每行重复展示，但明确禁止直接汇总；
- 只在一行展示；
- 按业务规则分摊；
- 另建合同级汇总输出；
- 其他规则。

## 11. 多次运行与延迟识别

### BR-HISTORY-001 `[CONFIRMED]` 保存运行快照

每次成功运行应在本地保存结构化快照，至少包含：

- 运行 ID、运行时间和规则版本；
- 合同号；
- 供应中心简称；
- 国家；
- `MIN(PRD)`；
- `MAX(CPD)`；
- `MAX(ATA)`；
- `MAX(ASD)`；
- 最终运输周期；
- 到货日期（按 PRD）；
- 到货日期（按 CPD）；
- 收入年月（按 PRD）；
- 收入年月（按 CPD）。

真实快照只保存在用户本地，不提交公开仓库。

### BR-HISTORY-002 `[CONFIRMED]` 对比稳定键

跨次对比按以下稳定业务键进行：

```text
合同号 + 供应中心简称
```

不得使用包含计划数量、收入金额或会随本次结果变化的字段作为身份键。

### BR-HISTORY-003 `[CONFIRMED]` 延迟比较字段

“出货延迟”比较的是两次运行中的：

```text
MIN(PRD) 所在年月
```

不是到货日期或收入年月。

### BR-HISTORY-004 `[CONFIRMED]` 同月变化不标记

如果本次和上次的 `MIN(PRD)` 仍在同一个自然月，即使具体日期变晚，也不标记出货延迟。

示例：

```text
上次：2026-09-01
本次：2026-09-28
结果：不标记
```

### BR-HISTORY-005 `[PROVISIONAL]` 跨月延迟

当前按月统计的理解是：本次 `MIN(PRD)` 的月份晚于上次月份时标记延迟，并计算相差月数。

示例：

```text
上次：2026-09-28
本次：2026-10-02
结果：延迟 1 个月
```

仍需明确：如果从 9 月变为 11 月，是否同样标记并显示“延迟 2 个月”，还是只关注恰好延迟 1 个月的记录。

### BR-HISTORY-006 `[PROVISIONAL]` 默认对比基线

当前建议默认与“上一次成功运行”比较；第一次运行只建立基线，不产生延迟记录。是否需要支持任意选择两个历史批次，后续确认。

### BR-HISTORY-007 `[TBD]` 已有 ATA/ASD 的记录

若记录已存在 ATA 或 ASD，但 `MIN(PRD)` 相比上次跨月变晚，是否仍显示在出货延迟清单中尚未确认。

## 12. 数据异常与处理方式

### 12.1 已确认需要识别的异常

- 需要输出的合同找不到供应中心；
- 同一合同出现多个不同国家；
- 需要运输周期时找不到“国家 + 供应中心”规格；
- 运输周期不是有效非负整数；
- 日期字段非空但无法解析；
- 需要 PRD/CPD 回退时没有有效基准日期；
- 必填业务字段不存在或出现重复表头。

### 12.2 `[TBD]` 阻塞策略

仍需确认：

- 任一异常是否终止整批处理；
- 或允许输出可计算记录，同时生成异常明细；
- 哪些异常属于阻塞错误，哪些属于告警。

推荐实现必须至少生成结构化异常信息，包含来源文件、Sheet、行号、合同号、供应中心、字段、原始值和错误原因。

## 13. 输出契约

### 13.1 `[CONFIRMED]` 目标模板优先

最终字段顺序、列名和样式以“目标输出基表格式”为准。正式实现前必须审计目标模板，并将每个输出列映射到本文件中的规则 ID。

### 13.2 当前已知核心输出

至少包括：

- 合同号；
- 供应中心简称；
- 国家；
- 到货日期（按 PRD）；
- 到货日期（按 CPD）；
- 收入年月（按 PRD）；
- 收入年月（按 CPD）。

遗留量、当月新订货、BG及其他非计算字段待逐列补充。

### 13.3 `[PROVISIONAL]` 输出值而非 VLOOKUP

当前工具设计以程序计算并写入结果值为默认方式。VLOOKUP 是原人工 Excel 的实现手段，不是业务规则。若目标模板明确要求保留公式，再单独增加输出适配，不改变核心计算。

## 14. 工程实现约束

### ENG-001 `[IMPLEMENTATION_NOTE]` 规则与 Excel 解耦

建议继续保留分层：

- Excel 读取/写出适配层；
- 字段映射与结构校验；

- 真实 `.xlsx/.xls`；

### ENG-004 `[IMPLEMENTATION_NOTE]` 可追溯测试

| 主题 | 当前 `main` POC | 本需求基线 | 结论 |
|---|---|---|---|
| 输入模型 | 单工作簿中的 `PRD`、`Shipment`、`Transit Days` 三个 Sheet | 遗留量、当月订货、要货明细、国家运输周期等真实源表 | 需要重构输入契约 |
| 最终粒度 | 以 PO/Shipment 记录为中心 | 合同号 + 供应中心简称 | 核心领域模型不一致 |
| 运输周期键 | `Trade Type` | 国家 + 供应中心，特殊贸易类型再调整 | 当前解析键错误 |
| 到货日期 | `Plan Month + Transit Days` | ATA → ASD → PRD/CPD + 运输周期的两条链 | 当前计算逻辑错误 |
| 日期聚合 | PRD 按 PO 选择，合同/发货点只是可选缩小范围 | 严格按合同号 + 供应中心聚合 | 当前范围不可靠 |
| 输出日期 | 一套 `Arrival Date/Revenue Month` | PRD 和 CPD 两套到货日期及收入年月 | 输出模型缺失 |
| 历史比较字段 | 比较 `Revenue Month` | 比较 `MIN(PRD)` 的年月 | 当前比较对象错误 |
| 历史身份键 | 可能包含 PO、贸易类型、计划数量或 Shipment ID | 合同号 + 供应中心简称 | 当前键可能随数据变化 |
| 数量/金额汇总 | 已实现 Plan Quantity 和 Revenue Amount 汇总 | 尚未确认正式统计口径 | 不得视为正式功能 |
| 配置 | 业务聚合规则大量位于 JSON | 字段映射外置，核心业务规则由代码承载 | 需要重新划分边界 |

结论：现有分层结构可以参考，但当前领域模型、输入契约、日期计算和历史比较不能通过少量改字段完成，后续应根据本基线有计划地修正或替换。

## 16. 最小验收场景

### AC-001 多供应中心

同一合同在要货明细中存在两个供应中心，最终必须输出两行，日期不得跨供应中心聚合。

### AC-002 ATA 优先

同组存在多个 ATA 时取最大 ATA；PRD 和 CPD 两套到货日期均直接使用该 ATA，不加运输周期。

### AC-003 ASD 回退

ATA 全部为空、ASD 存在时取最大 ASD；两套到货日期均直接使用该 ASD，不加运输周期。

### AC-004 PRD/CPD 回退

ATA、ASD 均为空时：

- 按 PRD：`MIN(PRD) + 最终运输周期`；
- 按 CPD：`MAX(CPD) + 最终运输周期`。

### AC-005 国家冲突

同一合同出现两个不同国家时必须产生数据异常，不允许取第一条。

### AC-006 运输周期缺失

需要回退计算且找不到“国家 + 供应中心”的运输周期时必须产生数据异常，不允许默认 0 天。

### AC-007 按月延迟

上次 `MIN(PRD)=2026-09-01`、本次 `MIN(PRD)=2026-09-28` 时不标记；本次变为 `2026-10-01` 时标记跨月延迟。

## 17. 优先待确认问题

### P0：确认后才能完成正式结果模型

1. 最终合同全集从哪些源表生成；
2. 遗留量准确业务字段和聚合口径；
3. 当月新订货准确匹配、聚合和税口径；
4. 合同级金额在多个供应中心行上的展示/汇总方式；
5. 实际文件名、Sheet、表头行和字段别名；
6. 目标输出基表的完整列清单与顺序；
7. 异常是整批阻塞还是允许部分输出。

### P1：影响历史比较和边界行为

1. “延迟一个月”是至少跨 1 个月，还是只取恰好 1 个月；
2. 默认是否只与上一次成功运行比较；
3. 已有 ATA/ASD 时是否仍报告 PRD 延迟；
4. ATA/ASD 命中时运输周期缺失是否阻塞；
5. “发货点”与“供应中心简称”的准确关系；
6. 特殊贸易类型字段、类型集合和调整规则；
7. 新增、消失的合同+供应中心如何展示在比较结果中。

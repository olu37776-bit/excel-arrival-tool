## 2. 当前范围

### BR-SCOPE-001 `[CONFIRMED]` 当前目标

工具分别读取四个独立的业务 Excel 源文件，完成：

- 源表与字段识别；
- 合同集合生成；
- 履行供应中心展开；
- 合同级属性与合同+履行供应中心级属性填充；
- 完全重复数据识别与去重；
- 日期聚合；
- 海运周期计算；
- 两套到货日期与收入年月计算；
- 派生标记、最晚日期、货未发完及收入分段类别计算；
- 三个人工调整字段跨次继承；
- RPD/CPD 收入年月跨期变化识别；
- 同一期 RPD/CPD 两个收入年月差异识别；
- 异常清单输出。

结果工作簿至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`
4. `供应需要提拉诉求清单粗表`
5. `异常清单`

### BR-SCOPE-002 `[CONFIRMED]` 当前非目标

- 不做正式收入金额汇总报表；
- 不做装运排程或资源优化；
- 不要求输出 VLOOKUP 等 Excel 公式；
- 不把真实业务数据、历史快照或本地输出提交到公开仓库。

## 3. 输入源文件

### BR-INPUT-001 `[CONFIRMED]` 独立文件结构

真实输入由四个彼此独立的 Excel 源文件组成：

1. `遗留量`源文件
2. `当月订货`源文件
3. `要货明细`源文件
4. `国家运输周期`源文件

不得假设它们位于同一个工作簿。实际文件名、路径及业务 Sheet 名由输入适配和字段映射处理。

### BR-INPUT-002 `[CONFIRMED]` 当月订货按合同号允许无匹配

`当月订货`源文件需要提供，但某个合同可以在其中没有匹配记录。此时：

- 合同仍可由遗留量或要货明细进入合同全集；
- `当月新订货`规范化为数值 `0`；
- BG 回退链跳过该合同在当月订货来源中的空值或无匹配状态；
- 不阻塞其他计算。

## 4. 字段与实现解耦

### BR-FIELD-001 `[CONFIRMED]` 三层解耦

必须区分：

1. 源表实际字段名；
2. 稳定内部字段 ID；
3. 输出显示名称。

例如 `supply_center`：

- 要货明细源字段：`供应中心简称`
- 国家运输周期源字段：`供应中心`
- 输出显示：`履行供应中心`

例如 `bg`：

- 遗留量：`行销产品维BG中文名称`
- 当月订货：`行销产品维BG中文名称`
- 要货明细：`BG_CN`
- 输出：`BG`

### BR-FIELD-002 `[CONFIRMED]` 字段匹配统一机制

所有字段统一执行：

1. 表头有限规范化；
2. canonical/alias 精确匹配；
3. 精确未命中时执行包含匹配；
4. 包含匹配必须唯一命中；
5. 多个候选时记录字段歧义，该字段本次不可用，但整批继续；
6. 不使用相似度、编辑距离或“最像字段”自动选择。

## 5. 业务粒度与合同集合

### BR-GRAIN-001 `[CONFIRMED]` 最终行粒度

```text
合同号 + 履行供应中心
```

同一合同存在多个履行供应中心时，每个中心输出一行。

### BR-GRAIN-002 `[CONFIRMED]` 合同全集

合同集合由以下三个独立源表的实际合同号合并后去重：

- 遗留量表 `华为合同号`
- 当月订货表 `华为合同号`
- 要货明细表 `原合同号`

合同进入全集后，通过要货明细取得履行供应中心集合。

若合同在要货明细中完全找不到匹配的合同号：

- 记录 `CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`；
- 不生成正常业务行；
- 整批继续。

若合同能够匹配要货明细，但所有匹配行的履行供应中心均为空，则无法形成业务键，同样不生成正常业务行，并记录 `MISSING_SUPPLY_CENTER`。

### BR-GRAIN-003 `[CONFIRMED]` 合同级字段

遗留量、当月新订货以及主要合同属性按合同号取得，不按履行供应中心拆分。同一合同展开到多个履行供应中心行时复制展示。

## 6. 同合同多记录与文本差异

### BR-FIRST-001 `[CONFIRMED]` 合同级来源

遗留量表、当月订货表及合同级属性出现同一合同多条记录时：

1. 完全重复记录先去重；
2. 默认按源表原始顺序取第一条；
3. 字段允许为空；
4. 后续合同级记录出现不同非空值时，仍使用第一条，并按当前合同级冲突规则写入异常清单；
5. 不求和、不取最大、不分摊，不阻塞整批。

### BR-GROUP-TEXT-001 `[CONFIRMED]` 要货明细组内文本差异不报错

同一 `合同号 + 履行供应中心` 下，地区部、国家、客户群、项目名称、贸易术语、BG 等文本字段出现多个不同非空值时：

- 不视为数据异常；
- 不写“文本冲突”异常；
- 需要单值输出时按去重后原始顺序取第一条有效值；
- 日期聚合、分批判断等继续按各自规则执行。

## 7. 空值、空白字符与 Excel `#VALUE!`

### BR-NORMALIZE-001 `[CONFIRMED]` 安静规范化

以下值统一按空值处理，不写异常：

- 真正空单元格；
- 空字符串；
- 仅包含半角/全角空格、制表符或换行的文本；
- NFKC 和空白规范化后等于 `(空白)` 的占位文本；
- Excel 错误值或文本值 `#VALUE!`。

处理结果按字段类型区分：

- 金额字段：空值归一为数值 `0`；
- 日期字段：空值归一为 `None`，不参与日期聚合；
- 文本/标识字段：空值归一为 `None`；
- 运输周期：空值归一为 `None`。

除 `#VALUE!` 外，其他非空 Excel 错误类型或无法识别的非法值仍按对应字段规则处理。

### BR-AMOUNT-001 `[CONFIRMED]` 金额输出必须为数值

`遗留量`和`当月新订货`在以下情况下均输出 `0`：

- 源单元格为空或只有空白字符；
- 源值为 `(空白)`；
- 源值为 `#VALUE!`；
- 合同在对应源表中没有匹配记录。

这样保证后续透视和汇总运算始终得到数值列。其他无法解析的非空金额值记录异常，并以 `0` 进入本次输出。

## 8. 属性来源

### BR-SOURCE-001 `[CONFIRMED]`

- BG：遗留量 → 当月订货 → 要货明细；
- 地区部：遗留量 → 要货明细；
- 国家：遗留量 → 要货明细；
- 客户群：遗留量 → 要货明细；
- 项目名称：遗留量 → 要货明细；
- 贸易术语：要货明细；
- 履行供应中心：要货明细。

优先来源为空时继续下一来源。普通属性为空可以是正常状态。

## 9. 派生字段

### BR-CARRYOVER-001 `[CONFIRMED]` 结转类型

只根据遗留量表自身 `国家中文名称`。属于以下任一国家时输出 `交付类`，否则留空：

- 阿拉伯联合酋长国
- 巴基斯坦
- 巴西
- 菲律宾
- 马来西亚
- 沙特阿拉伯
- 印度尼西亚

### BR-MULTI-SC-001 `[CONFIRMED]`

同合同不同有效履行供应中心数 > 1：`Y`；否则 `N`。

### BR-SPLIT-SHIPMENT-001 `[CONFIRMED]`

要货明细先去除完全重复行，再在同一 `合同号 + 履行供应中心` 下统计真实记录数：

- 记录数 > 1：`分批发货 = Y`
- 否则：`N`

完全重复行不得制造分批发货。

### BR-STOCK-001 `[PROVISIONAL]`

`是否解锁备货`读取 `备货总控标识`。同组多条真实记录暂按原出现顺序用 `|` 拼接，例如 `Y|Y|N`。展示格式后续可调整。

### BR-CONTROL-FLAG-001 `[CONFIRMED]` 同行总控标识一致性

对要货明细的每一条去重后真实记录，分别规范化 `备货总控标识`和`发货总控标识`：

```text
两者均为有效非空 Y/N，且值不同
→ 记录 CONTROL_FLAG_MISMATCH
```

任一值为空、空白占位或 `#VALUE!` 时，不产生该异常。该异常不阻塞整批。

### BR-MULTI-DEMAND-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 RPD 日期数 > 1：`多次要货 = Y`；否则 `N`。

### BR-SPLIT-SUPPLY-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 CPD 日期数 > 1：`分批供应 = Y`；否则 `N`。

## 10. 海运周期

### BR-TRANSIT-001 `[CONFIRMED]`

先读取要货明细 `贸易术语`，去首尾空白并忽略英文大小写：

```text
贸易术语 ∈ {FCA, FOB, EXW}
→ 海运周期 = 5 天
```

否则：

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

运输周期单位为自然日。若单元格显示格式为 `#,##0`、底层为非整数浮点，按零位小数显示结果四舍五入取整，不得直接截断。

查不到组合或周期值非法时：

- 记录异常；
- 海运周期留空；
- 整批继续；
- 仅当到货日期所选分支依赖海运周期时，影响该到货日期。

## 11. 日期聚合与货未发完

### BR-DATE-001 `[CONFIRMED]`

同一合同+履行供应中心内：

- ATA = MAX(`天_ATA`)
- ASD = MAX(`ASD日期`)
- RPD = MIN(`RPD日期`)
- 最晚ASD = MAX(`ASD日期`)
- 最晚RPD = MAX(`RPD日期`)
- CPD = MAX(`CPD日期`)

空值、空白字符、`(空白)`和`#VALUE!`均安静排除，不写日期异常。其他非空但无法解析的日期才记录异常并排除。

### BR-SHIPMENT-INCOMPLETE-001 `[CONFIRMED]` 货未发完

```text
最晚ASD、最晚RPD均有效，且最晚RPD > 最晚ASD → 货未发完 = Y
最晚ASD、最晚RPD均有效，且最晚RPD <= 最晚ASD → 货未发完 = N
任一日期无有效值 → 货未发完留空
```

因正常空值、空白字符或 `#VALUE!` 无法判断时，不写异常。

## 12. 到货日期

### BR-ARRIVAL-001 `[CONFIRMED]` 货未发完优先控制

到货日期先判断 `货未发完`，再选择日期来源。

当前“货未发完=Y”的定义要求最晚ASD和最晚RPD均有效，因此字面上的“Y 且 ASD 为空”无法同时成立。为保证规则可执行，正式口径按业务目的收敛为：

- `货未发完 = Y`：ATA/ASD可能仅代表已完成的部分批次，不作为整单最终到货日期；改用最晚计划日期加海运周期；
- `货未发完 != Y`（包括 `N` 或空）：才允许使用 ATA、ASD。

### BR-ARRIVAL-RPD-001 `[CONFIRMED]`

```text
如果 货未发完 = Y：
    最晚RPD 和海运周期均有效 → 到货日期（按RPD） = 最晚RPD + 海运周期
    否则 → 留空

如果 货未发完 != Y：
    ATA 有效 → 到货日期（按RPD） = ATA
    否则 ASD 有效 → 到货日期（按RPD） = ASD
    否则 → 留空
```

### BR-ARRIVAL-CPD-001 `[CONFIRMED]`

```text
如果 货未发完 = Y：
    CPD 和海运周期均有效 → 到货日期（按CPD） = CPD + 海运周期
    否则 → 留空

如果 货未发完 != Y：
    ATA 有效 → 到货日期（按CPD） = ATA
    否则 ASD 有效 → 到货日期（按CPD） = ASD
    否则 → 留空
```

补充边界：

- `货未发完=Y`时不使用已有 ATA/ASD 覆盖未完成批次的预计日期；
- `货未发完!=Y`时不再回退到 RPD/CPD 加周期；
- ATA、ASD、RPD/CPD均无有效值时直接留空，不写缺日期异常；
- 到货分支需要海运周期但查不到时，保留运输周期异常并将对应到货日期留空。

### BR-MONTH-001 `[CONFIRMED]`

- 收入年月（按RPD） = 到货日期（按RPD）的年月；
- 收入年月（按CPD） = 到货日期（按CPD）的年月；
- 对应到货日期为空时收入年月为空。

## 13. 收入分段类别

### BR-SEGMENT-001 `[CONFIRMED]`

收入分段类别每次重新计算，粒度为 `合同号 + 履行供应中心`。使用金额字段已归一化后的数值结果：

```text
1. 多次要货 = Y
   → 需判断

2. 多次要货 != Y，且 ATA 或 ASD 任一有效
   → 发未收

3. 多次要货 != Y，ATA/ASD均无有效值，且 RPD 或 CPD 任一有效
   3.1 遗留量 = 0 且 当月新订货 = 0
       → 未录入订货
   3.2 遗留量、当月新订货任一不为 0
       → 订未发

4. 多次要货 != Y，ATA/ASD/RPD/CPD均无有效值
   → 不要货
```

空白字符和 `#VALUE!` 已在规范化阶段按空值处理，不单独产生分类异常。

## 14. 三个人工字段

### BR-MANUAL-001 `[CONFIRMED]`

只有以下三列人工维护：

- 是否手工调整收入月份
- 手工调整收入月份
- 调整备注

首次运行或新业务行为空；后续按 `合同号 + 履行供应中心` 从上一期基表继承。它们不反向修改自动字段。

## 15. 跨月变化与供应差异

详见 `docs/comparison-output.md`。当前确认：

- RPD、CPD分两个跨期变化 Sheet；
- 比较两期对应自动收入年月；
- 提前和延后都列；
- 空→有、有→空也列；
- 输出变化方向与变化月数；
- 三个人工字段不参与比较；
- 另生成 `供应需要提拉诉求清单粗表`，比较同一期两套自动收入年月，绝对偏差达到1个月及以上时入表。

## 16. 异常处理

### BR-ERROR-001 `[CONFIRMED]` 业务/数据异常不阻塞整批

所有可恢复异常均：

1. 写入 `异常清单`；
2. 说明源文件、Sheet、行号或业务键、字段、原始值和原因；
3. 能继续计算的字段继续；
4. 无法计算的派生字段留空；
5. 不终止其他合同。

当前应记录的典型异常包括：

- 字段歧义或必需字段缺失；
- 合同进入全集但要货明细无匹配合同；
- 合同有要货明细但无法形成履行供应中心业务键；
- 合同级来源存在需保留的冲突；
- 完全重复行被忽略；
- 同一要货明细记录的备货/发货总控标识均有效但不同；
- 非空且非 Y/N 的枚举；
- 除 `#VALUE!` 外的非法非空日期或金额；
- 国家运输周期组合缺失或周期非法；
- 字段包含匹配出现多个候选。

以下情况不写异常：

- 空白字符、空字符串、`(空白)`；
- `#VALUE!`；
- 同合同+履行供应中心内多个不同非空文本值；
- 因所有相关日期为空而无法计算到货日期；
- 遗留量或当月新订货为空并被规范化为0。

任一必需源文件无法打开、文件损坏或无法继续读取时，属于可能阻止本次运行的技术故障。

## 2. 当前范围

### BR-SCOPE-001 `[CONFIRMED]` 当前目标

工具读取一个业务 Excel 工作簿中的多个 Sheet，完成：

- 源表与字段识别；
- 合同集合生成；
- 履行供应中心展开；
- 合同级属性与合同+履行供应中心级属性填充；
- 重复数据识别与去重；
- 日期聚合；
- 海运周期计算；
- 两套到货日期与收入年月计算；
- 派生标记与收入分段类别计算；
- 三个人工调整字段跨次继承；
- RPD/CPD 收入年月跨月变化识别；
- 异常清单输出。

结果工作簿至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`
4. `异常清单`

### BR-SCOPE-002 `[CONFIRMED]` 当前非目标

- 不做收入金额汇总或正式收入统计报表；
- 不做装运排程、资源优化；
- 不要求输出 VLOOKUP 等 Excel 公式；
- 不把真实业务数据、历史快照或本地输出提交到公开仓库。

## 3. 输入工作簿

### BR-INPUT-001 `[CONFIRMED]` 工作簿结构

真实输入按一个 Excel 工作簿、多个 Sheet 处理。当前业务 Sheet 顺序为：

1. `遗留量`
2. `当月订货`（可选）
3. `要货明细`
4. `国家运输周期`

实际 Sheet 名可通过字段映射配置适配，但业务角色固定。

### BR-INPUT-002 `[CONFIRMED]` 当月订货可选

月初可能没有当月订货数据，因此：

- 整个 Sheet 可缺失；
- 缺失不阻塞运行；
- `当月新订货` 输出空值；
- BG 回退链跳过该来源。

“未提供”不得静默转成金额 0。

## 4. 字段与实现解耦

### BR-FIELD-001 `[CONFIRMED]` 三层解耦

必须区分：

1. 源表实际字段名；
2. 稳定内部字段 ID；
3. 输出显示名称。

例如 `supply_center`：

- 要货明细源字段：`供应中心简称`
- 国家运输周期源字段：`供应中心`
- 输出显示：`履行供应中心`

例如 `bg`：

- 遗留量：`行销产品维BG中文名称`
- 当月订货：`行销产品维BG中文名称`
- 要货明细：`BG_CN`
- 输出：`BG`

### BR-FIELD-002 `[CONFIRMED]` 字段匹配统一机制

所有字段统一执行：

1. 表头有限规范化；
2. canonical/alias 精确匹配；
3. 精确未命中时执行包含匹配；
4. 包含匹配必须唯一命中；
5. 多个候选时记录字段歧义异常，该字段本次视为不可用，但整批继续。

不使用相似度、编辑距离或“最像字段”自动选择。

## 5. 业务粒度与合同集合

### BR-GRAIN-001 `[CONFIRMED]` 最终行粒度

```text
合同号 + 履行供应中心
```

同一合同存在多个履行供应中心时，每个中心输出一行。

### BR-GRAIN-002 `[CONFIRMED]` 合同全集

合同集合由以下三个业务表的合同号合并后去重：

- 遗留量表 `华为合同号`
- 当月订货表 `华为合同号`（Sheet 存在时）
- 要货明细表 `原合同号`

若当月订货 Sheet 缺失，则使用其余两表并集。

合同进入全集后，通过要货明细取得该合同的履行供应中心集合。若合同没有可用履行供应中心：

- 记录异常；
- 不生成“履行供应中心为空”的正常业务行；
- 整批继续处理其他合同。

### BR-GRAIN-003 `[CONFIRMED]` 合同级字段

遗留量、当月新订货以及主要合同属性按合同号取得。它们不按履行供应中心拆分。同一合同展开到多个履行供应中心行时复制展示。

## 6. 同合同多记录的默认规则

### BR-FIRST-001 `[CONFIRMED]`

遗留量表、当月订货表及合同级文本属性出现同一合同多条记录时：

1. 完全重复记录先去重；
2. 默认按源表原始顺序取第一条记录的值；
3. 字段允许为空；
4. 若同一合同后续记录出现不同非空值，仍使用第一条，同时写入异常清单说明冲突和值来源；
5. 不因冲突终止整批。

当前不做金额求和、最大值或分摊。

国家存在多值时同样记录异常，但仍按第一条作为本次计算输入，以便尽可能继续生成结果。

## 7. 属性来源

### BR-SOURCE-001 `[CONFIRMED]`

- BG：遗留量 → 当月订货（若有）→ 要货明细；
- 地区部：遗留量 → 要货明细；
- 国家：遗留量 → 要货明细；
- 客户群：遗留量 → 要货明细；
- 项目名称：遗留量 → 要货明细；
- 贸易术语：要货明细；
- 履行供应中心：要货明细。

某个优先来源值为空时继续使用下一来源。字段为空本身可以是正常数据状态，除非该字段进入最终到货日期的必要计算链。

## 8. 派生字段

### BR-CARRYOVER-001 `[CONFIRMED]` 结转类型

只根据遗留量表自身 `国家中文名称`：

- 阿拉伯联合酋长国
- 巴基斯坦
- 巴西
- 菲律宾
- 马来西亚
- 沙特阿拉伯
- 印度尼西亚

命中任一值：`交付类`；否则留空。

### BR-MULTI-SC-001 `[CONFIRMED]`

同合同不同有效履行供应中心数 > 1：`Y`；否则 `N`。

### BR-SPLIT-SHIPMENT-001 `[CONFIRMED]`

要货明细先去除完全重复脏数据，再在同一 `合同号 + 履行供应中心` 下统计真实记录数：

- 记录数 > 1：`分批发货 = Y`
- 否则：`N`

完全重复行不得制造分批发货。

### BR-STOCK-001 `[PROVISIONAL]`

`是否解锁备货` 读取 `备货总控标识`。同组多条真实记录时，暂按原出现顺序把每次值拼接到一个单元格，建议分隔符 `|`，例如 `Y|Y|N`。该展示格式后续允许调整。

### BR-MULTI-DEMAND-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 RPD 日期数 > 1：`多次要货 = Y`；否则 `N`。

### BR-SPLIT-SUPPLY-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 CPD 日期数 > 1：`分批供应 = Y`；否则 `N`。

## 9. 海运周期

### BR-TRANSIT-001 `[CONFIRMED]`

先读取要货明细 `贸易术语`，去首尾空白并忽略英文大小写：

```text
贸易术语 ∈ {FCA, FOB, EXW}
→ 海运周期 = 5 天
```

否则：

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

运输周期单位均为自然日。

若国家运输周期表找不到对应组合或周期值非法：

- 记录异常；
- 海运周期留空；
- 整批继续；
- 只有当该行最终到货日期必须依赖海运周期时，对应到货日期无法计算并留空。

## 10. 日期聚合与到货日期

### BR-DATE-001 `[CONFIRMED]`

同一合同+履行供应中心内：

- ATA = MAX(`天_ATA`)
- ASD = MAX(`ASD日期`)
- RPD = MIN(`RPD日期`)
- CPD = MAX(`CPD日期`)

空值不参与聚合。非空但无法解析的日期记录异常，并作为无效日期排除。

### BR-ARRIVAL-RPD-001 `[CONFIRMED]`

```text
有 ATA → MAX(ATA)
否则有 ASD → MAX(ASD)
否则有 RPD 且海运周期可用 → MIN(RPD) + 海运周期
否则 → 到货日期（按RPD）留空并记录原因
```

### BR-ARRIVAL-CPD-001 `[CONFIRMED]`

```text
有 ATA → MAX(ATA)
否则有 ASD → MAX(ASD)
否则有 CPD 且海运周期可用 → MAX(CPD) + 海运周期
否则 → 到货日期（按CPD）留空并记录原因
```

ATA/ASD 命中时无需海运周期即可得到到货日期；即使海运周期缺失，也只记录异常，不影响该到货日期。

### BR-MONTH-001 `[CONFIRMED]`

- 收入年月（按RPD） = 到货日期（按RPD）的年月；
- 收入年月（按CPD） = 到货日期（按CPD）的年月；
- 对应到货日期为空时收入年月也为空。

## 11. 收入分段类别

### BR-SEGMENT-001 `[CONFIRMED]`

同合同+履行供应中心：

```text
1. 多次要货 = Y → 需判断
2. 否则 ATA 或 ASD 任一有效 → 发未收
3. 否则 RPD 或 CPD 任一有效 → 订未发
4. 否则 → 不要货
```

日期原值非空但格式错误时先记录异常，再按有效日期结果参与分类；无法可靠判断时可输出 `需判断`。

## 12. 三个人工字段

### BR-MANUAL-001 `[CONFIRMED]`

只有以下三列人工维护：

- 是否手工调整收入月份
- 手工调整收入月份
- 调整备注

首次运行或新业务行为空；后续按 `合同号 + 履行供应中心` 从上一期基表继承。

它们不反向修改 RPD、CPD、到货日期、自动收入年月或收入分段类别。

## 13. 跨月变化

详见 `docs/comparison-output.md`。

当前确认：

- RPD、CPD 分两个 Sheet；
- 比较两期对应自动收入年月；
- 提前和延后都列；
- 空→有、有→空也列；
- 建议输出变化方向与变化月数；
- 三个人工字段不参与比较。

## 14. 异常处理

### BR-ERROR-001 `[CONFIRMED]` 业务/数据异常不阻塞整批

所有可恢复的业务与数据异常均：

1. 写入 `异常清单`；
2. 说明文件/Sheet、行号或业务键、字段、原始值、原因；
3. 能继续计算的字段继续计算；
4. 无法计算的派生字段留空；
5. 不终止其他合同处理。

典型异常包括：

- 字段歧义或缺失；
- 合同无履行供应中心；
- 同合同出现冲突属性；
- 完全重复脏数据；
- 备货/发货标识不同步；
- 非 Y/N 枚举；
- 日期格式错误；
- 国家运输周期表找不到组合；
- 运输周期非法；
- 最终到货日期缺少必要输入。

只有工作簿无法打开、文件损坏等无法继续读取的技术故障才可能导致本次运行无法执行。

## 15. 当前 POC 与正式需求边界

现有 POC 的分层结构可以参考，但其输入模型、日期字段、运输周期匹配键、领域粒度、输出和历史比较均与本需求不一致。后续需要结构性修正，不能只替换表头。

当前版本明确不需要旧 POC 中的数量/金额汇总主流程。

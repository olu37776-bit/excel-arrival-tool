## 2. 当前范围

### BR-SCOPE-001 `[CONFIRMED]` 当前目标

工具读取三个必选业务 Excel 源文件，并在存在时读取当月订货 Excel，完成：

- 源文件、业务表和字段识别；
- 可用业务源的合同全集生成；
- 履行供应中心展开；
- 合同级属性与合同+履行供应中心级属性填充；
- 完全重复数据识别与去重；
- 日期聚合、最晚日期和货未发完判断；
- 海运周期计算；
- 两套到货日期与收入年月计算；
- 派生标记和收入分段类别计算；
- 三个人工字段跨次继承；
- RPD/CPD 收入年月跨期变化识别；
- 同一期 RPD/CPD 收入年月差异识别；
- 异常清单输出。

结果工作簿至少包含：

1. `基表`
2. `RPD跨月变化`
3. `CPD跨月变化`
4. `供应需要提拉诉求清单粗表`
5. `异常清单`

### BR-SCOPE-002 `[CONFIRMED]` 当前非目标

- 不做正式收入金额汇总报表；
- 不做装运排程、运输优化或资源规划；
- 不要求输出 VLOOKUP 等 Excel 公式；
- 不把真实业务数据、历史结果或本地输出提交到公共仓库。

## 3. 输入源文件

### BR-INPUT-001 `[CONFIRMED]` 独立文件结构

业务输入角色仍为四类独立 Excel 文件，但必选性不同：

1. 遗留量源文件：必选；
2. 当月订货源文件：**可选，允许整份文件不存在或本次不提供**；
3. 要货明细源文件：必选；
4. 国家运输周期源文件：必选。

不得要求用户先合并为单工作簿。实际文件名、路径及文件内 Sheet 名由输入适配和配置识别。

### BR-INPUT-002 `[CONFIRMED]` 当月订货源文件可选

未提供整个当月订货源文件属于正常业务状态，不属于异常，也不得阻止运行。

当月订货源文件未提供时：

- 合同全集仅由遗留量与要货明细合同号合并去重；
- 所有正常业务行的 `当月新订货` 输出规范化数值 `0`；
- BG 来源链由 `遗留量 → 当月订货 → 要货明细` 自动退化为 `遗留量 → 要货明细`；
- 不生成“缺少当月订货文件”“当月订货未加载”等异常；
- 其他业务规则照常执行。

当月订货源文件已提供时：

- 合同全集使用遗留量、当月订货、要货明细三表合同号并集；
- 某个合同在当月订货中无匹配记录时，该合同 `当月新订货=0`，且不记录异常；
- BG 按既定优先级使用当月订货作为中间回退来源。

### BR-INPUT-003 `[IMPLEMENTATION_NOTE]` 已提供但不可识别不等于“未提供”

如果用户明确选择了当月订货文件，但该工作簿无法唯一识别符合字段契约的业务 Sheet：

- 必须产生明确的源数据识别异常，例如 `SHEET_ROLE_NOT_FOUND` 或 `AMBIGUOUS_SHEET_ROLE`；
- 不得把“用户提供了错误/不可识别文件”静默伪装成“本次未提供当月订货文件”；
- 在异常已明确记录的前提下，可按“当月订货数据不可用”继续其余合同处理，并将 `当月新订货`按0处理。

## 4. 字段与实现解耦

### BR-FIELD-001 `[CONFIRMED]` 三层解耦

必须区分：

1. 源表实际字段名；
2. 稳定内部字段 ID；
3. 输出显示名称。

示例：

```text
内部字段：supply_center
要货明细：供应中心简称
运输周期表：供应中心
输出显示：履行供应中心
```

```text
内部字段：bg
遗留量：行销产品维BG中文名称
当月订货：行销产品维BG中文名称（仅当文件存在）
要货明细：BG_CN
输出显示：BG
```

源字段变化只修改映射；输出标题变化只修改输出配置；核心规则继续使用内部字段 ID。

### BR-FIELD-002 `[CONFIRMED]` 字段匹配统一机制

所有字段统一执行：

1. Unicode NFKC 和有限空白规范化；
2. canonical/alias 精确匹配；
3. 精确未命中时执行包含匹配；
4. 包含匹配必须唯一命中；
5. 多个候选记录字段歧义，字段本次不可用但整批继续；
6. 禁止相似度、编辑距离或“最像字段”自动选择。

## 5. 业务粒度与合同全集

### BR-GRAIN-001 `[CONFIRMED]` 最终行粒度

```text
合同号 + 履行供应中心
```

同一合同存在多个履行供应中心时，每个中心输出一行。

### BR-GRAIN-002 `[CONFIRMED]` 合同全集

合同全集根据当月订货文件是否存在动态形成：

```text
当月订货文件存在且可读取：
遗留量合同号 ∪ 当月订货合同号 ∪ 要货明细合同号

当月订货文件未提供：
遗留量合同号 ∪ 要货明细合同号
```

合同进入全集后，必须通过要货明细展开履行供应中心。

如果一个合同来自遗留量或可用的当月订货，但要货明细中完全找不到该合同号：

- 记录 `CONTRACT_NOT_FOUND_IN_DEMAND_DETAIL`；
- 异常原因明确写“要货明细未找到该合同号”；
- 不生成履行供应中心为空的正常业务行；
- 继续处理其他合同。

该异常不得笼统表述为“合同有记录但没有可用履行供应中心”。

### BR-GRAIN-003 `[CONFIRMED]` 合同级字段

遗留量、当月新订货以及主要合同属性按合同号取得，不按履行供应中心拆分。同一合同展开到多个履行供应中心时复制展示。

## 6. 同合同多记录与文本值

### BR-FIRST-001 `[CONFIRMED]` 合同级第一条规则

遗留量表和存在时的当月订货表出现同合同多条记录时：

1. 完全重复记录先去重；
2. 去重后按源表原始顺序取第一条；
3. 当前不求和、不取最大、不分摊；
4. 不因多行终止整批。

国家存在不同非空值时仍记录国家冲突异常，并使用第一条继续计算。

### BR-TEXT-001 `[CONFIRMED]` 同业务组不同文本不报错

同一 `合同号 + 履行供应中心` 下，BG、地区部、客户群、项目名称、贸易术语等普通文本字段出现多个不同非空值时：

- 不记录文本冲突异常；
- 按去重后的原始顺序取第一个有效值；
- 后续值不影响该字段本次输出。

该规则不取消“同一合同国家冲突”的既有异常规则。

## 7. 属性来源

### BR-SOURCE-001 `[CONFIRMED]`

- BG：遗留量 → 当月订货（若文件存在且该合同有有效值） → 要货明细；
- 地区部：遗留量 → 要货明细；
- 国家：遗留量 → 要货明细；
- 客户群：遗留量 → 要货明细；
- 项目名称：遗留量 → 要货明细；
- 贸易术语：要货明细；
- 履行供应中心：要货明细。

优先来源为空或整个可选来源未提供时继续下一来源。普通业务字段允许为空。

## 8. 金额字段

### BR-AMOUNT-001 `[CONFIRMED]` 空值统一输出 0

`遗留量`与`当月新订货`是数值字段，最终基表不得输出空值：

- 源单元格为空、只有空白字符、为已识别空值占位符或合同无匹配记录时，输出 `0`；
- 当月订货整个源文件未提供时，所有业务行 `当月新订货` 输出 `0`；
- 读取到 Excel `#VALUE!` 或等价 VALUE 占位值时，按空值处理并输出 `0`，不记录异常；
- 正常数值保留；
- 其他无法解析的非空金额值记录异常，并以 `0` 作为本次输出值，以保证后续汇总和收入分段判断可执行。

金额的两位小数业务精度与0/非0判断见 `DR-002`。

## 9. 派生标记

### BR-CARRYOVER-001 `[CONFIRMED]` 结转类型

只根据遗留量表自身 `国家中文名称`。以下国家输出 `交付类`，其他留空：

- 阿拉伯联合酋长国；
- 巴基斯坦；
- 巴西；
- 菲律宾；
- 马来西亚；
- 沙特阿拉伯；
- 印度尼西亚。

### BR-MULTI-SC-001 `[CONFIRMED]`

同合同不同有效履行供应中心数量大于 1：`Y`；否则 `N`。

### BR-SPLIT-SHIPMENT-001 `[CONFIRMED]`

要货明细完全重复行先去重，再在同一 `合同号 + 履行供应中心` 下统计真实记录数：

- 真实记录数 > 1：`分批发货 = Y`；
- 否则：`N`。

完全重复脏数据不得制造分批发货、多次要货或分批供应。

### BR-STOCK-001 `[PROVISIONAL]`

`是否解锁备货`读取去重后真实记录中的`备货总控标识`，暂按原顺序使用 `|` 拼接。

### BR-CONTROL-FLAG-001 `[CONFIRMED]` 同行总控标识一致性

同一条要货明细记录中，`备货总控标识`和`发货总控标识`在两者均为有效 Y/N 时必须相同。不同则记录 `CONTROL_FLAG_MISMATCH`，并保留该行继续参与其他可计算规则。

### BR-MULTI-DEMAND-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 RPD 日期数 > 1：`多次要货 = Y`；否则 `N`。

### BR-SPLIT-SUPPLY-001 `[CONFIRMED]`

同合同+履行供应中心下，不同有效 CPD 日期数 > 1：`分批供应 = Y`；否则 `N`。

## 10. 海运周期

### BR-TRANSIT-001 `[CONFIRMED]`

贸易术语去首尾空白并忽略英文大小写后：

```text
FCA / FOB / EXW → 海运周期 = 5 天
```

其他贸易术语：

```text
国家 + 履行供应中心
→ 国家运输周期表
→ 运输周期
```

运输周期单位为自然日。显示格式为 `#,##0`、底层为非整数浮点时，按 Excel 零位小数显示结果四舍五入，不直接截断。

查不到组合或周期非法时记录异常并返回空海运周期。只有当到货日期路径确实依赖海运周期时，才会导致该到货日期为空。

## 11. 空值和 VALUE 标准化

### BR-NULL-001 `[CONFIRMED]`

以下值统一视为业务空值，直接标准化，不记录异常：

- `None` 或 Excel 空单元格；
- 仅包含空格、制表符、换行等空白字符的文本；
- NFKC 和去空白后等于 `(空白)` 的占位文本；
- Excel `#VALUE!`；
- 读取后等价的 `VALUE`、`#VALUE`、`#VALUE!` 文本标记，忽略大小写。

处理结果：

- 金额字段：转为数值 `0`；
- 日期字段：转为无日期 `None`；
- 普通文本和标识：转为空值；
- 上述标准化不进入异常清单。

其他 Excel 错误值和非空非法格式仍按相应字段规则处理。

## 12. 日期聚合和货未发完

### BR-DATE-001 `[CONFIRMED]`

同一合同+履行供应中心内：

- ATA = MAX(`天_ATA`)；
- ASD = MAX(`ASD日期`)；
- RPD = MIN(`RPD日期`)；
- 最晚ASD = MAX(`ASD日期`)；
- 最晚RPD = MAX(`RPD日期`)；
- CPD = MAX(`CPD日期`)。

标准化为空的值不参与聚合，也不记录异常。

### BR-SHIPMENT-INCOMPLETE-001 `[CONFIRMED]` 货未发完

```text
最晚RPD为空 → 货未发完为空
最晚RPD有效、最晚ASD为空 → 货未发完=Y
最晚RPD和最晚ASD均有效，且最晚RPD>最晚ASD → Y
最晚RPD和最晚ASD均有效，且最晚RPD<=最晚ASD → N
```

因正常空值无法判断时直接留空，不记录异常。

## 13. 到货日期

### BR-ARRIVAL-RPD-001 `[CONFIRMED]`

到货日期（按RPD）按以下闭合规则计算：

```text
A. 货未发完 != Y：
   1. ATA有效 → 到货日期=ATA
   2. 否则 ASD和海运周期有效 → 到货日期=ASD+海运周期
   3. 否则 → 留空

B. 货未发完 = Y：
   1. 不使用ATA/ASD作为最终到货日期依据
   2. 最晚RPD和海运周期有效 → 到货日期=最晚RPD+海运周期
   3. 否则 → 留空
```

### BR-ARRIVAL-CPD-001 `[CONFIRMED]`

到货日期（按CPD）按以下闭合规则计算：

```text
A. 货未发完 != Y：
   1. ATA有效 → 到货日期=ATA
   2. 否则 ASD和海运周期有效 → 到货日期=ASD+海运周期
   3. 否则 → 留空

B. 货未发完 = Y：
   1. 不使用ATA/ASD作为最终到货日期依据
   2. CPD和海运周期有效 → 到货日期=CPD+海运周期
   3. 否则 → 留空
```

如果 ATA、ASD、对应计划日期均为空，不做运算，结果直接为空且不记录异常。若有日期路径但所需海运周期缺失，则记录运输周期异常并留空。

### BR-MONTH-001 `[CONFIRMED]`

- 收入年月（按RPD）= 到货日期（按RPD）的年月；
- 收入年月（按CPD）= 到货日期（按CPD）的年月；
- 到货日期为空时对应收入年月为空。

## 14. 收入分段类别

### BR-SEGMENT-001 `[CONFIRMED]`

同一合同+履行供应中心按以下优先级计算：

```text
1. 多次要货 = Y
   → 需判断

2. 多次要货 != Y，且 ATA 或 ASD 任一有效
   → 发未收

3. 多次要货 != Y，ATA和ASD均为空，且RPD或CPD任一有效：
   3.1 遗留量=0 且 当月新订货=0
       → 未录入订货
   3.2 遗留量、当月新订货任意一个不为0
       → 订未发

4. 多次要货 != Y，ATA、ASD、RPD、CPD均为空
   → 不要货
```

金额判断使用统一的两位小数规范化金额。因此当月订货源文件未提供时，`当月新订货=0`按正常业务值参与判断。

## 15. 三个人工字段

只有以下三列人工维护：

- 是否手工调整收入月份；
- 手工调整收入月份；
- 调整备注。

首次运行或新业务行为空；后续按 `合同号 + 履行供应中心` 从上一期基表继承。它们不反向修改自动日期、收入年月或收入分段类别。

## 16. 跨期变化与差异清单

详见 `docs/comparison-output.md`。当前确认：

- RPD、CPD分两个跨期变化Sheet；
- 提前、延后、空→有、有→空均入表；
- 比较自动收入年月，不使用人工调整月份；
- 另生成同一期双口径差异清单。

## 17. 异常处理

### BR-ERROR-001 `[CONFIRMED]` 非阻塞原则

所有可恢复异常写入`异常清单`并继续处理。异常应说明源文件、Sheet、行号或业务键、字段、原始值、原因和处理结果。

当前应记录的典型异常：

- 已提供的源文件无法识别或出现业务 Sheet 歧义；
- 字段缺失或包含匹配歧义；
- 合同全集中的合同在要货明细完全找不到；
- 同一合同国家冲突；
- 完全重复行被忽略；
- 同一要货明细行备货/发货总控标识不一致；
- 非空且非 Y/N 的标识；
- 国家+履行供应中心找不到运输周期；
- 运输周期非法；
- 其他无法解析的非空金额或日期值。

以下情况不记录异常：

- **整个当月订货源文件本次未提供**；
- 空单元格、纯空白字符、`(空白)`；
- `#VALUE!`及等价 VALUE 占位值；
- 同合同+履行供应中心下普通文本字段存在多个不同非空值；
- 所有候选日期均为空，因此到货日期自然为空；
- 当月订货文件存在，但某合同在其中没有匹配记录。

## 18. 实施边界

当前代码与本基线存在差异。后续代码修复必须以本文件、`source-schema.md`和`output-schema.md`为准。

当月订货可选化至少要求：

- GUI 将当月订货标记为可选，不再阻止空路径执行；
- Application/RunRequest允许 `monthly_order_path=None`；
- `SourceFiles`/输入适配器不尝试打开未提供的当月订货文件；
- 配置中的 `monthly_order.optional` 改为 `true`，其余三个源角色保持 `false`；
- 合同全集、BG回退、金额默认值均按本文件定义处理；
- 提供了当月订货文件时，仍必须使用统一 SheetLocator 根据字段契约定位业务 Sheet，不能依赖固定 Sheet 名。

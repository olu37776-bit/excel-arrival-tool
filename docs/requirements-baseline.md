## 1. 文档体系与权威边界

本文件只维护总体目标、业务粒度、跨模块规则、工程边界和未决问题。详细契约按职责拆分，避免同一规则在多份文档中重复维护并逐渐漂移。

| 文档 | 权威范围 |
|---|---|
| `docs/requirements-baseline.md` | 总体范围、业务粒度、跨模块规则、未决问题 |
| `docs/source-schema.md` | 源表存在性、源字段准确名称、内部字段 ID、字段匹配策略 |
| `docs/output-schema.md` | 最终基表字段顺序、字段来源/计算、人工字段规则 |
| `docs/comparison-output.md` | RPD/CPD 跨期变化清单和结果工作簿结构 |
| `docs/decisions/*.md` | 已确认的单项决策及其影响范围 |
| `docs/reviews/*.md` | 一致性审查结果，不直接替代需求规则 |

发生冲突时不得静默选择任一版本。冲突本身属于文档缺陷，应先修订为一致状态。业务方最新明确确认的规则优先于旧《运算逻辑解释》、现有代码、测试和示例配置。

### 1.1 规则状态

统一使用：

- `CONFIRMED`：业务含义已明确，可以实现和验收；
- `PROVISIONAL`：方向已明确，但仍有边界待确认；
- `TBD`：未确认，不得在代码中静默假设；
- `REJECTED`：旧说明或旧实现已确认不适用；
- `IMPLEMENTATION_NOTE`：工程约束，不替代业务规则。

可在说明中附加“可选输入”“仅显示名称”等属性，但不再扩散新的主状态名称。

### 1.2 增量更新原则

用户可以逐条补充需求，不要求一次性讲完。每次更新应：

1. 使用稳定规则 ID；
2. 区分业务规则、源字段映射和输出显示名称；
3. 标记状态与影响范围；
4. 在变更记录中追加，不静默覆盖；
5. 规则确认后再同步修改代码、测试、README 和示例配置。

## 2. 当前业务目标与非目标

### BR-SCOPE-001 `[CONFIRMED]` 当前目标

工具读取业务 Excel，完成：

- 输入存在性和表头字段校验；
- 合同关联；
- 履行供应中心展开；
- 合同级属性与合同+履行供应中心级属性填充；
- 日期聚合；
- 运输周期匹配；
- 两套到货日期与收入年月计算；
- 派生标记与收入分段类别计算；
- 三个人工调整字段跨次继承；
- RPD/CPD 收入年月跨月变化识别；
- 结果工作簿输出。

当前结果工作簿计划包含：

1. `基表`；
2. `RPD跨月变化`；
3. `CPD跨月变化`；
4. 后续可增加 `异常清单`。

### BR-SCOPE-002 `[CONFIRMED]` 当前非目标

- 不做装运排程、资源优化或运输方案规划；
- 不做收入金额汇总、金额聚合或正式收入统计报表；
- 不要求输出 VLOOKUP 等 Excel 公式，默认写入程序计算结果；
- 不把真实业务 Excel、合同数据、运行快照或输出结果提交到公开仓库。

`遗留量` 与 `当月新订货` 当前只是基表中的合同级展示字段，不在本版本中进行汇总统计。

## 3. 输入资料

### BR-INPUT-001 `[CONFIRMED]` “底表”的含义

“底表”是源表统称，不是一张独立输入表。

当前业务资料包括：

- 遗留量表；
- 当月订货表；
- 要货明细表；
- 国家运输周期表；
- 目标输出基表格式；
- 原《运算逻辑解释》。

### BR-INPUT-002 `[CONFIRMED]` 当月订货表为可选输入

当月订货表允许整表不提供。月初可能尚未取数，因此缺少该表不得阻塞运行。

当该表缺失时：

- `当月新订货` 进入数据不可用分支；
- BG 回退链跳过当月订货来源，继续查询要货明细；
- 不得把“未提供”静默等同于金额 0。

最终显示空白还是 0 仍为 `TBD`，当前推荐空白。

### BR-INPUT-003 `[PROVISIONAL]` 其他资料的必选性

当前理解为遗留量表、要货明细表和国家运输周期表属于主要输入；目标输出模板用于规定用户可见字段顺序和格式。以下仍需由本地资料审计确认：

- 每项资料是独立工作簿还是工作簿内 Sheet；
- 文件名、Sheet 名和表头行；
- 是否存在允许缺失的运行场景；
- 目标模板是外部输入还是程序内置默认模板。

源字段准确名称以 `docs/source-schema.md` 为准。

## 4. 字段定位与解耦

### BR-FIELD-001 `[CONFIRMED]` 三层解耦

实现必须区分：

1. 源表实际字段名；
2. 稳定内部字段 ID；
3. 最终输出显示名称。

例如内部字段 `supply_center`：

- 要货明细源字段：`供应中心简称`；
- 国家运输周期源字段：`供应中心`；
- 基表输出显示名：`履行供应中心`。

三者名称可以不同，但映射到同一稳定业务语义。

### BR-FIELD-002 `[CONFIRMED]` 业务字段优先

不得把固定列字母、VLOOKUP 列序号或当前列位置作为稳定业务接口。列位置仅用于结构审计、变更告警和错误定位。

### BR-FIELD-003 `[CONFIRMED]` 精确优先、受控包含匹配

字段解析顺序为：

1. 有限规范化后精确匹配；
2. 明确 alias 的精确匹配；
3. 仅对配置显式允许的字段执行 `contains`；
4. `contains` 必须唯一命中，否则报歧义错误；
5. 禁止基于编辑距离或相似度自动选择“最像”的字段。

## 5. 数据粒度与行生成

### BR-GRAIN-001 `[CONFIRMED]` 最终业务粒度

最终基表一行的业务粒度为：

```text
合同号 + 履行供应中心
```

同一合同存在多个履行供应中心时，每个中心分别输出一行。供应中心来自要货明细 `供应中心简称`。

### BR-GRAIN-002 `[CONFIRMED]` 合同级字段

`遗留量` 与 `当月新订货` 都是合同级字段：

- 遗留量按合同号从遗留量表取得；
- 当月新订货按合同号从可选当月订货表取得；
- 两者不按履行供应中心拆分或分摊；
- 同一合同展开为多个履行供应中心行时，合同级值复制到每行。

当前工具不做金额汇总，因此重复展示不属于当前错误。

### BR-GRAIN-003 `[TBD]` 最终合同全集

仍需确认最终合同集合来自：

- 遗留量表与要货明细表合同并集；
- 是否还包括可选当月订货表中的独立合同；
- 或以要货明细中的合同+履行供应中心为唯一行源。

如果进入合同集合但要货明细中找不到履行供应中心，当前方向是记录数据异常，不生成供应中心为空的正常行。

## 6. 已确认的字段来源优先级

详细字段名见 `docs/source-schema.md`，输出顺序见 `docs/output-schema.md`。

### BR-SOURCE-001 `[CONFIRMED]` BG

```text
遗留量 行销产品维BG中文名称
→ 当月订货 行销产品维BG中文名称（若表存在）
→ 要货明细 BG_CN
```

### BR-SOURCE-002 `[CONFIRMED]` 合同属性

- 地区部：遗留量 `地区部中文名称` → 要货明细 `地区部`；
- 国家：遗留量 `国家中文名称` → 要货明细 `国家中文名称`；
- 客户群：遗留量 `客户群中文名称` → 要货明细 `签约客户群`；
- 项目名称：遗留量 `交付项目中文名称` → 要货明细同名字段；
- 贸易术语：要货明细 `贸易术语`；
- 履行供应中心：要货明细 `供应中心简称`。

当月订货不参与地区部、国家、客户群和项目名称的回退链。

### BR-SOURCE-003 `[CONFIRMED]` 国家唯一性

同一合同必须对应唯一国家。跨来源或同一来源出现多个不同国家时，不得静默取第一条，应产生数据异常。

## 7. 派生字段

### BR-CARRYOVER-001 `[CONFIRMED]` 结转类型

结转类型只根据遗留量表自身的 `国家中文名称` 判断，不使用经过回退后的输出国家。

属于以下任一国家时：

- 阿拉伯联合酋长国；
- 巴基斯坦；
- 巴西；
- 菲律宾；
- 马来西亚；
- 沙特阿拉伯；
- 印度尼西亚；

输出：

```text
交付类
```

其他情况留空。

### BR-MULTI-SC-001 `[CONFIRMED]` 多个供应中心发货

同一合同的不同有效履行供应中心数量大于 1 时输出 `Y`，否则输出 `N`。

### BR-SPLIT-SHIPMENT-001 `[CONFIRMED]` 分批发货

在同一 `合同号 + 履行供应中心` 内，相关总控/发货记录数大于 1 时输出 `Y`，否则输出 `N`。不要求多条记录的 Y/N 值不同。

`备货总控标识` 与 `发货总控标识` 业务上应同步；具体一致性校验和重复行处理仍需结合实际数据确认。

### BR-STOCK-001 `[PROVISIONAL]` 是否解锁备货

来源为要货明细 `备货总控标识`，源值为 Y/N。若同一组有多条记录，当前先保留每次出现的值，最终单元格展示格式仍为 `TBD`。

### BR-MULTI-DEMAND-001 `[CONFIRMED]` 多次要货

同一 `合同号 + 履行供应中心` 下，不同有效 RPD 日期数量大于 1 时输出 `Y`，否则输出 `N`。

### BR-SPLIT-SUPPLY-001 `[CONFIRMED]` 分批供应

同一 `合同号 + 履行供应中心` 下，不同有效 CPD 日期数量大于 1 时输出 `Y`，否则输出 `N`。

## 8. 运输周期与日期计算

### BR-TRANSIT-001 `[CONFIRMED]` 基础运输周期

国家运输周期表按以下复合键匹配：

```text
国家 + 履行供应中心
```

取得 `运输周期`，单位为自然日。找不到有效规格时不得静默使用 0 天。

部分特殊贸易类型会调整基础运输周期。具体类型和调整规则尚未补充，但实现必须与基础规格查询及日期优先级解耦。

### BR-DATE-001 `[CONFIRMED]` 日期聚合范围和方式

所有日期均在同一 `合同号 + 履行供应中心` 内聚合：

- ATA = `MAX(天_ATA)`；
- ASD = `MAX(ASD日期)`；
- RPD = `MIN(RPD日期)`；
- CPD = `MAX(CPD日期)`。

空值不参与聚合；非空但无法解析为日期的值应产生数据异常。

### BR-ARRIVAL-RPD-001 `[CONFIRMED]` 到货日期（按RPD）

```text
有 ATA → MAX(ATA)，不加运输周期
否则有 ASD → MAX(ASD)，不加运输周期
否则 → MIN(RPD) + 最终运输周期
```

ATA、ASD、RPD 均无有效值时无法计算该字段，应产生异常。

### BR-ARRIVAL-CPD-001 `[CONFIRMED]` 到货日期（按CPD）

```text
有 ATA → MAX(ATA)，不加运输周期
否则有 ASD → MAX(ASD)，不加运输周期
否则 → MAX(CPD) + 最终运输周期
```

ATA、ASD、CPD 均无有效值时无法计算该字段，应产生异常。

### BR-MONTH-001 `[CONFIRMED]` 收入年月

- 收入年月（按RPD）= 到货日期（按RPD）的年月；
- 收入年月（按CPD）= 到货日期（按CPD）的年月。

## 9. 收入分段类别

### BR-REVENUE-SEGMENT-001 `[CONFIRMED]`

收入分段类别每次运行重新计算，粒度为 `合同号 + 履行供应中心`，优先级如下：

```text
1. 多次要货 = Y → 需判断
2. 多次要货 != Y，且 ATA 或 ASD 任一有值 → 发未收
3. 多次要货 != Y，ATA/ASD 为空，且 RPD 或 CPD 任一有值 → 订未发
4. 多次要货 != Y，ATA/ASD/RPD/CPD 全空 → 不要货
```

非空但无效的日期不能当作空值继续分类，应产生数据异常。

## 10. 人工调整字段

### BR-MANUAL-001 `[CONFIRMED]`

只有以下三个字段由人工维护：

1. 是否手工调整收入月份；
2. 手工调整收入月份；
3. 调整备注。

首次运行时三列为空。后续运行按 `合同号 + 履行供应中心` 从上一轮基表继承；上一轮无对应记录时仍为空。本次自动计算不得覆盖继承值。

`收入分段类别` 不是人工字段，每次重新计算。详细决策见 `docs/decisions/DR-001-manual-adjustment-fields.md`。

## 11. 跨期变化清单

### BR-COMPARE-001 `[CONFIRMED]` 比较粒度与对象

跨次比较按：

```text
合同号 + 履行供应中心
```

分别比较：

- 上期与本期 `收入年月（按RPD）`；
- 上期与本期 `收入年月（按CPD）`。

比较的是自动计算收入年月，不使用手工调整收入月份替代。

### BR-COMPARE-002 `[CONFIRMED]` 输出结构

同一结果工作簿中分别生成：

- `RPD跨月变化`；
- `CPD跨月变化`。

两张表的详细字段见 `docs/comparison-output.md`。

### BR-COMPARE-003 `[TBD]` 变化范围

仍需确认：

- 同时列出提前和延后，还是只列延后；
- 是否增加变化方向和变化月数；
- 上期空→本期有、上期有→本期空如何处理。

此前“直接比较 MIN(RPD) 月份作为独立延迟清单”的旧表述已不再作为当前唯一比较定义。若业务仍需要独立的计划出货延迟清单，应另立规则，不得与收入年月变化清单混用。

## 12. 数据异常与处理

### BR-ERROR-001 `[CONFIRMED]` 至少需要识别的异常

- 必填源表或字段缺失；
- 字段包含匹配出现多个候选；
- 合同号为空或格式异常；
- 需要输出的合同找不到履行供应中心；
- 同一合同出现多个不同国家；
- 国家+履行供应中心运输周期缺失或无效；
- 日期非空但无法解析；
- 需要 RPD/CPD 回退时没有有效基准日期；
- 国家运输周期规格出现重复键且值冲突；
- 同一业务粒度的文本属性出现无法解释的冲突。

### BR-ERROR-002 `[TBD]` 阻塞策略

仍需确认哪些异常：

- 终止整批；
- 只阻塞单行；
- 允许输出并进入异常清单；
- 仅记录告警。

异常信息至少应包含文件、Sheet、行号、合同号、履行供应中心、字段、原始值和原因。

## 13. 当前 POC 与正式需求的主要偏差

| 主题 | 当前 `main` POC | 当前正式需求 | 结论 |
|---|---|---|---|
| 输入模型 | `PRD`、`Shipment`、`Transit Days` 三个 Sheet | 遗留量、可选当月订货、要货明细、国家运输周期、目标模板 | 输入契约需要重构 |
| 核心粒度 | PO/Shipment | 合同号 + 履行供应中心 | 领域模型不一致 |
| 日期名 | PRD | RPD | 必须迁移 |
| 运输周期键 | Trade Type | 国家 + 履行供应中心，特殊贸易类型再调整 | 当前匹配键错误 |
| 到货日期 | Plan Month + Transit Days | ATA → ASD → RPD/CPD + 运输周期两条链 | 当前计算错误 |
| 输出 | 一套 Arrival/Revenue Month | 两套到货日期、两套收入年月、29列基表 | 输出模型缺失 |
| 历史比较 | Revenue Month，且身份键不稳定 | 合同号+履行供应中心，分别比较RPD/CPD收入年月 | 需要重写 |
| 金额汇总 | 已实现数量/金额汇总 | 当前明确不做 | 应移出当前主流程 |

现有分层结构可参考，但领域模型、输入契约、计算逻辑和比较逻辑不能通过少量改字段完成。

## 14. 当前高优先未决问题

### P0：影响结果结构或计算正确性

1. 最终合同全集和行生成算法；
2. 遗留量表、当月订货表同一合同出现多行时的金额聚合规则；
3. 各来源中同一合同或同一合同+履行供应中心的文本属性冲突处理；
4. 实际文件、Sheet、表头行和目标模板使用方式；
5. 整批阻塞、单行阻塞和告警的错误等级。

### P1：影响边界和展示

1. 当月订货表缺失时，当月新订货输出空白还是 0；
2. 是否解锁备货多记录时的单元格展示格式；
3. ATA/ASD 已命中时，运输周期规格缺失是否仍阻塞该行；
4. RPD/CPD 跨月变化清单的提前/延后和空值变化口径；
5. 特殊贸易类型的字段、类型集合和运输周期调整规则；
6. 前一次结果由用户选择还是自动定位最近一次成功运行。

## 15. 本地资料一致性审计重点

后续对本地资料的审计应输出事实，不得直接修改本基线中的业务规则。重点核对：

- 文件和 Sheet 的真实结构；
- 表头准确文本与列位置；
- `BG_CN`、`RPD日期`、`天_ATA` 等字段是否与本契约一致；
- 同一合同和同一合同+履行供应中心的重复数据分布；
- 日期、金额、Y/N 标识的实际值域和空值率；
- 国家+供应中心运输周期表是否唯一；
- 目标输出模板是否确为29列及当前顺序；
- 原《运算逻辑解释》与本需求基线的差异。
